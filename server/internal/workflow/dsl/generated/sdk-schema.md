# Workflow SDK: schema

Every user-facing inputSchema property must include a short title and a concise description in the user language. The input-parameter preview shows the title and description separately. Titles are noun phrases, ideally 2-10 Chinese characters or 1-4 words; descriptions are one short sentence, ideally at most 40 Chinese characters or 20 words. State what to provide and only the essential format, unit or missing-input behavior. Do not repeat the title, prefix text with required/optional, add long parenthetical explanations or describe the whole workflow. Express requiredness only through the schema required array and actual default values through schema default. Keep detailed business rules, branches and follow-up questions in worker instructions or workflow logic; preserve essential user-facing constraints in concise wording. For example, title: Requirements, description: Paste the current requirements.; title: Environment, description: Provide one environment and version per line.; title: Approval threshold, description: Ask for approval when remaining high-risk items reach this count., default: 1. Include only inputs needed for the user goal, and reuse these concise labels and descriptions when summarizing parameters in chat. Use stable keys for code, never as the only form label. Declare file inputs and final file outputs as {type: 'string', format: 'file', title, description}. Arrays use items with this same file schema. Input forms upload files and run admission replaces uploaded ally-file references with real absolute paths in the managed workflow workspace. Workers must read those paths using actual tools; never treat references as file contents. Final file values must be paths to real files created in flowContext.workspace.runDirectory by default, or the business destination explicitly selected by the user in flowContext.scope.workingDirectory; users and the API can download these files. Return actual paths rather than base64 data or made-up download URLs. Ordinary strings are never inferred to be file outputs. Input form controls support x-ui-control: input or textarea for strings, radio or select for scalar enum, switch or checkbox for booleans, and checkboxes for arrays whose items.enum lists the allowed values. x-ui-labels supplies user-facing choice labels in enum order. These annotations only select controls; values still follow the declared JSON Schema types and constraints. Use these same annotations in askUser schemas.

```typescript
type Json = null | boolean | number | string | Json[] | { [key: string]: Json };
type Schema = { [key: string]: Json };
interface VisualNode { id: string; label: string; description?: string; phase: string; inputs?: string[]; outputs?: string[]; successCondition?:{path:string;equals:Json} }
```
