# 插件边界收敛实施计划

> 用户已明确批准本设计并要求开始改造；继续实施，不重复请求确认。

**Goal:** 系统仅安装自有插件库，关闭上传导入与聊天系统安装，聊天原生插件与外部相同 CLI 共用环境。

**Architecture:** 自有插件维持 HTTP 分发、伙伴关系和统一授权。第三方原生插件归 CLI 管理；自有能力以执行级原生配置附加，模型账号继续隔离。

**Tech Stack:** Go、React/TypeScript、既有 ACP adapter、Node 发布构建。

**Spec:** [设计](../specs/2026-10-19-plugin-design.md) 与 [Spec](../specs/2026-10-19-plugin-spec.md)。

## 约束

- 在当前工作区继续；`.scratch/plugin-boundary/baseline.json`、补丁及文件副本记录已有修改，不回滚或顺手提交无关工作。
- 不操作用户真实 CLI 插件、账号及配置，不控制运行 UI，不推送或发布新版本。
- 仅定向验证；生成契约由根代理最终串行执行项目命令，避免与源码编辑并发。
- 保留自有插件包内解析/原生派生和统一认证能力；仅取消面向用户的任意插件导入。

## Review Focus

1. 隐藏按钮后旧 HTTP 扫描/准备接口是否仍能导入。
2. 聊天旧能力/别名/系统 Skill 是否仍可安装到系统。
3. CODEX_HOME / CLAUDE_CONFIG_DIR 是否令插件安装落入私有临时环境。
4. 共享插件环境是否覆盖或泄漏模型账号，或污染外部全局受管安装关系。
5. 受限执行是否加载外部未授权插件；自有原生插件是否仍正常交付。
