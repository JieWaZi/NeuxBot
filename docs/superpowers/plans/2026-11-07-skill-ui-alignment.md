## 本轮修正与验收边界

- [x] 正式来源更新为 Release v0.1.2；飞书、企业微信与 GitHub 三个插件包版本均为 0.1.1，目录及公开资料继续使用 schemaVersion 1。Release 版本、包版本和目录 schema 分别记录，不互相替代。
- [x] 定位并修正飞书依赖锁中的错误资产名称：真实上游 `*-neuxally.1` 被改为不存在的 `*-neuxbot.1`，导致首次授权准备下载返回 404。Core 原先把依赖准备失败折叠为认证失败，面板又把首次入口统一标为重试，造成账号失效的误导。GitHub 与企业微信在相同 Core 下能够发出挑战，没有证据把三者归为同一依赖故障。
- [x] Core 对白名单依赖准备失败保留 `PluginDependencyUnavailable`，初始 HTTP 与会话稳定错误码一致；前端通过生成错误目录本地化，未知码保留未完成语义，不展示供应商原始输出。安装授权重试覆盖最新失败，读取并发上下文到发起授权共用提交锁；未核验状态不代表失败或成功。
- [x] 使用真实 Core 的生产 HTTP 路由、隔离 SQLite 和配置修订／账号代次 CAS 验证正式三包，范围到生成授权挑战与取消会话。前端 MSW 另验证初始 generation 12、完成事件后 generation 13 的安装请求，保留匹配版本与修订；这属于自动化替身回归，不是实际账号登录或真实安装验收。
- [x] 固定静态 Renderer 后完成三包隔离 Electron 桌面复验：均生成真实授权挑战，分别等待观察 22、21、21 秒后取消；未登录供应商账号，也未创建真实伙伴安装。开发服务器中的 GitHub 挑战消失与并发源文件 HMR 错误处于同一验收窗口，不能据此认定 Core 授权失败；固定静态包的复验与该次开发态现象分开记录。
