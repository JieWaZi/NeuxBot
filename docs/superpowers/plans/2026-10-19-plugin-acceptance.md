# 插件边界改造验收记录

本记录针对“系统仅安装自有插件库，聊天原生插件与外部同一 CLI 共用环境”的当前方案。依据见[设计](../specs/2026-10-19-plugin-design.md)、[Spec](../specs/2026-10-19-plugin-spec.md)及[当前插件架构](../../architecture/plugin-resources-cn.md)。

## 交付范围

- 详情按用户最终要求直接展示 provenance.upstream 声明：“开发者”为 Lark Suite CLI contributors，“插件版本”为 v1.0.98，许可与源码使用同一上游记录，不单列上游版本，不显示封装维护者和 0.1.0。封装作者与包版本仍如实保留在标准清单；没有业务上游固定版本时隐藏版本，不能把 GitHub 授权辅助 CLI 版本当作远程 MCP 服务版本。
- 资源页、插件详情及公开客户端取消插件上传、ZIP/目录导入和本地版本添加；独立技能和连接器维持原有入口。
- 删除旧扫描、外部准备 HTTP 路由及聊天四项系统插件操作，系统 Skill 引导当前智能体按原生方式管理聊天中的插件请求。
- 系统新增安装、显式版本切换复验配置目录中的真实归档及内容摘要。包内 provenance 或旧资源 SourceKey 不能单独作为来源证明。当前目录不再提供的历史版本不能新增安装，既有伙伴固定关系保留；真实目录及归档缓存可离线复验。
- Codex、Claude Code 原生插件由各自 CLI 管理，不同步到系统资源、伙伴安装或统一授权状态；自有插件继续以执行级原生格式附加。
- 插件仓库双语 README 与维护指南明确自有库、原生环境和授权职责。GitHub 仓库已更名为 neux-plugins。统一来源规范、JSON schema、英文修改说明及官网本地图标已纳入正式 [v0.1.0](https://github.com/JieWaZi/neux-plugins/releases/tag/v0.1.0)，main、tag 与目录 sourceCommit 均为 `ec4463db8a428301d629e58db906978a1aae2ad4`。按用户要求强制覆盖同一 tag 与自有目录、两个完整 ZIP、两个公开资料文件、校验文件；保留原有 14 个固定程序和许可资源，先更新 ZIP、公开资料与校验文件，再更新目录，正式 latest 继续使用 v0.1.0。
- 应用在当前功能分支工作区实施；代码复审与提交只包含插件相关改动，保留无关工作流讨论文档。

## 接口验收

使用最终源码新构建 Core，运行隔离数据库、受管目录及本地 HTTP 目录/ZIP：

| 验收项 | 结果 |
| --- | --- |
| 旧扫描与外部准备接口 | 均返回 HTTP 404，未创建资源 |
| 自有库查询与只读详情 | 最终 Core 直接使用默认公网 latest 源读取 v0.1.0 的真实公开资料，未创建资源 |
| 未安装、未授权的说明阅读 | 详情、双语 README 和技能正文可读；本地真实发布产物 HTTP 验收只请求一次目录、各一次资料，完整 ZIP 请求为零 |
| 安装与阅读并发 | 慢 ZIP 下载期间，冷、热缓存详情均独立返回；并发恢复请求数约束保持 |
| 自有库准备与伙伴安装 | 归档 SHA-256 核验通过，安装成功 |
| 原生插件与资源分离 | 系统只显示自有库资源，外部配置及模型凭据哨兵未改变 |
| 伪造来源与版本切换 | 复制真实 provenance 但改写内容仍拒绝，原伙伴版本保持 |
| 目录离线与既有固定关系 | 有真实缓存可复验；缺少证据拒绝新增，既有关系保持 |

接口验收没有使用用户真实 CLI 安装或账号；结果不代表模型已主动执行原生安装。

## 授权弹窗整改

安装授权弹窗等待首次状态、外链、验证码或二维码时显示同位置 loading，返回后替换为实际操作。安装弹窗等待授权时移除重复的重新授权、取消本次认证与重新检查入口；非二维码授权失败、取消、过期或尚未启动时保留就近重试，编辑页保留完整管理入口。关闭 X、Escape、遮罩及组件卸载只取消本弹窗尚未完成的会话，启动回执晚到时补偿取消；已完成认证和安装成功自动关闭均不撤销共享账号。二维码刷新先等待旧会话退出，取消失败可见且能重试。

后续布局验收反馈调整为二维码或授权码居中、说明及刷新在展示区下方，底部使用绿色全宽授权按钮；复制仅保留图标及复制成功勾选反馈。准备插件保存的默认英文名不再误判为用户重命名，所有已声明译名按当前语言展示；真正自定义名称仍优先。已用“目录名称为 slug、准备后保存英文默认名”的实际数据形状复现并修复中英混显，模型、卡片与详情 15 项定向测试通过。

对应三文件最终 40 项测试通过；独立审查另跑授权面板与安装弹窗 38 项通过。没有操作用户真实界面或账号。

布局与中英名称问题修复后，授权面板、安装弹窗、设置、名称模型、卡片与详情六个文件合计 56 项定向测试通过，TypeScript 与改动文件格式检查通过。

## 通用授权阶段提示

插件仓库以共享 schema 定义 `notice.messages`，允许 `en`、`zh-CN` 纯文本文案；包内展示声明使用任意具名映射，供应商与阶段名称不进入宿主判断。桥接在当前挑战中选择提示，前端以黄色提示卡按界面语言展示。飞书首次应用设置挑战发送二次扫码说明，下一账号权限挑战不携带提示。缺省无提示；新挑战、取消、到期和终态均清除旧提示，提示映射隔离驱动、事件与响应引用。

- 前端提示阶段替换、英文回退及取消隐藏先红后绿；授权面板、安装与设置三文件最终 43 项定向测试通过，TypeScript、ESLint、格式检查通过。
- Go 授权与桥接两包测试、vet通过；生命周期 race 重复三次通过，含非法提示拒绝、深拷贝、阶段替换及终态清理。
- 独立评审无阻断；另验证前端两项、插件声明四项通过。
- 插件包内真实双语声明、两阶段桥接及取消路径通过 fixture 测试，固定快照构建可重现。更新保留 `v0.1.0`，不替换已经安装的不可变内容；旧测试包需删除后重新安装读取新声明。没有运行真实账号扫码验收。

## 原生环境验证

临时原生 home、无真实模型请求的实际 CLI 探针：

- Codex `0.161.0`：API 模型账号和原生模型账号两种模式均成功初始化；`skills/list` 同时发现外部 fixture 插件及 NeuxBot 本轮附加插件。
- Claude Code `2.1.159`：`--settings` 模型覆盖下仍发现原生注册的 fixture 插件；通过管理入口禁用后，外部同一 CLI 立即读取到禁用状态，再启用成功。随后经真实 CLI 管理入口从本地 marketplace 添加并安装，在外部列表中无错误，实际初始化同时返回外部 `outside-probe` 与自有 `managed-probe`，模型凭据来源为本轮 API 环境。
- 原生管理入口持久写入共享 home、其余命令保留当前执行环境、模型秘密清理、外部启停引起能力重建、受限执行不挂载外部包，由定向自动化覆盖。

模型账号与插件所有权分别处理：原生/API 模型账号使用共享根及进程覆盖；Codex 订阅模型账号保留隔离根，共享可复用的插件与 OAuth 存储。绑定 home 的 Secrets 后端与隔离订阅账号组合被准确拒绝，包括首次授权；profile、未知覆盖及本机管理配置层也准确拒绝。显式配置与开关按真实 CLI 的配置、enable、disable 优先级处理。使用不支持的组合时需选择原生 CLI 账号或 API 模型账号；不可观察的企业云策略不在承诺范围。具体条件见当前插件架构，不宣称全部认证后端均可透明共享。

真实探针验证初始化、发现、启停及本地 fixture 原生安装，没有运行公网插件下载、真实账号登录、供应商授权或模型业务请求。文件型 OAuth 首次写入和外部替换由 fixture 自动化覆盖；钥匙串语义依据实际 CLI 实现检查，未运行真实钥匙串登录。

## 代码复审与废弃内容清理

三路子代理分别复核目录与安装、执行与授权、前端交互。安装授权终态缺少重试入口的回归已先复现再修复；执行测试默认使用临时数据根，清理源码目录内遗留的 146 个原生环境缓存文件。移除无运行时引用的空内置插件指南、对应生成与校验逻辑，以及旧供应商专用授权说明键。原有插件导入组件、扫描和准备接口、聊天系统安装实现的删除一并纳入交付。

分叉首次续聊不再把新工作区缺失缓存误判为能力变化。接纳事实冻结原生插件摘要，分叉沿既有配置继承，并在续聊时与当前环境比较；相同摘要继续原生子会话，变化或未知摘要仍拒绝。真实接纳、分叉和续聊的回归先失败再通过，未放宽能力核验。

最终定向验证：前端插件模块及资源页 17 文件、108 项测试通过，TypeScript、改动文件 ESLint 与格式、UI 策略通过；插件相关 API、内部包、安装服务、能力 contract、Repository Controller 通过，Execution、Chat、事件日志三个相关 Go 包完整通过。OpenAPI 及生成客户端一致性、系统 Skill、插件资产、文档链接与差异格式检查通过。
