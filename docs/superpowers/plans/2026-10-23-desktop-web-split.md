## 1. 分工与实施边界

主负责人维护共享应用、平台接口、Core 客户端、协议生成与集成。Web 负责人维护配对、会话、上传、独立启动与发布。Desktop 负责人维护原生宿主、Core 文件/Git 服务、原生资源装配与安装包。

首期是浏览器访问本机 Core 的个人使用场景。默认使用回环地址，同一数据目录只允许一个 Core。预览使用隔离数据目录；正式使用与 Native 保持既有数据布局。不复制数据库，不引入云端账号或远程多用户部署。

验证按变更点执行，未运行全量检查。真实模型、浏览器视觉和 Windows 运行验证独立记录，不能用构建通过替代。

## 3. 重要实施决定

### 单份业务与单份执行

`packages/frontend` 保存共享业务界面和领域逻辑，`web` 与 `desktop` 保存各自入口和宿主动作。文件、Git、终端执行统一通过 Core；Native 只保留窗口、系统打开、原生通知、内嵌浏览器等宿主能力。服务不存在时明确报错，不返回空列表或假成功。

资源适配器和终端适配器按首次使用加载。设置中的账号与运行环境页面延迟加载。Native 首屏预算包含真正等待的宿主模块，不以分块掩盖启动成本。

### 终端方案调整

原计划探索 Go PTY；最终保留成熟 node-pty 和 xterm 屏幕实现，把执行所有权迁至 Core。Node worker 通过 stdio JSONL 连接 Core，关闭输入即清理子进程，不是独立守护服务。Web 包需要 Node.js 22+；Native 使用内置 Electron Node 模式。macOS 有真实运行证据，Windows 发布前仍需原机验证。

### 范围和破坏性动作

已接纳 Chat 使用冻结范围；创建 Chat 前，用户明确选择的目录签发 draft scope，支持搜索和分支选择，但不能用于创建终端。文件删除确认时记录版本，提交删除时携带该版本；Git 丢弃及目录删除使用共享确认组件。变更失败不自动重放。

### 生成器一致性

开发机旧全局 toolx 曾遗漏 OpenAPI 路由。生成脚本现按 server/go.mod 安装固定版本到临时目录，再生成并归一化契约。SDK 只能由生成命令更新。最终完整 api:check 检出 Git 兼容修复新增的两项 413 错误响应，按生成结果更新后，对受影响 OpenAPI 与 SDK 再次生成并比较，结果一致；未用手工编辑规避检查。

## 4. 启动与交付命令

在仓库根运行：

```sh
pnpm install --frozen-lockfile
pnpm dev:web
pnpm dev:native
```

两条开发命令分别启动 Web 或 Native，不应同时使用同一数据目录启动两个 Core。Web 首次使用需要终端输出的一次性配对码；过期后在启动终端输入 `pair` 重新签发。

```sh
pnpm build:web
pnpm package:web
pnpm start:web
pnpm build:native
```

`build:web` 只构建静态资源；`package:web` 装配 Core、Web、Pi bridge、终端、技能、插件和许可证，`start:web` 从该发布目录运行。`build:native` 构建桌面安装包，保留各平台资源与预算检查。

## 6. 集成与回退

合并前先处理主工作区既有冲突，再审查共享目录移动与行为变更；不能覆盖主工作区未提交内容。切换版本前关闭 Web、Native 和活跃终端，确认 Core 已退出及数据锁释放。回退应配套回退 Core、Web 和 Native 版本，使用原数据目录；不要尝试恢复旧 scope、sessionId 或已经关闭的 PTY。
