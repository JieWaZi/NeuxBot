# 伙伴委派与团队会话统一计划

基线：已公开推送的主会话路由与工单协作提交 `7a1255a5`。本次继续在原分支 `codex/superagent-main-conversation` 开发，优先验收用户实际能看到的会话与状态；保留已有历史、权限和外部绑定。

## 工单和投影

1. 核对伙伴及团队主会话是否经同一接纳入口。沿用 `server/services/mainconversation` 和 `server/services/workticket`，不要重新发明一条调度队列。
2. 在 `server/apis/work_tickets` 增加或扩展受授权的列表投影。源主会话按根工单获取子单；接单伙伴按自身获取受托工作。工作来源、状态和执行身份只来自工单或执行记录。父子关系、来源与接收者按相应的主体授权核验。
3. 用针对性集成用例验证 A 发起 B 执行、结果只回原对话、团队接收者成员校验、续接原任务和请求重放。历史任务仍由原记录解析，不能同时在两条执行链写入。

## 前端导航

1. `packages/frontend/src/app/layout` 负责左栏模式切换与导航。伙伴页保留伙伴和团队主会话，并按工单归属展示委派与受托工作；会话页保留独立会话的目录、图标和状态。模式与当前打开会话是独立状态。
2. 搜索常驻且跨两个视图。展开只动当前树，工作结束只换状态，不自动移动或取消选中。清楚区分加载中、无结果与错误。
3. `packages/frontend/src/modules/chat` 负责主会话委派状态、结果来源及配套设置侧栏。伙伴与团队共享同一种状态展示，B 的私人主会话不复制 A 的消息。主会话右侧替换旧摘要和会话列表；工作会话保留原工具。
4. 为切换时保留当前聊天、完成后仍在树中、跨伙伴搜索、可访问来源跳转和权限拒绝写回归测试。动效尊重系统减少动态效果设置。
