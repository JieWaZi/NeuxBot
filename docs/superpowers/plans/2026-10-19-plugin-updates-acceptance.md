# 插件更新验收记录

依据：[实施计划](2026-10-19-plugin-updates.md)、[插件 Spec](../specs/2026-10-19-plugin-spec.md)与[当前架构](../../architecture/plugin-resources-cn.md)。

## 交付行为

- 插件库按目录展示发布版；我的插件和伙伴详情保持实际安装版，准备新版不提前替换旧内容与派生组件。
- 同一可信来源存在更高语义版本时，卡片右上角和详情提供更新入口。同号、目录回退、未知版本及会使任一伙伴降级的混合目标不提示升级。
- 搜索框前是无灰色悬停背景的 Info 图标；交互浮层显示上次成功检查时间和刷新按钮，允许指针移入点击和键盘操作，输入框后没有独立刷新按钮。没有常驻时间行，检查中禁用，失败仍保留缓存及本机安装。
- 更新弹窗没有伙伴选择；确认准备固定归档，满足新版本配置、信任和账号要求后，一次更新全部伙伴，保留各自启停状态。
- 最终事务校验全部安装集合、每个原版本与配置修订，统一切到同一目标；并发变化全部回滚。旧执行保留原接纳快照，不做历史兼容分支或迁移。

## 审查与验证

独立代码审查发现并修复两个组合问题：新必填配置导致展示摘要无账号、从而阻止已完成真实授权的更新；同版本重新准备时旧 Query 缓存导致草稿持续冻结旧配置修订。回归分别覆盖真实授权面板与无会话已连接账号、保存冲突后重读同目标并用新修订提交。准备前的伙伴区域也采用可滚动布局，防止多伙伴或窄窗口裁切确认按钮。

服务端验证通过：

- `go test ./apis/plugins ./internal/plugins/catalog ./services/plugininstallation -count=1`。
- `go test ./services/execution -run Plugin -count=1`。
- 相关 API 与 catalog 包 `go vet`。
- catalog 并发刷新、冷读与关闭取消用例的定向 race。
- `pnpm api:check`，生成客户端与 OpenAPI 一致。

前端最终验证：插件模块与两个直接受影响的资源页测试共 19 文件、150 项全部通过；最终 Info 交互浮层调整后，三个直接相关测试文件另跑 41 项通过；TypeScript、全部改动文件 ESLint 与 Prettier、UI 策略及差异检查通过。独立审查运行更新弹窗与插件列表两个文件、22 项通过，最终 Info 调整后另跑列表 13 项通过；最终源码复核无剩余可复现阻断。真实布局仍未运行视觉验收。

## 验收边界

只使用临时目录、测试账号响应与本地 HTTP fixture，未启动真实应用、浏览器、供应商账号或模型。未验证真实桌面布局、账号授权、公网发布升级与其他平台；未运行全量 check 或全仓测试。中途磁盘空间不足导致一次 Go 链接失败，清理可重建旧构建缓存后定向重跑通过，未改变业务资料。
