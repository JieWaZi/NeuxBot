# 插件发现新版与伙伴更新实施计划

> 用户已确认“插件库显示最新、我的插件显示已安装、落后版本可更新”的完整行为并要求实现；在当前工作区继续，保留无关修改。
> **For agentic workers:** 使用 subagent-driven-development 按下列边界实施并做最终独立评审。

**Goal:** 实现目录检查、准确版本比较、卡片提示及全部伙伴更新的完整闭环。

**Architecture:** 目录元数据与伙伴安装仍分别为唯一事实；列表按精确 SourceKey 批量派生更新摘要，不下载归档或修改安装。更新先准备固定归档，再复用共享配置与版本切换事务，保留既有启停和运行快照。

**Tech Stack:** Go、现有目录缓存、React、TanStack Query、生成 OpenAPI Client。

**Spec:** 用户在本聊天确认的版本语义；当前模块职责见 [插件资源](../../architecture/plugin-resources-cn.md)。

## 约束

- 基线与无关修改记录在 `.scratch/plugin-updates/`；保留 shared/ui/resource-page.tsx、toolbar.tsx 和工作流讨论稿原修改；架构文档在其现有修改上更新。
- 不启动真实应用、浏览器、账号或模型；仅运行定向测试与检查，不运行全量 check。
- 不增加插件或更新影子表、不永久轮询、不自动升级、不允许降级或任意源导入。用户明确不需要历史兼容，不保留局部版本更新分支或数据迁移。
- 用户进一步确认：一次更新全部已安装伙伴，不提供选择。以包的语义版本判断新旧，来源必须完全匹配；用户展示版本复用真实上游资料，不拿辅助 CLI 版本冒充服务版本。
- 目录失败保留安装数据并表达未知或陈旧；显式检查通过现有插件事件刷新，只有准备/更新操作下载归档。

## Review Focus

- 已准备但未安装的新版不能覆盖“我的插件”的实际安装信息。
- 多伙伴不同版本在一次事务中统一更新；保留各自 disabled 状态。
- 检查失败、目录回退、同号不同内容、并发目录变化不能误报或静默换版。
- 配置变更兼容全部目标；授权、信任及乐观并发失败时不改变安装。
- 已接纳执行保留原版本、配置和身份快照。
