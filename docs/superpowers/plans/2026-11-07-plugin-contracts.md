# 标准插件、账号与管理扩展实施计划

> 状态：阶段一已按确认范围实现并完成本轮定向验收；阶段二仅保留后续方案，另行批准。
> 设计：[标准插件、共享账号与管理扩展](../specs/2026-11-07-plugin-contracts-design.md)。

## 1. 范围与依赖

本计划记录阶段一的实际交付与验证边界。包仓、解析、共享账号、安装执行、生成契约及前端闭环分别列项；实现完成不代替最终联合工件、真实平台、账号和视觉验收。

阶段一必须同时交付包仓库、Core、生成契约与前端安装／账号闭环。阶段二建立在第一阶段的固定内容、配置修订及统一账号 owner 上，但管理入口不依赖 authentication 声明。本轮不开发 management RPC 或 GitHub 仓库列表。

实际清理用户数据、提交、推送和发布均不在本计划授权中。验收使用独立新数据目录；不新增历史迁移、双轨解析或旧协议转发。

## 3. 阶段一工作包

### A. 包仓库与发布夹具

**主要位置：** neux-plugins 的 `plugins/*/plugin.json`、`mcp.json`、`skills/`、`.neuxbot/`、Schema 与发布脚本。发布工具从固定本地快照构建，不临时获取供应商内容。

- [x] 从唯一根清单构建发布包，把 OpenAI 信息和 NeuxBot 声明归到各自扩展。
- [x] 删除包根旧清单、旧命名空间、旧授权协议和多套原生源包；技能正文、许可、provenance 与业务版本保留真实来源。
- [x] 补标准 defaultPrompt、capabilities、支持链接、主题图标与品牌色；填写真实业务资料，缺失能力不造占位值。
- [x] 生成本地化提示词、连接说明和新版公开资料；保证提示翻译等长且索引稳定。
- [x] 提供纯技能、匿名 MCP、标准认证 MCP、包内新授权驱动四类夹具；实际未支持的认证目标有明确拒绝夹具。
- [x] 固定 Schema 与 Core 共用正常／异常样例，包括未知版本、越界路径、额外执行字段和秘密泄漏。

**依赖：** C02–C04。**交付：** 可复现 ZIP、catalog、details、摘要清单及夹具；不自动发布。

### B. 唯一包解析、展示与 Runtime 派生

**主要位置：** `server/internal/plugins/{package,presentation,integration,configuration,native_target,native_authentication}.go`、`catalog/{catalog,details}.go` 与对应测试。

- [x] 重写 Load 的唯一输入规则，移除 compatibilityFormat、旧清单／MCP 发现、旧原生源包选择。
- [x] 新解析快照记录目标契约版本；所有只消费持久 Package 的安装、账号、诊断与执行入口拒绝缺标记的旧快照，不靠重新读取清单才发现旧数据。
- [x] 解析 root com.openai、com.neuxbot、标准 MCP 服务认证；声明无效或不支持时明确返回状态错误。
- [x] 配置仅来自新显式 fields／bindings，删除展示名、组件和秘密字段的重复／隐式发现。
- [x] 补展示字段归一化、提示词单一来源、双语索引校验、主题资产安全读取和正文优先级。
- [x] 更新公开资料白名单与工件版本，不通过资料生成执行配置，不保留旧资料到 ZIP 的隐式补读。
- [x] Codex 使用目标根标准部分；其他保留目标按实际能力派生，不把输出适配重新接回输入解析。
- [x] 同步目录、组件、原文与受管内容测试；不改无关外部 CLI 原生插件发现。

**依赖：** A 的目标夹具。**解锁：** C05 详情 DTO 和前端静态展示可并行接入。

### C. 共享账号与新授权生命周期

**主要位置：** `server/repositories/models/plugin.go`、Plugin Repository、`internal/plugins/{authorization,commandbridge}`、`services/plugininstallation`、`global` 插件装配。

- [x] 保留资源、不可变版本、伙伴安装及共享配置；登记唯一 PluginAccount 和受保护材料，移除配置中的账号材料归属。
- [x] 定义账号代次的条件写、并发冲突和公开缓存读取；普通读取不解密材料，不恢复重启前动态摘要。
- [x] 升级唯一 owner，使授权、执行和未来管理租约同源；操作开始即隔离迟到结果，实际调用终止后再释放。
- [x] 实现 neuxbot-auth/1 初始化及新 envelope；不增加旧 auth 协议转发或协议猜测。
- [x] 复用已验证的二维码／验证码、进程组关闭、取消等待、内容租约和精确组件秘密绑定。
- [x] 按 C03 为实际支持的标准认证方式提供目标账号适配；不得借用 AI 账号或复制独立 MCP 账号。
- [x] 显式认证完成分别验证目标与仍安装的版本；外部认证失败保留安装，不伪装事务回滚了供应商状态。

**依赖：** C04、B 的声明类型。**解锁：** 安装／账号 API 和前端授权弹窗。

### D. 安装、配置、更新与执行固定事实

**主要位置：** `server/apis/plugins`、`repositories/controllers/plugin_controller.go`、`services/plugininstallation`、`services/execution/plugins.go`、`internal/plugins/runtime.go`。

- [x] 将静态详情、配置读取、缓存账号、显式核验和授权会话分为明确职责；首屏不默认返回全管理状态。
- [x] 普通配置保存与全伙伴更新使用不同用例；更新请求固定目标摘要、全部旧安装、配置修订和账号代次。
- [x] 保留准备不安装、逐伙伴安装结果、重复安装不切换版本、停用仍安装、下架仍可管理的真实规则。
- [x] 外部校验在事务外持有内容与身份；短事务再次核对全部确认事实并原子提交配置与版本切换。
- [x] 执行声明／快照加入账号代次或材料上下文，活动消费者保持租约，不能被退出／更新破坏。
- [x] 最后引用卸载、整体删除与准备后取消沿真实 owner 清理；失败保留关系，避免孤立授权或误删仍在使用内容。
- [x] 消费者完成迁移后直接删除旧 DTO、路由与代码，不保留转发包装；外部原生插件仍走原 CLI 边界。

**依赖：** B、C、C05。**交付：** 可供前端使用的实际接口与固定版本执行闭环。

### E. 生成契约与前端闭环

**主要位置：** `server/openapi.json`、前端生成目录、plugin 模块、已有聊天草稿和引用入口。

- [x] 通过 `pnpm api:generate` 生成契约；前后端只消费同一 DTO，不手写第二套 wire 类型。
- [x] 详情读取新标准展示与安全账号状态；区分安装、启停、授权、MCP 诊断和更新。
- [x] 配置和账号管理按用户操作惰性读取；页面浏览不启动授权／健康检查。
- [x] 示例点击仅填草稿；覆盖全局选伙伴、当前伙伴、无伙伴、尚未安装／停用、安装取消及返回。
- [x] 授权弹窗固定新上下文，会话晚到补偿取消；退出说明共享影响，停用／卸载保持各自语义。
- [x] 保留现有 browse 窄列表和 category；不把新详情字段、秘密或全伙伴关系放进浏览摘要。

**依赖：** B 可先完成静态字段；账号与安装交互依赖 D 的实际接口，不使用模拟成功状态验收。

## 4. 阶段二后续方案（待另行批准）

### F. 独立管理声明、驱动与 Core 用例

**主要位置：** `internal/plugins` 内按职责建立管理深模块，复用插件唯一 owner；`server/apis/plugins` 实现单入口用例。

- [ ] 实现不依赖 authentication 的 management 声明、information／collection 及受限字段校验。
- [ ] 驱动初始化返回能力与静态声明取交集；不提供任意命令、URL、表达式或页面加载器。
- [ ] 完整上下文绑定 source、搜索、游标、配置修订、账号代次和实际驱动指纹；结束时再次核对。
- [ ] 显式 POST 接纳、requestId 结果读取与取消共用一个请求 owner；资源事件只唤醒对应结果，不新增轮询。
- [ ] 实现 30 秒期限、实际终止后释放、大小限制、100 页／10 MiB 缓存及失效／淘汰。
- [ ] 错误准确区分前置条件、忙碌、取消、超时、上游、协议、内容与过期，不更新伙伴或聊天候选事实。

**依赖：** C、D、C06。**必须先交付：** 无 authentication 的匿名管理夹具，用于证明管理与授权没有从属关系。

### G. GitHub 样例与通用组件

- [ ] 驱动封装上游分页和账号绑定游标；宿主不解析供应商响应或任意上游 URL。
- [ ] 前端固定组件展示账号、权限、仓库及失败；本地搜索明确只覆盖已加载项。
- [ ] 不展示 GitHub App 仓库选择，不把仓库列表当执行白名单。
- [ ] 用两个身份完成读取中退出／切换、旧游标、迟到结果、空集合、上游失败及取消的验证。

**依赖：** A、F 的正式夹具和接口；供应商代码留在包仓库。

## 6. 当前验证边界

Core 的解析、公开资料、账号／授权、插件 API、安装、执行及 Repository 定向验证已有通过证据；SQLite 覆盖独立账号材料加密、CAS、失败保留安装、完整更新集合、有索引窄读与查询预算。普通 ReadStates 在配置 payload 损坏时仍可读取公开修订，账号与配置主键查询计划为 SEARCH，未新增 JOIN。

包仓指定的五个授权测试文件共 47 项通过，覆盖三包严格初始化与上下文拒绝、双阶段挑战、真实子进程取消／EOF／忽略 TERM、观察挑战后由测试时钟触发到期、私有身份与 launcher 的引号路径／argv／预加载隔离。测试使用受控供应商及下载边界，生产期限未缩短。Windows launcher 已审查批处理引用和环境清理，尚无原生 Windows 执行证据。

三包标准／扩展 Schema、公开资料和 Core TestBuilt 联验通过；真实 Codex CLI 0.159.2 的 app-server plugin/read 识别三份根标准包、展示字段与 28／0／15 个技能，本次未安装或执行业务 MCP。生成命令重复运行后 105 份文件摘要不变。前端定向行为、共享类型、改动文件格式／样式与文档检查通过。Computer Use 已只读观察原生 OpenBot v0.63.0，并在隔离 NeuxBot 桌面真实 Core 查看列表、三条目录详情及浅暗主题。真实桌面窄容器与已安装伙伴详情没有执行，不能以浏览器模拟结果替代。真实供应商账号、跨平台钥匙串与网络业务不由这些模拟边界测试代替。
