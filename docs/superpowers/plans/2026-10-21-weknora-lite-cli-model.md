# WeKnora Lite 与 CLI 模型接口重写计划

> 使用 subagent-driven-development 并行执行，所有开发代理采用 GPT-6.1 high。用户已批准删除旧整理实现并按最新讨论重写，不提交或推送。

**目标：** 知识整理直接运行固定 WeKnora Lite 管线，CLI 仅提供模型生成服务；去除后台整理对伙伴、Chat、Execution、聊天 JSONL 和候选文件交接的依赖。

**架构：** 独立知识核心拥有任务、来源、批次、模型阶段与发布；宿主只装配模型配置、文档读取、权限和生命周期；Runtime 复用现有 ACP 协议与账号解析。前端只显示文档列表状态，失败诊断在状态悬停提示中展示。

**参考：** Tencent/WeKnora 固定提交 `8776a2d92d11ad3e76865d51cf3192e37e2a9976`，以该提交的 Lite 分支和实际源码为准。仓库中的旧候选与固定 worker 设计不再约束本次实现。

## 全局约束

- 保留现有库、原件、Wiki、检索、图谱及远端资源能力和无关修改；只删除旧整理专用实现。此项约束代码能力；用户后续明确授权清空本地开发知识数据库，实际离线操作按最新要求执行，原件文件不主动永久删除。
- 生成产物由原脚本更新。独立核心编辑源位于本次工作区的暂存源，随后通过 `knowledge:sync` 生成受管快照。
- 默认对齐上游 `Thinking=false`；Runtime 能力无法关闭时记录实际选择，不能将 low 宣称为关闭。
- 同库批次串行；批大小和 Map、Reduce、引用并发按固定上游配置；来源或页面局部失败不回滚兄弟成果。
- 中文文档与字段注释，保留上游许可及迁移来源，不扩宽架构检查和启动包预算。
- 自动化检查与真实账号、真实模型和视觉验收分别报告。

## 接口

`core.Generator.Generate(context.Context, core.GenerateRequest) (core.GenerateResult, error)`。

请求包括 `JobID/SourceVersionID/StageID/Stage`、`Messages[{Role,Content}]`、`MaxTokens/Temperature/Thinking`；结果包括正文、停止原因和必要诊断。每次生成独立上下文，上游允许的长度续写仅限本次调用。

`RunOrganize` 保留现有公开名称；删除生成端口的 Start/Await/Cancel、ExecutionID、候选校验及 next/submit 协议。

## 重点验收

- 空账号或模型不可用时不得假接纳生成；配置错误可在原区域修复。
- 失败或取消后不得把迟到结果发布为成功，已完成页面保持可见。
- 重启恢复不得创建新的伙伴聊天，也不得重复计入来源结果。
- 同文档多阶段、不同文档并发不得混用上下文或正文。
- 文档状态与失败诊断来自原件权威状态，原件预览不重复状态和过程。
