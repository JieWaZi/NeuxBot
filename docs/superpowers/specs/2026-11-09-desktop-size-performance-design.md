# 桌面交付体积与启动优化

## 目标与边界

核对用户所指约 200MB 安装包的版本和平台，按实际制品区分下载体积、展开应用体积、Renderer 资源和启动 JS。保留现有桌面、聊天、文件预览、PDF、Excel、终端与工作流能力；仅移除证实无消费的资源或限制过宽的依赖入口，不用延迟加载冒充安装包缩小。

在当前分支保留无关修改。真实应用与浏览器不打开、不控制、不截图；安装包可离线构建和检查。只运行受影响的定向验证，不运行全量测试，不放宽启动预算。

## 度量

现有本地 DMG 是旧 NeuxAlly 制品，不能作为当前源码包体积。公开 v0.2.0 的 macOS arm64、Intel 和 Windows 安装包分别约 121.52、134.67、139.72MB；约 200MB 文件的来源仍需核对。下载 MB 使用十进制，MiB 使用二进制，不混用压缩安装包和展开应用。

当前 Renderer 原始产物为 45,921,043 字节。原生交付已有 Brotli 文本编码，前后统计必须走相同的交付和安装包压缩链，不把已存在的压缩收益计成本次优化。首屏入口 509,449 字节超过 500,000 预算；工作台实际启动链 4,378,240 字节在 4,500,000 预算内。

## 已确认修改

- 将工作流和自动任务文案从欢迎阶段入口移至工作台同步注册，保留中英文和回退；工作台仍计入真实启动成本。
- 文件代码预览使用显式支持的 Shiki 语言和两个现有主题，保持原有扩展名映射、嵌入语法和 token 颜色，不交付全量语言与主题入口。
- 原生构建显式只使用 KaTeX WOFF2；Web 保留已有字体回退。原生 PDF 交付剔除没有消费者的 QuickJS 沙箱文件，保留 PDF 解码、字符映射、标准字体和许可。
- 删除没有源码消费者的两张旧欢迎图。终端 node-pty 交付排除 source map 和测试，不擅自更换 ABI 或删除实际加载的二进制。
- 粒子材质单独放大 20% 作视觉体积补偿，不扩大头像布局槽或改变毛绒比例。

## 验证与剩余边界

定向验证真实语言入口和 token 等价、欢迎至工作台的文案导入顺序、原生与 Web 资源差异、PTY 过滤、头像资源交接与形变。统一生产构建后核对 manifest、原始及 Brotli 产物、安装包内容和大小；能完成离线打包时输出真实本地制品，不自动发布。

Electron 动态库、Core 的实际双 SQLite 使用、PDF 解码和文档 worker 不能仅因体积大删除。额外 Go 构建标签若受第三方源码缺陷阻断，记录实测与风险，不在本次优化中引入新的依赖 fork。
