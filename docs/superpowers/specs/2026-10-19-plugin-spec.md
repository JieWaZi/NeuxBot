# 插件 Spec

[设计与职责](2026-10-19-plugin-design.md) 是本轮范围依据，当前架构以 [插件资源](../../architecture/plugin-resources-cn.md) 为准。

## 1. 系统插件来源

- 插件库只接受 neux-plugins 发布的受维护条目；可配置 HTTP 镜像或本地目录清单用于分发与测试，不提供任意本地包或远程 URL 导入。
- 目录条目绑定完整来源提交、固定下载 URL、包路径和 SHA-256；下载失败或摘要不符不建立系统安装。
- 不提供上传、目录扫描、ZIP 扫描、导入或新增本地版本接口。关闭 HTTP 路由并移除生成客户端，不仅隐藏界面。
- 原生插件不登记为系统资源、不进入插件及派生技能/连接器列表、不参与伙伴启停、配置和卸载。
- 新增安装和显式版本切换重新核对当前目录真实归档及内容摘要；仅有 SourceKey 或包内 provenance 不能证明来源。可通过来源绑定的索引及摘要核验归档缓存离线验证。
- 目录已经移除的历史版本不能新增安装或显式切换；既有记录和伙伴固定快照不自动清空，本轮不增加历史数据迁移。

## 2. 聊天与原生环境

- 聊天使用当前 CLI 自己的插件安装和认证机制，与外部相同 CLI 使用同一原生插件环境。
- 不再向智能体暴露 `plugins.catalog.search`、`plugins.catalog.get`、`plugins.installations.install`、`plugins.installations.get` 系统操作，旧操作请求准确拒绝。
- 系统 Skill 不再要求用 allycli 安装插件，也不把原生安装拦截为系统安装。
- 普通执行可使用外部已安装并启用的插件，后续执行可发现其原生变更；原生配置为权威，不创建软件侧影子安装表或双向同步事实。
- 共用必须涵盖发现、安装注册与启停，不能只共享缓存而保留私有安装注册文件。
- 账号选择、模型服务和秘密保护沿现有账号模块；不能为共享插件覆盖外部 auth.json、模型配置或会话数据。
- 受限执行按既有能力范围处理，不因外部插件启用而绕过白名单。

## 3. 自有能力与适配

- 插件使用标准原生清单、skills、MCP 与相关资产。自有库包的语义和依赖由维护者验证。
- 内部解析器和 adapter 保留，只服务自有发布包与执行级目标派生，不作为对外通用转换产品。
- Codex/Claude 优先使用受验证的原生交付方式，自有插件不能写入外部 CLI 的持久安装注册关系。
- 没有原生插件机制的受支持目标使用经过验证的 Skill/MCP；不对任意 CLI 承诺兼容。
- 伙伴安装继续固定自有包版本、配置修订和账号身份；当前活跃执行不因新安装而改写快照。

## 4. 统一授权与展示

- `.neuxally/integration.json` 定义受支持授权策略、桥接入口及精确目标绑定，不重复标准清单身份。
- 插件桥接处理供应商细节；Core 管理身份占用、真实状态、取消、期限和私密凭据；前端渲染结构化动作，不按插件名增加特例。
- 动作限受支持的链接、二维码及验证码；打开链接或点击完成不能代替供应商账号核验。
- 原生第三方插件自己的认证归 CLI；不在系统构造其统一账号状态。
- 详情直接读取固定包 provenance.upstream 的 author、tag/version、license、repository；飞书开发者为 Lark Suite CLI contributors，插件版本为 v1.0.98。没有版本声明则隐藏；不单列上游版本，也不显示封装作者与封装包版本。真实包 author/version 和封装修改说明继续保留在清单及来源记录中。
- 自有插件保持中英文业务 README、名称和简介及声明图标；目录在安装前提供可展示图标。维护信息在开发文档及来源声明中，公开详情不展示原生实现路径和摘要。

## 5. 版本发现与更新

- 插件库读取当前发布目录；我的插件读取实际安装内容，准备未安装的新版本不能替换其展示。
- 更新摘要精确绑定来源、语义版本及固定归档；普通本机读取只使用轻量目录缓存，不等待远端或下载完整包。
- 卡片右上角和详情提供更新，资源列表提供显式检查；检查失败保持本机内容与陈旧语义，复用插件事件，不增加轮询。
- 用户更新时覆盖全部安装伙伴，不提供选择。先准备固定目标并满足信任、共享配置及真实授权，再原子提交完整安装集合。
- 更新保留每个伙伴启停；安装集合、原版本或配置修订发生并发变化时整次拒绝，旧执行继续使用其接纳快照。
- 详细职责和故障边界以[插件架构](../../architecture/plugin-resources-cn.md#发现新版与统一更新)为准。

## 6. 验收

| 编号 | 触发 | 预期 |
| --- | --- | --- |
| PLG-01 | 打开全局及伙伴插件资源页、详情页 | 没有上传、导入和本地版本操作，库安装仍可用 |
| PLG-02 | 请求旧扫描/准备接口 | 路由不可用，不登记资源或版本 |
| PLG-03 | 请求聊天旧系统插件操作 | 能力未公开且请求被拒绝，无安装副作用 |
| PLG-04 | 从自有目录准备、授权并安装 | 摘要固定、真实状态和伙伴关系保持既有契约 |
| PLG-05 | 临时外部原生环境已安装插件 | 普通执行可按原生规则发现，系统列表没有记录 |
| PLG-06 | 在相同原生环境执行安装/启停 | 外部同一 CLI 可读取持久结果，后续执行不覆盖结果 |
| PLG-07 | 受管插件附加交付 | 外部插件和账号配置未被受管清单覆盖；自有能力仍加载 |
| PLG-08 | 受限执行与原生外部插件 | 能力范围检查保持，不能隐式加载越范围组件 |
| PLG-09 | 目录发布较新版本、已有旧安装 | 插件库显示发布版，我的插件保持安装版并提示可更新 |
| PLG-10 | 同号、回退、来源不同或准备未安装 | 不误提示升级，不覆盖实际安装展示 |
| PLG-11 | 显式检查成功或失败 | 成功刷新目录，失败保留安装与陈旧状态；均不自动升级 |
| PLG-12 | 确认更新、存在多伙伴及禁用伙伴 | 无选择控件，全部原子切至同一目标，启停保持 |
| PLG-13 | 确认后安装集合、版本、配置或目录变化 | 拒绝不一致目标，不部分提交或静默换版 |
| PLG-14 | 新版需要配置或授权、已有活跃执行 | 满足真实准入后更新，已有执行快照保持 |

定向自动化、真实 CLI 初始化与真实供应商账号验证分别记录。未经授权不操作真实用户环境或运行 UI。
