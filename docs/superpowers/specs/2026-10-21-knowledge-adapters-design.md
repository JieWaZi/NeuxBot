# 知识库统一操作适配设计

后续 API 集成、统一远端接入及上传／整理时机以 [API 集成规格](2026-10-21-api-integration-design.md)为准：后端自动识别服务类型，自有远端上传与整理分开，WeKnora 保持上传自动处理并在上传前提示。本文保留统一领域操作和完整资源身份的适配边界，不要求调用方选择提供者。

## 目标与范围

所有现有知识库行为经统一的知识库 Adapter：库读取、创建、配置与删除；资料列表、上传、预览、下载、整理、重建、删除和清理恢复；Wiki 目录、页面、索引、编辑、历史与删除；图谱与页面定位。界面不直接选择本地或远端生成客户端。

用户明确要求目录悬停菜单提供新建子目录、重命名和删除；远端不支持的操作保留入口，点击明确提示“远端能力未支持”。权限不足与协议不支持分别反馈。远端动作不能误落到同 ID 本地资源。

## 约束与实现选择

- 本地 Adapter 使用本机知识 HTTP API；远端 Adapter 使用连接范围下的 HTTP API，内部适配 custom 和官方 WeKnora 的能力差异。
- 复用现有生成 SDK、TanStack Query、版本和稳定 requestId；未知写入结果继续原请求对账，不能静默重复提交。
- 协议支持、主体权限、资源或配置条件分别表达；能力读取失败不能推断允许。
- 保留当前目录最多两层、同级重名拒绝及非空目录拒绝删除的规则；不增加级联删除。
- 完整读取远端目录层级，保留身份、父子关系、计数；取消与读取错误不得伪装为空目录。
- 自有远端已具备的能力接入真实接口。当前没有协议合同的宿主配置、远端分块预览等返回明确不支持，不使用本地配置补齐。
- 本地与远端复用交互；远端整理使用服务端 profile，不携带本机 Runtime 或凭据。
- 中文文案、共享菜单与 Dialog；hover、focus 和菜单打开时可访问操作，避免嵌套 button。
- 不操作运行中的应用，不提交、不推送，保留已有工作区改动。
