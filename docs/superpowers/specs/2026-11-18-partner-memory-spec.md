# 伙伴记忆功能规格

状态为待实施。适用于 Web 与桌面的共享伙伴记忆页、聊天与 botcli。内部流程、数据所有权和复盘时序见 [伙伴记忆架构方案](2026-11-18-partner-memory-design.md)。

## PM-01 记忆只归属伙伴

- 记忆入口位于伙伴详情。「新建记忆」直接打开该伙伴的表单。搜索、日期筛选、编辑、遗忘和已有变更历史均以当前伙伴为范围。项目下拉、项目标签和项目记忆入口退出。
- 记忆 API 从路径中的伙伴 ID 确定归属。botcli 从已授权执行确定归属。查询、创建、更新和遗忘统一采用伙伴范围；旧 `scope`、`projectId` 请求参数返回输入错误，旧项目条目和其他伙伴的条目不对当前伙伴公开。
- 升级后保留既有伙伴条目的 ID、正文、时间和变更历史。旧项目记忆与旧命令回执保存在本地升级备份中，活跃查询和模型上下文只可访问迁移后的伙伴数据。升级中断后可以重试。项目删除退出记忆清理，伙伴删除仍清理其活跃记忆与复盘状态。

## PM-02 区分核心记忆与普通记忆

伙伴记忆页按顺序展示「核心记忆」和「普通记忆」。分类用两个分组标题表达，行内显示记忆正文和现有相关信息。搜索和日期范围同时应用于两组，服务端在分页前过滤分类，两组分别查询、加载和显示空状态。

- 新建、迁移、伙伴命令和自动复盘产生的条目默认进入「普通记忆」。
- 普通条目提供「设为核心记忆」，核心条目提供「设为普通记忆」。切换保留原 ID 与正文。确认成功后，条目在符合当前筛选条件的目标组中出现，离开原组，刷新页面后分类一致。移动期间一个 ID 最多显示一次。焦点返回目标条目的操作入口，目标条目暂不可见时落到目标分组标题。
- 每位伙伴核心快照总预算为 **8 KiB**，按最终序列化的 UTF-8 字节数计算，包含结构与标识开销。设置为核心或编辑核心条目超出预算时，保留原内容与分类，显示可理解的错误。取消核心资格和遗忘会释放预算；并发操作共同遵守同一上限。
- 中英文分组名称为「核心记忆」/ `Core memories` 和「普通记忆」/ `Regular memories`。浅色、暗色与窄容器都用标题及布局传达分类，键盘可完成分类操作。

## PM-03 在会话中使用记忆

| 类型     | 使用方式                                                                 |
| -------- | ------------------------------------------------------------------------ |
| 核心记忆 | 在合格的普通伙伴聊天中直接作为上下文数据附到原生模型输入。               |
| 普通记忆 | 伙伴按任务需要调用已有的 `memory entries search/get`，在授权范围内检索。 |

- 新原生绑定、替换、分叉后的首轮或交付状态未知时，发送当前核心快照。原生绑定和核心版本均相同的热续聊只发送新增用户输入。分类变化、核心正文更新或遗忘后，下一轮交付新版本。清空全部核心条目时交付空快照。
- 聊天界面和公开历史保存用户原文。核心快照是模型参考数据，权限和指令优先级由既有运行时策略控制。先前已经交付的内容仍受原生会话历史的保留规则约束。
- 核心读取依赖本地伙伴身份与确定的工作台入口，适用于普通伙伴聊天，包括已绑定项目或临时工作目录的会话。独立的团队、工作流、自动任务、IM 与内部生成入口排除。加载核心快照失败时，本轮聊天继续，下一次合格轮次仍可交付。关键路径只读取有界本地快照。

## PM-04 自动记忆

- 设置入口内按伙伴开启，默认关闭。启用时显式选复盘账号和模型，并说明脱敏后用户原文会送至所选模型服务。开启语义索引时，待保存条目正文沿用现有 Embedding 配置。
- 只有启用代次下，工作台发起、未绑定项目或临时目录的普通伙伴聊天成功轮次计数。按公开 Chat 独立累计 **20 个成功轮次**，或至少 **3 个成功轮次且空闲 15 分钟** 后触发。在途轮次期间推迟空闲触发。关闭标签页只是导航，重启补齐游标后的合格终态。
- 单批最多读取 **20 轮、24 KiB 用户文本**的有界增量，只将脱敏后的用户原文和批内消息标识发给模型。因文本预算拆批时，继续处理至触发时冻结的终态上界，包括少于三轮的尾批。继承历史、建档、档案优化、IM、团队、自动任务、工作流、失败和取消轮次排除，分叉后新发的合格轮次正常计数。
- 模型提出带来源的长期事实。Go Core 校验来源、敏感信息、伙伴归属和重复内容，自动新增普通记忆。空结果也推进处理游标。关闭、更换复盘账号或模型时，使旧待处理批次失效，从新代次接纳的轮次重新计数。删除归属或主动遗忘后拒绝迟到结果。重复批次幂等提交，后续自动候选按规范化正文排除已遗忘的同文条目。
- 待处理批次可在重启后继续。持续失败在该伙伴的记忆设置中展示原因和重试动作。复盘成功在记忆列表和原变更历史中体现，聊天发送与交付不等待复盘模型。

## PM-05 复盘会话临时化

- 每批新建一个无工具的独立原生会话，运行一轮，返回 JSON 候选。Go Core 是唯一记忆写入者。
- 成功、失败、取消和重启后，公开 Chat、共享原生 JSONL 和 CLI 历史里都没有这次复盘的提示、过程或原始回答。应用能够回收临时工作目录与临时原生状态，保留的用量凭证只有调用身份、模型、用量和无正文的终态元数据。
- 仅当运行时同时验证无工具与无原生历史落盘两项能力时开放自动复盘。首个候选运行时为 Claude。暂不可用时说明原因，伙伴手工记忆和核心注入仍可用。
