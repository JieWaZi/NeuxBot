# 伙伴记忆与技能学习功能规格

状态为待实施。适用于 Web 与桌面共享的智能体设置、伙伴记忆、伙伴技能、聊天与 botcli。内部流程、数据所有权和复盘时序见 [前后端设计](2026-11-18-partner-memory-design.md)。

## PM-01 记忆只归属伙伴

- 记忆入口位于伙伴详情。「新建记忆」直接打开该伙伴的表单。搜索、日期筛选、编辑、遗忘和已有变更历史均以当前伙伴为范围。项目下拉、项目标签和项目记忆入口退出。
- 记忆 API 从路径中的伙伴 ID 确定归属，botcli 从已授权执行确定归属。查询、创建、更新及遗忘均限制在当前伙伴范围。
- 本功能按新数据结构交付，历史数据迁移、归档与旧命令回执兼容均不在范围内。删除伙伴时清理其记忆与复盘状态。

## PM-02 区分核心记忆与普通记忆

伙伴记忆页按顺序展示「核心记忆」和「普通记忆」。分类用两个分组标题表达，行内显示记忆正文和现有相关信息。搜索和日期范围同时应用于两组，服务端在分页前过滤分类，两组分别查询、加载和显示空状态。

- 用户新建和伙伴命令产生的条目默认进入「普通记忆」。自动复盘可把跨会话反复需要的事实新增为核心记忆，预算不足时作为普通记忆保存。用户人工编辑或切换分类后，自动复盘尊重该选择。
- 普通条目提供「设为核心记忆」，核心条目提供「设为普通记忆」。切换保留原 ID 与正文。确认成功后，条目在符合当前筛选条件的目标组中出现，离开原组，刷新页面后分类一致。移动期间一个 ID 最多显示一次。焦点返回目标条目的操作入口，目标条目暂不可见时落到目标分组标题。
- 每位伙伴核心快照总预算为 **8 KiB**，按最终序列化的 UTF-8 字节数计算，包含结构与标识开销。设置为核心或编辑核心条目超出预算时，保留原内容与分类，显示可理解的错误。取消核心资格和遗忘会释放预算；并发操作共同遵守同一上限。
- 中英文分组名称为「核心记忆」/ `Core memories` 和「普通记忆」/ `Regular memories`。浅色、暗色与窄容器都用标题及布局传达分类，键盘可完成分类操作。

## PM-03 在会话中使用记忆

| 类型     | 使用方式                                                                 |
| -------- | ------------------------------------------------------------------------ |
| 核心记忆 | 在合格的普通伙伴聊天中直接作为上下文数据附到原生模型输入。               |
| 普通记忆 | 伙伴按任务需要调用已有的 `memory entries search/get`，在授权范围内检索。 |

- 新原生绑定、替换、分叉后的首轮或交付状态未知时，发送当前核心快照。原生绑定和核心版本均相同的热续聊只发送新增用户输入。分类变化、核心正文更新或遗忘后，下一轮交付新版本。清空全部核心条目时交付空快照。
- 聊天界面和公开历史保存用户原文。核心快照通过本轮独立上下文作为模型参考数据交付，权限和指令优先级由既有运行时策略控制。先前已经交付的内容仍受原生会话历史的保留规则约束。
- 核心读取依赖本地伙伴身份与确定的工作台入口，适用于普通伙伴聊天，包括已绑定项目或临时工作目录的会话。独立的团队、工作流、自动任务、IM 与内部生成入口排除。加载核心快照失败时，本轮聊天继续，下一次合格轮次仍可交付。关键路径只读取有界本地快照。
- 记忆服务、复盘或可选技能暂不可用时，普通聊天可发送和接续。伙伴自行判断已有记忆和技能是否有用。并行会话共用同一伙伴的已校验技能目录时，等在途轮次结束后再切换投影。

## PM-04 自动记忆与共用复盘

- 自动记忆及技能学习按伙伴独立配置，默认关闭。两项共用后台复盘、同一 Chat 进度和同一 CLI 配置。轮次接纳时记录各功能资格与设置代次，开启新功能只纳入开启后接纳的轮次。
- 每个 Chat 在累计配置数量的合格成功轮次后触发，默认 **20 轮**，可选 5、10、20、30、50 轮。至少 **3 个合格成功轮次且空闲 15 分钟** 后触发。在途轮次期间推迟空闲触发，关闭标签页只是导航。每批最多 20 轮、24 KiB 脱敏证据，按冻结终态区间拆批，继续处理剩余轮次。重启后从已提交边界恢复。
- 记忆复盘限未绑定项目或临时工作目录的普通伙伴聊天。模型接收脱敏用户原文、来源标识及有限的相关已有记忆。两项同开时在同一次调用中标注两类证据用途。模型可提出新增、更新或遗忘，每项操作都须引用合格用户消息。
- 自动更新或遗忘仅作用于已提供给模型、由自动流程写入且当前未受用户保护的条目。手工创建或编辑的正文持续受保护。自动生成的条目手动设为核心时受保护，改回普通后恢复自动更新和遗忘。复盘期间条目有变化时按修订号跳过旧提议。合法变更写入现有记忆历史，并同步更新搜索索引和核心快照。
- Go Core 校验伙伴、输入资格及来源，并按规范化正文去重。空结果也推进进度。关闭一项功能后，丢弃该功能旧代次的迟到结果，继续处理保持启用的功能。切换 CLI 或实际调用配置使旧批次失效，从新配置下接纳的轮次重新计数。配置暂不可用时暂停，同一配置恢复后可继续。保存记忆和完成复盘都不阻塞聊天。

## PM-05 复盘会话临时化

- 每次复盘判定与技能正文生成分别通过一轮独立文本会话完成。Core 不挂载应用工具，也不批准原生工具请求。共用复盘失败时整批重试。技能生成和发布失败可从原聊天独立重试。Go Core 校验结构化输出并负责领域写入。
- 成功、失败、取消和重启后，Core 的公开 Chat 与共享原生 JSONL 均无复盘提示、过程或原始回答。Core 回收自己管理的临时目录，保留调用身份、模型、用量和无正文的终态元数据。
- 已接入且启用的智能体可用于复盘。原生工具和本地会话历史取决于适配器能力。Claude 临时模式关闭原生工具和会话历史。Codex 确认原生临时线程后才接收正文。其他智能体沿用各自支持的限制。所选 CLI 或账号暂不可用时暂停复盘并显示原因，等待该配置恢复。伙伴手工记忆和核心注入仍可用。

## PM-06 智能体设置

- 「设置 → 智能体 → 记忆与学习」提供「使用的智能体」和「整理频率」设置。默认跟随伙伴新开普通对话时使用的 CLI、账号和模型，也可全局指定专用 CLI、账号和模型。自动记忆和技能学习共用这套配置。
- 「配置伙伴」二级页按功能展示所有伙伴的开关。技能学习开启后可选择先询问或自动保存。展示实际 CLI、暂停原因和适用的重试入口。语义检索沿用现有 Embedding 配置、测试和重建入口。
- 开启时说明各功能实际向模型发送的数据。伙伴记忆页和技能页可跳回智能体设置并选中该伙伴。

## SL-01 判断是否值得学习

- 共用复盘先判断是否存在可复用的工作方法，每批可返回至多一条建议。优先识别用户对做法的纠正、失败后验证有效的方法，以及已明确验收的可复用步骤。优先修订已经覆盖同类任务且可由本地技能库修订的技能，没有合适目标时才建议新建。提议只能引用该伙伴可用的技能和本批证据。
- 技能学习可覆盖普通伙伴聊天及其绑定项目的对话。启用时说明包含项目对话。临时目录、团队、工作流、自动任务、IM、建档、档案优化、分叉继承轮次和未成功轮次均排除。
- 技能证据包括脱敏的用户消息、必要的最终答复和有界的结构化工具步骤，例如工具名称、成功或失败、脱敏错误摘要及其后的有效步骤。附件、文件原文、完整命令参数和原始工具输出不读取或外发。无法安全清理的证据予以跳过。

## SL-02 保存或修订技能

- 「先询问」在来源聊天显示建议名称、学到的做法及消息来源，新建显示「保存为技能」，修订显示「更新技能」，另可选择「忽略」。用户确认后才调用模型生成正文。
- 「自动保存」在检测到有效建议后生成正文并保存。来源聊天将建议按提出时间显示，保存成功后按发布回执时间显示居中的生成或更新提示。点击技能名称打开详情。生成或发布失败保留可重试的建议。关闭技能学习停止自动判定及未发布的任务。
- 新建技能生成单份 `SKILL.md`，发布初始版本并为来源伙伴安装启用。修订 ZIP 导入或学习生成的本地技能使用现有版本校验，生成不可变新版本，保留未涉及的正文和其他资源，沿用正常的技能历史与回滚。
- 修订会影响其他已安装伙伴时，建议先在来源聊天标出影响并要求确认。内置、插件派生和 Git 同步的技能沿用各自的来源更新规则。
- 重复保存返回同一发布结果。切换技能学习模式或实际复盘 CLI 配置，以及删除来源聊天或伙伴，会作废尚未发布的旧任务。已发布技能继续通过技能库管理。
