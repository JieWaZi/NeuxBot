# 文档约定

## 文档职责

README 负责项目介绍与入口；CONTRIBUTING 负责贡献流程；AGENTS 负责智能体阅读路由和约束；CONTEXT 只定义核心业务词汇。

指南面向使用者，说明操作、结果和可见限制。架构文档面向开发者，说明当前职责、身份、权威数据、主流程和故障边界。工程约定负责以后如何修改代码。

## 写作规则

- 文档使用中文；源码注释语言遵守[后端约定](backend-cn.md#6-go-常量注释错误和日志)的目录规则，其他关键业务注释使用中文；命令、协议标识和第三方许可保留原文。
- 根目录 `README.md` 默认使用英文，`README.zh-CN.md` 提供简体中文；两份 README 保持内容对应，并在顶部提供双向语言切换入口。
- 直接描述当前实现，更新原章节；不追加日期修正、重构过程、废弃方案或实施进度。
- 未实现方案和执行计划放在 Issue 或独立讨论中，不进入当前能力说明。
- 每条规则只在一个权威位置维护，其他位置使用链接。
- CONTEXT 的定义保持一到两句话；字段、状态机、页面布局及算法归模块文档。
- 不重复维护完整 API、CLI 参数或 SDK 声明表；链接生成来源和实际发现入口。
- 新模块有独立职责和阅读需要时才增加文档；普通修复更新原文。
- 示例只用虚构数据与通用路径，不使用个人目录、真实密钥、内部服务或研究材料。
- 图片与相对链接必须随仓库可用；示意图明确标明用途，实际截图不得带私人数据。
- 第三方组成集中记录于根目录 THIRD_PARTY_NOTICES.md，不将真实来源描述为自主实现。

## 完成条件

修改行为、协议或业务含义时同步更新权威文档，运行 `pnpm docs:check` 检查链接与私有路径。实际能力以源码和对应测试为依据，未经验证的范围不得写成已通过。
