# NeuxBot UI 标准

## 适用范围与优先级

本文定义跨页面基础与普通控件默认。插件、技能、连接器的目录、详情及添加页，以及工作流的资源目录，必须同时完整阅读[资源目录与详情 UI 标准](resource-ui-cn.md)；其组件角色和上下文规则优先于本页普通按钮、Toolbar、Card 与页头的默认。业务能力决定真实操作和信息，尺寸由共享组件与语义 Token 维护。验证边界见[界面核对](../discussions/workbench-ui-review-cn.md)。

## 体系与组件

Tailwind CSS 4 是页面样式体系，shared/ui 持有基础组件，Radix 提供交互原语，Lucide 提供默认图标。业务页面复用共享组件和变体，不重复实现基础控件或引入第二套样式系统。

界面保持紧凑桌面密度。浅色、暗色及跟随系统使用相同布局；主题由 ThemeProvider.resolvedTheme 与根 data-theme 决定。普通 Card 使用语义背景、排版和留白分层，无装饰性常驻边框和阴影；只有可交互 Card 或行承担 hover，静态详情填充 Card 不整卡变色；选中态通过语义背景、勾选控件表达，不添加黑色边框或黑色轮廓；键盘焦点与错误使用对应的语义强调色。资源 Card 的根表面和 CardBody 统一管理 hover，业务内容区不得叠加独立 hover 背景。

删除、移除等危险动作的文字保持危险语义色，普通态与悬停态一致。菜单复用 `DropdownMenuItem variant="destructive"`，资源局部动作复用 `catalog-danger`；不被普通菜单高亮样式覆盖为正文色。

## 排版与尺寸

界面使用随应用分发的 Inter Variable，中文回退系统字体；代码与终端使用系统等宽字体，不从远端加载字体。排版使用 type-_，text-_ 仅承载颜色。

| Token                   | 字号／行高         |
| ----------------------- | ------------------ |
| caption                 | 11 / 16px          |
| ui                      | 12 / 16px          |
| body                    | 13 / 20px          |
| label                   | 14 / 20px          |
| title                   | 16 / 24px          |
| page-title              | 20 / 28px          |
| display                 | 24 / 32px          |
| conversation            | 15 / 26px          |
| conversation-title      | 24 / 32px          |
| conversation-heading    | 20 / 30px          |
| conversation-subheading | 17 / 26px          |
| conversation-code       | 14 / 22px          |
| chat-inline-code        | 0.875em / 继承行高 |

常规字重使用 400、500、600；不使用低于 11px 的文字。普通文字按钮通过 size 使用 28 / 32 / 36px 阶梯，普通表单控件使用 control-sm / md / lg 的 28 / 36 / 44px 阶梯，普通独立操作提供至少 36×36px 命中区。资源目录和详情按[角色矩阵](resource-ui-cn.md#2-组件角色与操作矩阵)分别核对尺寸、行高、图标与实际命中区，不把普通默认或单个 catalog 尺寸应用于全部角色。所有操作均需可访问名称。

图标 icon-xs / sm / md / lg / xl 为 12 / 14 / 16 / 20 / 24px，默认描边 1.5。正文链接使用 `icon-inline` 随所属字号缩放；控件继续使用固定图标阶梯。头像 avatar-xs / sm / md / lg / xl / hero / docked 为 24 / 32 / 40 / 56 / 80 / 128 / 160px，保持完整身体与透明边缘。

工作区文件类型图标统一使用 `WorkspaceFileTypeIcon` 的本地 Material Icon Theme 精选素材；文件树与消息文件引用共用同一文件名和扩展名匹配规则。工作区文件树目录行只保留展开箭头，不重复放置文件夹图标；文件行保留彩色类型图标。消息文件引用无常驻边框和底色，悬停时呈现与图标主色协调的轻背景；文字与悬停背景共用文件类型语义色，浅暗主题均保持可读对比度；用户气泡采用适配反色表面的同色系明度，其中表格和代码块仍按正文表面适配。普通操作图标继续使用 Lucide。

间距使用 4px 网格，紧凑控件允许既有 2px、6px 半步。radius-xs / sm / md / lg / xl / 2xl / 3xl / 4xl 为 4 / 6 / 8 / 12 / 16 / 20 / 24 / 32px。文字按钮和 Scene Tab 使用 radius-control，圆形和胶囊使用明确变体。

尺寸与颜色的实际权威定义在 shared/styles、shared/ui 及其变体；禁止通过页面 className 重写基础组件的高度、字号、圆角、图标与阴影。

## 表面、布局与表单

- Scene 使用统一页面背景和 pt-shell-content-top。相同层级优先共享表面，不反复嵌套 Card、标题与分隔线。
- 任务看板与自动任务的统计卡片用于选择筛选，再次点击已选卡片保持当前筛选；通过任务总数或筛选字段切回全部。
- 列表复用 ResourcePageSurface、Header、Toolbar、SearchField 和 CardGrid。普通资源工具栏保留标题、计数与适用的批量选择操作，控件达到可读下限后才换行；普通资源卡片列表首批九项，滚动追加后续批次，不显示翻页控件。插件、技能、连接器及工作流资源目录使用[专用规范](resource-ui-cn.md)的浏览结构。
- 资源 Card 的伙伴使用摘要最多重叠展示四个真实头像，保留总使用数；没有头像资料时使用中性占位。插件、技能及连接器目录与详情使用[专用规范](resource-ui-cn.md)。
- 详情页 PageHeader 操作区从左到右：启用状态（开关与说明）→ 维护操作（编辑、删除等图标）→ 带文案的主 CTA（`PageAction` 的 `intent="primary"`）在最右；多个带文案动作时，主 CTA 仍置末位，其余用 `secondary` 等语义区分。资源目录详情的身份头与危险操作按[专用规范](resource-ui-cn.md#2-组件角色与操作矩阵)分配，不套用普通页头的维护动作排列。

- 响应式以所属 Scene 或 pane 的实际容器宽度判断；空间不足时换行或调整结构，保留字体与命中区。
- 表单控件填满所属列；名称、路径、URL 和多行字段使用整列。筛选、搜索、日期范围使用共享语义宽度。
- 单选、短枚举和搜索多选分别复用 Select、ResourceFilterSelect、SearchableMultiSelect。浮层匹配触发框并限制于视口。
- Popover 筛选触发使用 FieldControlTrigger，不用操作 Button 模拟输入字段。
- 字段提供可见标签、示例及必要说明。错误就近显示，说明与错误分别表达；不将数据模型全部展开为默认表单。
- 设置使用唯一 Settings Scene，导航、顶栏路径与内容分别拥有自己的区域，分类导航与内容独立滚动；详细结构见下节设置规范。
- 主面板、分组和浮层各有明确层级。常驻阴影只用于有空间语义的浮层，不作为普通内容分组装饰。

## 插件目录与详情

插件、技能、连接器及工作流资源目录的设计约束、组件角色矩阵、Shell、浏览行、详情 Item、信息字段、危险区、表单保存条、主题适配和业务扩展统一维护于[资源目录与详情 UI 标准](resource-ui-cn.md)。修改相关页面须完整阅读，不以本页普通资源默认代替专用规范。

## 设置

设置分为导航、路径、正文三个区域，正文使用分组行结构。共享 `SettingsContentShell`、`SettingsGroup`、`SettingsRow` 与 `SettingsFieldGroup` 管理排版和表面，页面不复制基础控件外观。

- 左栏保留本地搜索和可独立滚动的平铺分类，不重复设置标题或“集成”分组标题。通用、智能体以及集成保留真实入口；账号不另占顶级分类，订阅和 API 配置进入所属智能体详情。页面导航使用共享 settings 外观及 13/18 排版，不套用模态框的 14px 导航；键盘焦点与选中态分开，图标操作使用 36px 命中区。
- 右侧正文的外容器最大 784px，包含桌面水平 32px、窄容器 16px 留白；上、下各 24px，分组间隔 24px。顶栏已有分类路径时，正文不重复大标题和说明；需要识别集成对象的二级详情使用 48px 图标、名称、真实状态及必要简介，连接三级直接从配置分区开始。
- 智能体列表为默认智能体行、带局部搜索的已安装列表、其他可安装项；整行进入详情，不在列表中嵌套全部配置表单。详情头右侧放启用和权限，不另设重复用途分组；已安装时显示账号、API、版本与模型，未安装时先显示版本和真实安装动作。没有真实能力的动作不展示。默认账号、模型、推理与 Fast 是本产品已有能力，在详情中编辑。
- 集成总览按 IM、API、MCP 上下排列三个分组，不显示页签。IM 的微信、飞书、企业微信整行进入平台二级，连接行进入三级；API、MCP 仅展示真实入站服务。资源库出站连接器归属不变。二级保留紧凑身份，IM 平台、API 与 MCP 服务身份头均复用共享的悬停／键盘焦点返回，回到集成总览；连接三级没有正文标题、品牌身份头或悬停返回，只使用顶栏面包屑导航。各层顶栏路径始终挂载，三级路径为「集成 / 平台名称 / 连接名称」。旧 connection、binding、chat 深链及服务旧入口继续定位真实对象。
- 连接三级使用配置、聊天授权、对话记录、危险操作四个分区；状态在配置 Card 只出现一次。编辑在所属 Card 内，连接配置与授权项一次编辑一个作用域，保存和取消停留当前连接。新增扫码、专用授权、新对话、删除确认保留所属弹窗。空授权、空记录位于同一白色语义 Card 内，空记录不显示零计数、表头或分页；有记录保留真实数据和既有客户端分页。
- 设置分组复用 SettingsCard、SettingsFieldGroup 与设置行，浅暗均使用语义表面、12px Card 圆角、无装饰外框和阴影；行间分隔左右内缩 16px，父子不得重复绘线。同一 Card 的普通字段须位于同一相邻行容器，不逐行重包字段组或叠加分区间距。设置行说明为 13/18，字段标签为 14/20；嵌入 Card 的字段组不再增加表面。复杂编辑的保存条使用 SettingsPageFooter，归所属 Scene 底部槽，与正文滚动区平级，最小 60px；跨 Portal 提交显式关联原表单。dirty 草稿离开由同一守卫覆盖路径、浏览器后退和实际切换／关闭 Scene，关闭其他标签或不离开作用域的操作不提示放弃。
- 设置危险操作使用完整 SettingsDangerZone：最后分区、填充 Card、具体动作与真实影响、右侧危险 ghost 操作，再进入领域确认。危险文字沿本产品常红规则；不以裸红字替代危险区。删除连接保留 revision、依赖摘要与活动运行／待发送阻断，已有内部对话按原领域规则保留。
- 普通设置行至少 64px，内边距为纵向 12px、横向 16px。标题和必要说明在左，控件或局部动作在右；窄容器换行且保留字体和命中区。填充分组无常驻装饰边框和阴影，同级字段只用分隔表达层次，静态区不增加整卡 hover。
- 设置文字动作复用 `Button size="settings"`：高度为 32px、14/20、横内边距 12px、图标 14px；添加账号与添加密钥按本产品要求使用分组标题右侧的纯加号，提供 Tooltip 和访问名称，密钥分组不重复显示 API Key 摘要行。安装为主色实心动作。版本行只保留检查更新或更新，不并列重新检测图标；模型刷新、列表检测和重启使用无背景图标及 Tooltip，列表检测位于搜索框前，重启在提交时表达忙碌状态。
- 模型配置保留并排字段，以白色语义表面的 fieldset 和轻边框表达整体边界，暗色主题使用同一语义 Token。字段使用原有 field 表面，不改为每字段一张卡，账号模型表单保留原密度。已有有效目录的后台刷新不禁用编辑；只读能力握手不算账号写入，默认值保存不等待无关目录读回。刷新按钮独立表达后台读取。
- 不提供程序路径、前置参数、配置目录和手写运行时模型的设置入口，也不展示安装命令。未安装、安装失败或当前平台不能自动安装时，保留“官方下载”入口，使用无边框单图标、Tooltip 和可访问名称，通过宿主打开对应官方页面，供用户自行安装后重新检测。
- 自动保存的单项设置就地提交，复杂账号表单提供自己的保存及取消；API Key 的创建动作归密钥分组，不放到整页标题。不增加全设置统一确定按钮。
- 状态标签使用共享 `StatusPill`，包含 6px 状态点；已连接用成功浅底与语义成功文字，待处理用警告浅底与文字，未安装／进行中用中性表面，停用用轻轮廓与空心点，不使用黑色描边。安装、程序可用和鉴权分别判定，未知鉴权不能显示已连接。标题副行只放已知事实，不展示没有本地归属依据的“无伙伴使用”计数。
- 未安装时保留登录分组的未安装提示，版本行右侧提供真实安装；进行中同处显示阶段／进度与取消，失败显示安全的具体原因并提供重试。已安装时显示本机版本及来源，初始提供“检查更新”，仅官方版本检查确认存在更高版本后显示“更新”；检查失败或版本未知不能视作已是最新。受管程序完整性损坏时显示“重新安装”，同版本也允许修复，不提示当前无需更新。状态 GET 不查询官方网络，列表检测继续负责本机发现。独立重启行回收该智能体的闲置原生连接并重新探测，活动任务或关闭失败按真实结果反馈，不伪装成功。
- 系统账号行按原生认证能力提供登录或重新连接；不支持强制重新授权的已连接 Codex 提供“验证连接”，现有账号确认与完成新授权按后端结果分别表达。受管订阅账号使用自己的授权入口，不混用账号范围。密钥只在 API 分组管理，不在系统账号行重复放置入口。只有原生明确支持的 agent 方法或已核实的 CLI 设备授权命令可启动网页登录；没有密钥管理能力的本机凭据限制可提供官方配置说明。登录弹层以共享状态呈现准备、等待授权、连接确认及失败，使用局部图形与适度动效，减少动态效果偏好下保持静态。等待时不虚构已打开浏览器或完成百分比，成功不只显示一句文字；验证码、原生授权链接、取消和重试留在所属状态。取消携带精确任务身份，旧弹层不能取消后续登录。
- 智能体详情复用 `PageHeader` 的悬停／键盘焦点返回操作，回到智能体列表，与技能详情保持同一行为。程序删除归危险操作，确认框显示实际程序位置并明确保留账号、登录和伙伴；未知归属不能显示可执行的假删除。更新与删除均以当前使用的安装来源及后端能力为准。
- 首次读取用对应行和分组的骨架，分类、路径和返回保持可用；后台刷新保留已有数据，错误在原操作附近提供重试。密钥不在摘要中明文展示，破坏性账号操作确认后执行。

## 动效与状态

使用 instant、quick、standard、slow、deliberate 及现有共享 Presence。只过渡实际变化属性，不使用 transition-all 或缩放至零的弹入。监听 prefers-reduced-motion，隐藏、离屏与卸载时暂停或释放动画。

Shell、输入区及可用操作先挂载，加载与错误在所属区域展示。内容首次加载使用与实际布局对应的 Skeleton 骨架屏；知识库卡片、文档列表、Wiki 目录及正文均遵守这一约束，不用转圈或加载文字替代内容骨架。首次加载、空、无结果、后台刷新、离线、错误、取消与禁用分别表达；后台刷新保留已有数据。

资源列表与详情首次读取统一使用匹配内容布局的 Skeleton，不使用居中 Spinner 替代整块内容。列表骨架复用资源卡片网格，详情和正文按分区、文本结构占位；页头、返回、筛选和页签保持挂载。加载区域提供 `role="status"`、`aria-busy="true"` 与可访问名称，骨架本身对辅助技术隐藏，并遵循减少动态效果偏好。Spinner 仅用于按钮提交等局部操作反馈。

统一 Toast 与通知按通知模块契约工作。提示消失不代表阅读或业务处理；当前错误仅在对应操作恢复后清除。权限请求和问答保持原领域入口。

## 工作台与可访问性

Shell 模块栏宽 52px，区域顶栏高 38px；资源库紧随伙伴入口，设置留在底部。工作看板只通过侧栏顶栏前进箭头之后的通知入口进入，不在模块栏或更多菜单重复提供。按本产品 Shell 布局要求，有左栏时各模块（含资源分类侧栏）与正文之间显示同一竖向分隔线；顶部对应列位置的短竖线在所有模块常驻。无左栏时正文使用完整宽度，不额外增加正文竖线；所有左侧栏共用全局宽度偏好，默认 280px、范围 216–400px；有左侧栏的页面均支持拖动，跨页面切换沿用同一宽度，不按模块设置独立宽度或最小宽度，也不收起。伙伴详情及子页在左栏展示概览、项目、记忆、资源，聊天保留身份列表。主／右顶栏使用同一表面与 Tab 变体；Tab 之间留 4px、轨道两侧留 8px，+ 跟随最后一项并参与横向滚动。关闭按钮置尾，悬停统一作用于整个 Tab，不增加 X 的独立底色。伙伴／团队分段条真实命中区 36px，28px 灰轨道内放 24px 白色选中面，内缩且完整圆角。

Scene 和 pane 组合聊天、文件、浏览器、终端等内容。聊天与工作台并排时为聊天保留至少 320px，拖动、键盘调整和缩窗遵循同一限制；所属容器不足以容纳聊天和工作台最小宽度时，工作台使用已有浮层布局，不挤压聊天或卸载内容。切换布局保留文档、原生视图和终端身份。工作流会话与画布位于主容器，资源库归属与侧栏规则见[插件目录与详情](#插件目录与详情)，其他文件进入右侧工作台。关闭内容时释放其资源。

伙伴模块默认直接显示聊天。没有已验证的最近聊天时进入当前伙伴的聊天入口，由原查询解析最近会话，无会话则显示可输入的草稿。旧 `/wakers` 入口沿用同一聊天 Scene。侧栏新建伙伴在右侧打开创建 Scene，沿用伙伴列表；新建团队打开团队表单。

图标操作有 Tooltip 与访问名称；菜单、表单、分屏和弹层支持键盘及焦点恢复。键盘焦点使用主题色语义 Token，不使用黑色环；字段触发器只在 `focus-visible` 时强调边线，鼠标点击不留下深色焦点框。状态同时使用文字和语义色。普通文字对比度至少 4.5:1，重要图标与交互边界至少 3:1。

聊天输入容器保持轻量细边界，内部编辑器或按钮获得焦点时不叠加整圈聚焦外框；错误边界与局部按钮的键盘焦点提示分别保留。输入区 Git 分支控件的可见文字与 Tooltip 仅显示分支名称。多仓库时，控件的可访问名称、分支菜单和冲突确认框包含目标仓库路径。

运行时坐标、图表或编辑器高度、原生窗口适配允许必要布局值，重复使用时提升为共享 Token。任何例外必须解释真实需要，不通过修改检查规则绕过生产约束。

## 验证

按本次改动运行定向前端检查及 UI 策略检查；全量验证仅按用户明确要求执行。验证浅暗主题、窄容器、长中文、键盘、焦点、加载与错误状态。真实页面与原生视图的视觉验收需用户明确授权，并与自动化结果分别说明。
