# 团队协作

## 聚合与身份

Channel 保存团队配置，成员创建或修改时解析账号、模型、强度与 Fast 默认值；ChannelThread 在首次发送时保存成员、负责人、工作范围和有效执行设置。首次发送的显式成员覆盖在新对话接纳时解析，已保存配置不再次继承默认。每位成员对应一个 Chat，负责人的成员 Chat 同时作为主会话，不创建额外协调 Chat。

成员资格、负责人、Chat 映射与已解析执行选择保持原接纳事实。TEAM.md 和成员发现按这些成员身份批量读取当前公开档案；当前字段清空也直接生效，仅伙伴缺失时回退历史展示资料，不扩大成员资格。已解析空模型、强度或 Fast 保持原生默认，不因运行环境默认变化被重新填充。Fast 保留未指定、关闭和开启三态，随成员配置传入线程、成员 Chat 准备及负责人、成员、排队输入和结果通知派发。普通成员编辑保留已保存的显式 Fast 选择；改选智能体、账号或模型时清除原 Fast 选择。

ChannelTask、依赖、Attempt、补充输入与报告是结构化协作事实。任务状态不由聊天文字推断。负责人负责规划、分派、验收协调与必要汇总，明确提及可以路由到指定成员执行。

## 派发与报告

成员执行绑定 task、attempt 和能力期限，只能操作当前获准工作。任务正文包含标题、说明与所需上游结果，避免重复播种无关聊天历史。

线程详情按已有任务集合索引读取已接纳的首次派发、改派与失败重试，返回委派双方、尝试标识、接收执行与发起、派发和交付时间，不扫描同成员的补充历史。排队补充换人时单独记录改派原因；未接纳尝试释放或恢复后，继续接纳保留原派发原因。发起时间在创建任务、请求重试或改派入队时保存，每次尝试固定对应的发起时间，成员忙碌、接纳失败和普通任务编辑均不改写它。同一回复绑定的委派合为一行，按伙伴身份去重并保留首次出现顺序，共用最近交付时间；不同回复或尚未定位来源消息的记录独立保留。委派行居中呈现且不显示时间：接收端绑定执行对应的输入消息之前，发送端绑定发起任务的回复之前，不按晚到的接纳回执把提示追加到回复之后。点击伙伴打开该线程内对方的原 Chat；悬停与键盘聚焦使用头像色调及共享头像的临时表情。记录使用尝试的实际成员，后续重分配不改写原委派；显式用户提及不冒充伙伴委派。委派行只随当前聊天已加载的历史区间呈现，读到起点后补齐更早记录。

成员通过 botcli team reports submit 提交事实报告，包含实际成果、验证及重要限制。提交候选与任务终态分别确认。报告按 Attempt 幂等投影到负责人 Chat，保留真实作者身份；成员完整工具过程仍属于自己的 Chat。

满足单项直接交付条件的报告可作为用户结果，并使用共享消息卡片呈现；其他情况由负责人在任务状态稳定后协调或汇总，避免重复唤醒和重复结果。非直达报告按回复轮次和真实伙伴身份归组，默认收起，在负责人回复上方居中显示“收到来自…的消息”。点击伙伴名称独立展开或收起其本组全部消息，伙伴入口与委派提示复用同一头像色调、悬停表情和键盘焦点反馈。展开后复用普通消息 Card，不再显示专用报告标题与外框；报告截断提示仍就近保留。负责人尚未回复时也可查看已收到的消息，消息深链会展开目标伙伴。团队主会话与成员会话的回复显示实际伙伴头像和名称，时间统一放在卡片底部操作区右侧。每条头像均支持悬停交互；当前回复继续保留真实执行反馈，普通聊天仍只展示最新回复头像。

团队组合头像保持成员顺序，使用等大双列聚合：两人横向重叠、三人上二下一、四人完整排列，超过四人才使用数量补位。组合内单独校准 SVG 放大与视觉偏移，成员按顺序覆盖，沿透明身体绘制与所在行底色一致的轮廓，形成实际身体的重叠和遮挡，不改变全局头像或材质标定。侧栏组合头像与伙伴导航共用尺寸，悬停时成员共同切换表情，离开恢复。组合头像呈现成员身份，工作状态沿用团队角标；静态场景不启动交互与播放循环。其他场景沿用所属语义尺寸；聚合面部与间距比例参考本地 OpenBot，身体材质仍复用共享 Bloub。

## 控制与一致性

任务依赖在派发前判断；持久输入与结果通知采用明确状态及条件更新。迟到、重复结果不能覆盖新尝试，重启按持久事实恢复。

停止当前工作取消活跃成员执行并收敛排队协作，保留可继续阅读的对话。永久删除需要活跃工作结束及用户确认；删除整个团队或单个对话均保护外部项目目录。

前端按 thread 和 Chat 身份读取快照、历史与事件。团队 timeline 使用独立 Query 身份，持有负责人持久消息、成员报告和未投递输入；导航刷新不使其消息页失效。连续 Chat 事件直接提交原 Query，接纳回执交接已确认身份，健康 Chat 终态不重复读取正文。团队领域事件只对账真正变化的输入、报告、详情或导航；命令恢复与事件共用[查询刷新所有者](notifications-and-work-board-cn.md#查询与事件所有权)。成员切换不混合消息、文件权限或执行配置，隐藏 Scene 保留草稿并暂停所属读取与订阅。

输入框的团队工作状态直接复用目录与权限顶栏：错误优先，关闭错误后显示仍在进行的团队状态，空闲后恢复原工作范围与权限。工作成员入口同时展示头像与名称；排队消息继续在顶栏上方展开，不为团队状态另加一层。

时间线保留已加载连续区间及原分页下界，最新窗口变化不能丢失被挤出的旧消息；缺口恢复按服务端游标只补到缓存区间。普通任务变化只补 pending 窗口，断线恢复额外核对未直达报告；直达事件按原通知身份更新报告，较旧响应不能撤回已确认交付。旧纯正文页继续复用。

负责人和成员观察原 Hub 的准确 execution 生命周期，先订阅后读取 Outcome 补偿，不从零重放公开消息；成员仅终态读取本轮正文生成报告。未投递补充按 thread 任务集合、时间与角色游标在持久层限量，再有界合并，不逐任务读取全部补充历史。

实现入口为 services/channel、internal/teamwork、internal/teamcapability、modules/team 和共享聊天工作区。
