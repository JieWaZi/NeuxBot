# 团队协作

## 聚合与身份

Channel 保存团队配置；ChannelThread 在首次发送时冻结成员、负责人、工作范围和执行设置。每位成员对应一个 Chat，负责人的成员 Chat 同时作为主会话，不创建额外协调 Chat。

ChannelTask、依赖、Attempt、补充输入与报告是结构化协作事实。任务状态不由聊天文字推断。负责人负责规划、分派、验收协调与必要汇总，明确提及可以路由到指定成员执行。

## 派发与报告

成员执行绑定 task、attempt 和能力期限，只能操作当前获准工作。任务正文包含标题、说明与所需上游结果，避免重复播种无关聊天历史。

成员通过 allycli team reports submit 提交事实报告，包含实际成果、验证及重要限制。提交候选与任务终态分别确认。报告按 Attempt 幂等投影到负责人 Chat，保留真实作者身份；成员完整工具过程仍属于自己的 Chat。

满足单项直接交付条件的报告可作为用户结果；其他情况由负责人在任务状态稳定后协调或汇总，避免重复唤醒和重复结果。

## 控制与一致性

任务依赖在派发前判断；持久输入与结果通知采用明确状态及条件更新。迟到、重复结果不能覆盖新尝试，重启按持久事实恢复。

停止当前工作取消活跃成员执行并收敛排队协作，保留可继续阅读的对话。永久删除需要活跃工作结束及用户确认；删除整个团队或单个对话均保护外部项目目录。

前端按 thread 和 Chat 身份读取快照、历史与事件。团队 timeline 使用独立 Query 身份，持有负责人持久消息、成员报告和未投递输入；导航刷新不使其消息页失效。连续 Chat 事件直接提交原 Query，接纳回执交接已确认身份，健康 Chat 终态不重复读取正文。团队领域事件只对账真正变化的输入、报告、详情或导航；命令恢复与事件共用[查询刷新所有者](notifications-and-work-board-cn.md#查询与事件所有权)。成员切换不混合消息、文件权限或执行配置，隐藏 Scene 保留草稿并暂停所属读取与订阅。

时间线保留已加载连续区间及原分页下界，最新窗口变化不能丢失被挤出的旧消息；缺口恢复按服务端游标只补到缓存区间。普通任务变化只补 pending 窗口，断线恢复额外核对未直达报告；直达事件按原通知身份更新报告，较旧响应不能撤回已确认交付。旧纯正文页继续复用。

负责人和成员观察原 Hub 的准确 execution 生命周期，先订阅后读取 Outcome 补偿，不从零重放公开消息；成员仅终态读取本轮正文生成报告。未投递补充按 thread 任务集合、时间与角色游标在持久层限量，再有界合并，不逐任务读取全部补充历史。

实现入口为 services/channel、internal/teamwork、internal/teamcapability、modules/team 和共享聊天工作区。
