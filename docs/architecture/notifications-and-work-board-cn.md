# 通知与工作看板

## 事实归属

审批、提问、验收与工作流人工操作由原业务请求拥有。Chat 日志记录消息与执行事实，可读消息索引随原 Chat 投影和 `Chat.LatestSequence` 在同一事务更新。每个 Chat 独立保存阅读游标，每个可查看的原 Run 独立保存查看确认。

Go 从原容器、有效请求和阅读记录派生摘要。未读消息数、未读会话数、运行会话数、等待工作数、有效请求数、待查看工作数分别计算。伙伴聚合覆盖其可见会话；团队只计主对话的公开消息；工作流 worker 和 joined 子运行按所属运行归并。操作和跳转仍使用真实请求及会话身份。铃铛只显示 `hasAction || hasUnread` 的小点。

知识库整理不生成应用通知、弹出提示或未读成果；进度、失败和结果由知识库页面展示。原 `knowledge` 主题按 `knowledge.task.changed` 更新任务、来源和活动，实际发布的 `knowledge.content.changed` 才刷新内容与目录；普通资源配置变化仍使用 `knowledge.changed`。本地成功接纳由已提交事件统一刷新，无推送远端的主动对账另行保留。

## 阅读与提示

自动阅读以窗口聚焦、Scene 在前台且合格正文实际呈现的消息为边界。消息深链先定位目标，再启用视区阅读。主动标未读可后移游标并推进代次，跨窗口的旧命令在服务端冲突。持久 hold 由下一次用户真实打开或主动标已读解除，重连和查询刷新只对账。晚到文件引用更新原消息，保留其阅读身份。

提问卡片由有效请求驱动待回答提示，助手答复沿用现有未读计数规则。会话列表用问号气泡标记待回答，用盾牌勾标记待审批，用数字显示未读。需要操作的标记优先，处理后显示仍存在的未读。

任务看板可用伙伴默认模型配置发送首条消息，权限优先使用完全访问，可在发送前调整。已知智能体不支持完全访问时使用其可用权限。原聊天接口接纳后打开对应对话。“需要处理”按有效请求展示，“待我查看”按原工作容器展示，两栏独立分页。下方“全部任务”统一显示各状态的记录。日期只筛选下方记录。

审批、回答和验收调用原领域接口。团队验收提交实际呈现的代次，原事务同时核验代次和任务状态。工作流待办查询与人工提交均核验原运行及其 joined 祖先的状态和期限。读消息、确认查看和收起提醒均不改变请求状态。“全部标为已查看”冻结范围内的原消息或运行身份和阅读代次，分批提交。删除与代次冲突按项返回。重开页面后从权威查询恢复实际结果。

Electron 主进程在共享连接上消费已提交的 live 事件。原会话提交者发布请求和终态消息的稳定身份，主进程弹出前查询实际公开归属及有效性。自动任务或工作流创作现场接纳、团队首发就绪时，补交本次执行在归属确认前已提交的终态。终态提示以原执行释放会话占位为前提。原提交和绑定交错时，主进程按同一消息身份合并核验与展示。窗口焦点和提醒偏好控制显示，预览开关控制显示内容。请求结束时收回对应提醒。点击时重新核验原消息或请求，直到窗口派发仍保留该点击的有效性，目标失效时回工作看板。接纳回执对账、初次读取、缺口恢复与重连通过查询恢复。

## 实时通道

Electron 主进程持有一条带认证的 Core WebSocket，Renderer 通过受限 Bridge 订阅固定主题和资源。普通 CRUD 继续使用 HTTP；本机文件和 Git 复用共享原生监听。

事件升级默认接受无 Origin 的原生连接、`ally://app` 与开发来源 `http://127.0.0.1:1420`。额外 Web 来源由 Core 进程环境变量 `ALLY_EVENT_TRUSTED_ORIGINS` 显式配置为 JSON 字符串数组，例如 `'["http://127.0.0.1:1422","https://ally.example.com"]'`，设置后重启 Core。只接受完整匹配的 HTTP／HTTPS origin；域名使用 ASCII／punycode，IP 支持 IPv4／IPv6，可省略默认端口或明确指定 1–65535 端口。不接受通配、用户信息、路径（包括末尾 `/`）、查询或片段；配置中任意无效项都会拒绝所有额外来源，既有默认来源不变。来源白名单不替代本机令牌认证，也不授予任何业务资源权限。

初始及恢复读取权威快照。连接交付序号与领域持久游标分别检查；缺口、Core 重启和缓冲超限要求快照或历史对账。未知、离线与陈旧状态保持可见，不能表示为正常零值。

消费者加入已经打开的共享资源订阅时，也通过既有 resync 入口补读权威状态；共享连接的游标不能证明新消费者已收到此前事件。快速隐藏和恢复期间，旧退订与新订阅可能交错，不能仅凭连接仍然打开就省略恢复。恢复通知只交付给仍属于该订阅的消费者。

Chat 的公开持久事件使用原日志中的递增游标，允许内部绑定、输入消费记录及合并后的旧检查点造成间隔，不要求相邻公开事件的游标相差一。前端按真实游标丢弃旧快照并更新原消息缓存；连接交付序号仍连续检查，服务端订阅溢出和断线通过明确的 resync 信号恢复。不能为凑连续序号发送虚构的业务事件。临时消息增量有独立的代次与序号，仍按其自身规则检查连续性。

同资源多消费者共享订阅并引用计数释放。工作区物理监听按核验后的真实路径与文件／目录语义共享，各消费者分别校验授权和读取快照；最后一个消费者退出后释放监听。macOS 使用兼容无 CGo 构建的 FSEvents 递归事件流，其他平台保留 fsnotify 目录监听，避免在 macOS 按项目文件数持有描述符。文件变化只传递可合并的失效信号，慢消费者读取当前快照，不积压逐次文件变化。文件仍在写入导致快照版本冲突时交付恢复状态并保留订阅，后续文件事件重新读取完整快照；授权失效和不可恢复错误仍终止观察。Git 自动刷新及慢请求补读经过同一个入口，每个查询完成后至少一秒才允许下一次自动读取；没有变化时不轮询。项目 Git 与会话文件分别订阅所属根，单个项目失败不遮蔽其他项目或会话文件。高频流式内容按资源有界批量交付，不能逐 Token 刷新全局看板。隐藏 Scene 释放或暂停所属消费，不取消后台业务工作。

## 查询与事件所有权

领域变化由提交方说明范围，查询消费者只响应自己依赖的事实。插件使用引用与插件配置分开；伙伴活动与团队活动按真实归属发布，普通伙伴聊天不能触发无关团队目录重读。事件仍复用同一连接，不建立页面轮询。

同一 QueryClient 内相同查询共用一次事件刷新调度，消费者只声明查询及当前活跃性，不各自取消和重取同一请求。首次读取期间到达变化必须补读；隐藏时标记陈旧，恢复可见后对账。取消只用于淘汰已经落后于变化的读取，不能让隐藏消费者打断可见消费者的新请求。命令式缺口恢复也进入同一实际 Query 所有者，等待必要读取完成；请求期间的新变化不能被旧 Promise 消耗。同批读取范围按完整程度合并，后来的局部变化不能将完整恢复降级；查询销毁时取消并释放所属等待。断线恢复仍以权威查询为准。

`reading.changed` 失效对应 Chat 或 Run 的阅读查询。`work-board.changed` 失效看板及摘要依赖的原事实，`work-board.live` 仅交给主进程判断系统提醒。事件在提交后发布，终态通知遵循原执行占位释放边界。缺口或 Core 重启后按实际查询重新对账，完整性标记保留已确认的事实及恢复状态。

## 新能力接入

新增状态或提醒必须确定事实来源、身份、版本、归属、查询、事件、恢复与释放规则，注册既有通道。外部平台长轮询、设备授权轮询与调度器时间检查由相应协议模块负责；不新增永久页面状态轮询或独立业务连接。

看板分页、筛选与准确计数由服务器负责，索引与查询预算需按实际查询计划验证。顶部关注列表失效后最多重读前 100 项，后续分页沿新游标继续。用户浏览第 100 项以后的内容时保留当前视区，回到头部范围或重新打开看板时对账，摘要计数照常更新。有限预览不能冒充完整总量，部分失败不能覆盖已知事实。

待办只遍历当前等待的聊天、验收任务与人工请求，沿有效待办的主键部分索引每批最多读取 256 条，按候选身份批量补齐原团队、工作流和 joined 祖先，在 Go 中统一判断归属与有效性。执行对象摘要先在 SQL 按原伙伴、团队和工作流范围限定候选。准确计数检查范围内当前等待请求，分页只保留排序身份，确定当前页后再补齐详情。顶部概览的待办工作数、请求数与预览在同一次遍历中产生；看板工作行的待办数只读取本页容器相关的请求。

摘要和看板使用 SQLite 短读事务。铃铛按存在性查询，工作看板分别统计准确总量和读取当页身份，只为选中的结果补齐消息边界。消息计数读取可读索引及游标，按原工作身份去重。全局查询不扫描历史日志。一次批量写入精确失效各原阅读记录，并合并聚合摘要失效。Chat 投影由原提交和恢复入口修复。日志缺失或截短时隔离对应会话并保留用户游标，读取报告不完整。首次切换先建立旧消息和可见运行的已看基线，再允许原执行恢复生成新结果；后续重启从阶段标记继续。设计及 OpenBot 源码索引见 [会话阅读、待处理与桌面提醒设计](../superpowers/specs/2026-11-10-conversation-reading-and-attention-design.md)。
