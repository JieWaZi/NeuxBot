# 知识核心与宿主接入

知识内容由独立 `neux-knowledge` 核心维护。NeuxBot 保存连接和库模型偏好，文档整理通过 Runtime 的独立文本生成接口调用 CLI，已有 Wiki 的主动整理通过独立工具 ACP 会话执行。两类后台知识任务均不创建伙伴、Chat 或 Execution，不写聊天 JSONL。知识库列表与各库详情使用独立标签页，详情按后端、连接与库身份区分；同一库的文档、Wiki 和图谱复用该详情标签。库内左侧通过知识、摘要、原件分段导航切换内容，原件列表在左侧仅显示文件图标与名称，长名称截断并可悬停查看完整名称；右侧展示 Wiki 或所选原件正文；图谱由顶部标题右侧操作进入。详情顶部只展示知识库名称与同行操作，保留创建、文档上传与手动整理。

## 统一操作适配

`packages/frontend/src/shared/api/knowledge` 是知识库页面的 HTTP 适配边界。本地与远端实现提供同一组库、资料、目录、页面、历史、任务与配置操作；所有请求固定完整后端、连接和库身份，调用方的路径不能改写目标。Query 管理服务器事实，Adapter 只拥有协议转换和能力检查，不建立知识内容副本。目录、原件、页面正文、图谱和历史等内容读取失败统一进入右上角错误提示，内容区不展示错误文案或重试按钮。错误沿既有身份去重，读取恢复后清理对应提示；隐藏 Scene 不主动弹出读取错误。首次失败不冒充成功空内容，后台刷新失败保留已读取内容，取消请求不作为业务错误提示。权限或服务能力不允许的控制按钮置灰禁用，未支持的附属查询不发送。

Wiki 左侧目录使用独立 `page-directory` 接口，本地与自有远端每批最多读取 1000 条，仅包含页面身份、标题、类型、简介、所属目录、目录路径、排序和版本。核心 SQL 显式选择这些列，不读取正文、证据、来源与链接关系；目录统计使用单表分组计数。自有远端的文件夹表一次完整返回，不按父目录重复拉取整表；官方协议仍按真实父子关系逐层枚举。前端取得完整目录后用于树形导航与索引分组，不将轻量条目当作详情缓存；选中页面后通过详情接口读取正文。空页或重复身份不会被认定为完整目录。

WeKnora 官方接入继续使用官方 `/wiki/pages` 分页协议，每批上限保持 100。适配层只向前端输出轻量目录字段，正文点击后通过官方页面详情读取；官方列表自身仍包含完整页面，官方数据库查询与远端到本机的传输不受宿主字段裁剪影响。

入口同步固定身份与静态实现策略，完整方法表通过类型检查核对本地／远端合同；协议实现在首次异步操作时加载。整理冻结输入独立于执行模块，删除器在首次操作时加载并保留同一实例，页面 Shell 和可用控件不等待这些模块。

远端能力分别保留协议支持、主体权限及当前条件。官方合同允许的读取仍交由服务器逐次授权；未支持的操作不作为阅读页面的自动附属查询，用户明确发起的操作按具体能力反馈。权限不足、执行配置缺失和读取失败分别反馈。自有远端只使用真实远端接口，不能回退本机同 ID 的库、索引、Runtime 或凭据。未知写入失败继续原请求及宿主持久操作对账，原操作和删除清单的核对不会被库删除后的能力查询阻断。

## API 集成与指定库接入

设置中的“发布集成 → API 集成”管理应用级 Key 和唯一发布服务。认证只查询完整 Key 的摘要，密钥仅在创建的本次响应显示；管理操作仅包含修改和删除。删除立即使密钥失效并保留既有运行记录。授权由知识库／自动任务两组各自的能力集合与明确资源集合组成，空范围默认拒绝；“整理”必须同时具备读取权，但不允许任意编辑。名称与使用时间不改变授权代次。删除知识库或自动任务时，同步移除所有 API Key 对该资源的授权；资源组清空后移除该组，Key 本身与其他有效授权保留，全部资源删除后保持无授权。授权清理递增编辑与授权版本，旧表单不能重新写回失效引用；管理列表读取时对历史失效引用按权威资源存在性对账，读取失败不作为资源删除。

对外监听仅注册已声明的知识与任务 Operator，以及知识 Streamable HTTP MCP 的 `/mcp` 入口，与桌面管理认证隔离，默认回环 `127.0.0.1:8431`，配置独立保存在 `integration-api.json`。公开合同由运行时登记和同一 ginx 扫描器生成，`/integration-openapi.json` 只含公开路由和可达 Schema。功能按全新配置实现，无旧 Token／数据库结构迁移或兼容监听。

MCP 设置位于“发布集成 → API 集成”内，使用共享 Switch 控制，默认关闭。API 服务开启后，才可启用 MCP 并复制占位 API Key 的连接配置。API 总开关控制发布监听，MCP 子开关控制知识工具入口；关闭总服务保留子开关偏好，重新开启后恢复。两者复用同一监听地址和密钥权限；不建立独立端点、Token 或权限表。MCP URL 从发布地址移除末尾 `/api/v1` 后追加 `/mcp`，保留反向代理路径前缀。

MCP 的工具名将 `agentcapability/contract` 中发布知识命令的点号转换为下划线，业务 Schema 与 allycli 同源；内部聊天任务等待和重复页永久清理不随目录扩展自动授予外部 Key。读取复用既有 Provider，编辑、导入及任务操作复用知识 Service；外部身份由 `X-API-Key` 认证，每次调用重新检查该 Key 的明确本地库范围。读取需要 `retrieve`，直接编辑和导入需要 `retrieve + ingest`，整理和重试需要 `retrieve + organize`。该入口不转授已挂载远端库的凭据，也不创建内部 Chat 或 Execution。整理显式指定库及已导入来源，不能引用内部对话的附件序号。

写工具使用独立于 JSON-RPC id 的稳定 `requestId`，幂等身份隔离 API Key 与内部执行；同请求异内容冲突。同步写入沿同一提交屏障与版本检查，后台任务沿冻结授权检查。外部重试在原任务约束上追加本次 Key 的约束，以核心重试回执确认哪次配置生效；未接纳的候选不影响其他请求，重启后仍按真实回执恢复。权限核对在同一次授权读锁中完成，不能靠换 Key 或内部重试解除原约束。

知识库列表统一调用本机后端的跨来源目录接口，按保存位置筛选，按名称与用途搜索全目录后再全局分页返回本地库和远端库。搜索条件保存到 URL，改变搜索时回到第一页；不支持搜索的来源按每批 100 条库元数据遍历，只保留当前返回窗口与匹配计数，Wiki 统计仅补读返回页。远端认证、权限、协议或网络失败不会中断整个目录；明确挂载及识别阶段已验证的远端库使用本机元数据返回，并标记 `offline`，正常本地库和其他远端库继续展示。远端卡片显示“在线”或“离线”，分别使用共享 Badge 的淡绿成功色和淡红危险色；本地库不展示连接状态。本机数据库读取失败仍按真实错误返回。

添加远端只填写 URL、API Key、知识库 ID。宿主只读验证指定库和服务证据，原子保存加密连接及挂载；展示库不依赖远端全库目录权限。自研明确声明 `separate`：上传只保存原件，整理按服务端配置独立执行。已验证 WeKnora 为 `automatic`：提交前显示自动处理提示，上传即由远端处理；不能确认身份或模式时仅开放已验证读取。第三方 Wiki 无法证明原子 CAS 时不开放编辑。

每次写入固定完整目标、连接代次、已确认上传模式及稳定请求。模式变化先停止发送，重新检测后重显提示。已发送但结果未知的操作保持原身份，不自动重传；宿主持久保留发送事实与不可变原连接快照，现有上传、整理等操作沿各自流程核对原结果；知识库列表不提供全局远端操作恢复入口。接纳、原件保存与整理完成分别展示。

公开知识维护成功写入页面并确认宿主回执后复用 `knowledge.changed`，正文、目录和历史读取方沿原资源事件失效；生成失败或写入冲突不发成功事件。公开知识整理使用独立 Generator，不创建聊天或工作流。后台每次来源、页面、目录和索引实际提交前检查原 Key 的凭据代次、授权版本和核心库策略；删除密钥或授权变化成功后，后续候选不能继续提交，重启也不重新赋权。

## 文档界面

详情标题区仅展示知识库名称，图谱、设置、整理与上传资料操作与标题同行靠右；标题区下方使用分隔线，不展示库简介或独立工具栏，也不展示远端上传模式说明与重新检测横条。视图切换按钮显示目标视图：文档中显示图谱，图谱中显示文档。搜索仅位于左侧栏，知识与摘要搜索 Wiki 页面，原件搜索源文件。库操作包含图谱、设置、整理与上传资料；图谱、设置和整理仅显示图标，保留 Tooltip 与访问名称。原件 Tab 在左侧展示文件列表，滚动接近底部时自动追加下一批，仅保留文件图标和名称，不展示表格或状态列。点击文件名在右侧内容区展示标题、包含状态的基本信息、非空文档摘要与文件内容，通过左侧列表直接切换文件，标题不增加返回按钮或分隔线；不提供自定义元数据。Wiki 引用等独立查看场景继续复用共享 Dialog 预览。Markdown 和文本读取原件字节，PDF、Office 等读取已保存的解析分块，不在预览请求中运行模型；尚未产生正文时保留原件下载入口。下载复用桌面保存能力。

整理期间允许继续上传原件和选择其他资料提交整理。上传只保存为待处理，不扩大已接纳任务的文件范围；同库按持久接纳顺序排队串行执行。来源读取独立投影任务占用，文件选择与重建同时核对该占用；已排队、处理中，以及同批任务尚未结束的成功或失败资料不能重复提交，真实处理结果保持原样展示。入队沿既有知识资源事件刷新其他读取方。

原件列表由后端按文件名关键词筛选、计数并按最新上传顺序分批读取，前端累计展示已加载结果，不自行筛选或重排。每批读取 10 条，向下滚动自动追加，无页码和每页条数控件；搜索变化重新从首批读取，实时状态减少匹配总数时重新核对已加载目录。排队与整理中状态由同一读取事务中的活动任务和当前尝试投影，已完成来源的独立结论优先。自有远端使用同一查询合同；官方远端透传关键词、创建时间排序和其原生状态，不把本地专有整理状态冒充官方能力。

源文件正文标题右侧提供下载、重建知识与删除，列表不再提供行尾操作菜单。本地重建复用模型配置和独立知识任务接纳；自有远端选择服务器执行配置，由远端执行。两条路径均传递显式 rebuild、所选来源版本与本次整理要求。普通整理继续跳过已完成来源；重建在接纳事务内核对来源当前头、授权、库版本及活跃写入，清理这些来源的分块、向量和旧摘要并重置为待处理。原件字节、已有 Wiki 与人工内容保持不变；同一请求回放不再次清理，接纳失败回滚。

删除先读取来源所有版本及 Wiki 影响，用户确认后才提交原预览摘要与稳定身份。沿用核心来源清理：人工和多来源正文保留并标记核查，单来源生成页面按预览归档清空。接纳回执不等于清理完成，界面核对持久清单并恢复原清单；未知结果关闭后重开继续原身份；来源行消失后通过持久清理清单入口继续，切换视图或重启不会丢失待完成清理。自有远端的上传、下载、实际持久分块预览、重建、来源清理与恢复使用连接范围接口；原件阅读器只在服务明确支持来源清理时读取清单，不支持的重建与清理按钮禁用，原件正文读取错误统一通过右上角错误提示反馈。

## Wiki 界面

Wiki 使用独立目录组件，目录行与工作区文件树复用 shared/ui 的展示组件，不调用聊天内部的文件系统行为。进入库详情默认展示知识目录，左侧支持知识、摘要与原件切换，索引作为知识列表第一个独立文件项，不在摘要或原件下出现，Wiki 目录提供搜索；知识固定按主题树组织，摘要始终平铺，不重复展示主题目录。三个分段共用搜索和导航布局，导航行保留统一控件高度，目录内容单独滚动。右侧读取所选页面的真实 Markdown。目录完整读取所有分页，正文独立按页面身份查询，切换不会保留其他页面正文。尚无持久索引时，索引入口只汇总真实页面元数据。知识与摘要数量使用完整页面目录按类型计数，原件数量使用原件列表接口的服务端总数；库详情可见时保持原件查询启用，上传成功和知识变化事件刷新同一缓存，不依赖切换到原件分段。

索引入口名称固定为“索引”，正文一级标题固定为“Wiki Index”；模型只更新概述，文档增删继续更新概述与目录。旧导言在生成与读取展示边界规范标题，读取不改写历史正文，普通 Wiki 页面标题不受影响。索引页沿 WeKnora 分离持久 Markdown 导言与动态分类目录。目录接口按全库轻量元数据分组分页，前端将分类层级、页面链接及摘要拼成 Markdown，通过共享渲染组件展示，不使用文件行样式。导言只渲染一次，不把原始 Markdown 当作摘要重复显示；新增文档不以本批候选替换全库目录。远端公开协议未提供结构化索引接口时，使用同库完整分页读取的页面元数据和索引正文组装相同视图；分组每次展示 50 项并按需展开，不读取本机同 ID 索引或调用未公开接口。没有持久索引时仅汇总真实页面目录，目录读取失败不显示为完整空索引。

Wiki 复用统一知识库页头，不再增加单独的库标题或计数栏。当前页面的编辑、历史版本和删除位于正文标题右侧，长标题截断且为操作保留空间；索引操作与 Wiki Index 标题同行靠右。正文显示类型、版本标签及接口提供的更新时间，标题区与正文使用分隔线；Markdown 链接使用语义链接色和下划线。历史版本按需分页读取；本地页面通过既有归档写入从 Wiki 移除，保留历史版本，删除前明确确认。目录与正文隐藏滚动条并保留独立滚动。知识库详情不再使用 Dock；目录与右侧内容采用 pane 布局，保持独立滚动与窄容器重排，底部不保留 Dock 占位。

同一次整理任务对每页最多增加一个内容版本，新页保持 v1；分批合并、自动恢复及显式重试沿同一任务版本继续写入，中间过程、内容未变和自动链接维护不形成历史快照。首次更新前的快照保留，人工或其他任务更新后，原任务继续写入须报告冲突。整页保存同时回传打开时的页面更新时间，后台同版更新不能刷新旧草稿的读取屏障；缺失或过期的屏障明确冲突。每页最多保留 50 个版本（当前版本与最多 49 个历史快照），不区分人工、自动、智能体或恢复来源，写入事务裁剪旧快照，版本号继续递增。历史弹窗独立列出当前版本，默认比较上一版到所选版的增量；历史版本还可查看到当前版的累计差异和完整原文。比较覆盖标题、说明和正文，使用与技能版本共用的按需差异组件；首版以空内容为基准。所选快照缺失时不能恢复，上一版未保留时明确提示并展示所选完整内容，不伪造版本范围；普通读取失败统一通过右上角错误提示反馈。上一版不在已加载列表时按真实版本补读，切换版本不沿用前一次正文。

本地及有实际写权限的自有远端可确认恢复历史版本，沿既有恢复接口追加新版本，保留历史、当前目录与排序，编辑来源记为版本恢复。恢复固定目标历史、当前页面版本、目录版本与请求身份；版本冲突不覆盖新内容，未知结果在页面生命周期内保留独立核对入口，关闭弹窗、切换库内视图或原历史行消失后仍重用原请求。成功后失效所属库及库列表缓存，正文与历史重新读取。官方 WeKnora 远端沿当前只读适配合同提供比较，其恢复写入仍明确拒绝。

Wiki 阅读器沿固定上游规则，仅在正文首个非空行是与页面标题同名的一级标题时省略该行，保留不同标题、代码块、后续章节和存储原文；图谱阅读器已有独立标题时复用同一规则。说明作为独立导言展示，主阅读器页尾按持久 `inLinks` 和 `sourceRefs` 展示引用当前页的页面与来源文档，不从正文另造引用事实。引用区上方使用分隔线，链接使用主题绿色、无下划线并带圆点，横向排列至空间不足后换行；名称最多展示 24 个字符，超出省略，悬停与辅助技术可读取完整名称。两组引用各默认展示最多 30 个，通过更多与收起控制展开。正文和引用区使用独立组件身份，切换页面不保留旧正文。

知识库卡片、文档列表、Wiki 目录及正文首次加载复用共享 Skeleton，按实际内容结构占位；代码分包与数据读取使用一致布局。后台刷新保留已有内容，读取失败统一通过右上角错误提示反馈，隐藏 Scene 暂停骨架动效。

页面与设置骨架只同步加载基础导航文案；配置扩展词典随编辑器加载，图谱完整词典随图谱视图加载。标题右侧的图谱入口不提前引入画布与图谱词典，保持现有页面和弹窗外壳即时挂载。

本地和具备实际写权限的自有远端支持新建根目录或子目录、新建页面；已有页面只编辑标题、说明和正文，保留目录、页面地址及类型。操作携带打开编辑器时的目录版本和页面版本，失败保留草稿，未知结果保留固定草稿、对象快照、版本和请求身份；关闭重开或切换库内视图后仍有独立核对入口，原行消失不会丢失入口。成功只失效所属知识库与库列表缓存。目录行的操作菜单在悬停、键盘焦点或展开时可用，提供新建子目录、重命名和删除。目录保持最多两层、同级名称唯一、仅空目录可删除的核心规则；服务端逐次校验权限与结构版本。远端目录逐级完整读取，返回前校验自有完整目录表，缺失父级、重复身份、环与中断不能被视为成功的空目录。页面选择进入 URL，知识事件复用原资源订阅，隐藏视图不启动专属读取。Markdown 内部链接在库内定位，外链通过桌面适配打开；不执行原始 HTML，也不自动加载远端图片。

## Wiki AI 修订

当前页的 AI 修订复用共享 `ChatPane`、右侧工作台全屏时使用的 `FloatingChat` 与普通 Chat／Execution，按需加载维护视图，不另建聊天渲染器或内容状态机。首次发送固定后端、连接、库、页面及已读版本；后续发送保留同一绑定。关闭浮窗、切换文档／Wiki／图谱或切换知识库时保留原会话身份，隐藏 Scene 退出浮窗展示。页面修改成功后复用所属资源事件失效，正文与历史从核心重新读取。

本地维护入口以个人助理执行用户要求，服务端只签发原库读取和当前页修改工具，工作区只读且不装配额外 MCP。持久绑定复用宿主操作引用；不能通过普通聊天历史入口续发或原生重试解除范围，继续修订须回到原页面维护入口。首发和续发复用已有请求身份及消息接纳回执；结果未知时保留原消息与配置核对，不生成新身份重复发送。

修复流程迁自固定 WeKnora 的 `wiki_fixer`：读取当前页与用户修改要求、回读真实来源、确认问题仍存在、做必要的最小修改并回读核对。维护工具迁入整页写入、精确文本替换、重命名和归档，沿核心 SQLite 事务保存正文、版本、链接、活动与回执。AI 修改记为 Agent 来源；整页写入保留人工保护，明确替换只调整匹配的保护文本，不静默解除其他保护。重命名保留稳定页面身份并更新真实入链；归档清理入链但保留历史，代码示例不当作真实链接重写。

本地 Wiki 整理和去重范围内的归并以永久删除已核实的冗余页收尾。维护指南要求先核对完整内容、适用版本和来源，将有效知识保存到规范页并回读，再以两端已读版本、更新时间和当前目录版本提交归并归档，入链同事务改向规范页；随后读取归档页，以同一已核实规范页守卫调用永久删除。核心只允许清理已归档重复页，在写事务内再次核对规范页同库、已发布、版本与时间未变、祖先关系不会成环，将迟到引用改向规范页，再删除旧页、旧页历史和问题记录。原件、规范页、操作回执和维护报告保留，旧页永久删除后不再支持历史恢复。已有跳转空壳须回读最近的实质正文版本，核对知识未丢失后再处理；不能仅留下“内容已汇总至另一页”就认定合并完成。明确要求保留的页面或历史、有效导航页和存在独有内容或未决差异的页面继续保留，单页修订不获得永久清理能力。报告区分内容已合并、仅归档和已永久删除，记录旧页到规范页的映射及未完成原因。远端暂不提供永久删除与携带规范页守卫的归并归档；普通归档继续清理入链并保留历史。

页面只提供 AI 修订入口，用户在聊天中直接描述修改要求，不提供全库问题、当前页问题或手动标记问题的界面。手动问题管理的接口、CLI 命令与绑定一并移除；整理管线的自动质量核查继续保留。页面 AI 修订目前只支持本地；自有远端维护工具使用真实代理接口，尚无远端聊天接纳合同。官方远端未开放的维护写入明确拒绝。

## 图谱界面

图谱展示 Wiki 页面之间的真实链接，不启动额外实体抽取。进入图谱后隐藏左侧目录，画布填充整个标题下方内容区，使用 `react-force-graph-2d` 的 Canvas 2D 绘制、指针命中、平移缩放及 D3 布局时钟。WeKnora 的初始连通分组、主题名称、轮廓与标签避让作为纯几何能力保留。搜索与类型图例悬浮在画布上，类型可独立开关；节点支持拖动固定，画布默认支持空白拖动、滚轮缩放与箭头开关。背景和左下缩放控件与工作流共用。图谱及其第三方引擎随视图延迟加载。生产构建将引擎依赖置于独立模块作用域，避免 D3 原型扩展扩大启动时的 Mermaid 共享块；React 继续共用同一实例。

服务器关系事实由 Query Cache 保存，D3 仅修改独立的节点坐标、固定位置和边端点；增量展开按 slug 复用旧节点对象与视口，双向边合并为带双向箭头的一条视觉连线。D3 使用标准连线、排斥和碰撞力，分组约束仅校正整体漂移。React 只装配容器、业务操作与可见状态，布局帧不提交 React 状态。标签与轮廓每六个布局帧失效，平移复用几何缓存，悬停仅更新强调与标签，文本宽度按绘制器缓存。零尺寸等待真实容器尺寸后创建引擎；Scene 与窗口隐藏时暂停，卸载释放第三方实例及宿主监听、定时器。减少动态效果直接展示初始分组位置，不同步运行数百步模拟。

画布提供按节点组织的键盘入口：Enter／空格阅读，Shift + Enter 叠加，Ctrl／Command + Enter 聚焦邻域，上下方向键切换节点。画布获得焦点后方向键平移，加减键缩放，Home 适应画布，Escape 清除选择或退出分组聚焦。屏幕绘制与键盘入口使用相同业务身份。

单击节点在右侧按需读取真实 Wiki Markdown，正文内部链接在图中定位。双击或展开邻居聚焦一层邻域；Shift 单击、节点悬浮加号和扩张边缘叠加邻域，保留已有位置与固定节点。远端按最多六个并发请求读取邻域，合并上限为 1500 个节点，淘汰旧扩张时保护初始节点、当前中心及选择。

本地与自有远端图谱复用各自 Wiki 的完整分页查询与持久链接投影，不使用文档列表或 Wiki 当前分页合成全库关系。概览与单次邻域最多显示 500 个节点，累积展开最多保留 1500 个节点，从完整关系中按连接度选择；搜索可定位概览之外的页面。官方远端使用原有有界图谱接口与全库页面搜索，单次请求遵守 200 条的协议上限，保留实际覆盖范围与截断说明。节点关联数保留原始关系事实。服务器数据仍由 TanStack Query 管理，并复用所属库的事件失效；隐藏视图不启动额外读取，动画在隐藏或卸载时释放，减少动态效果模式展示静态初始布局。

## 数据权威与配置

本地知识库使用独立 SQLite 和受管原件目录。上传入口提供文件、文件夹两种来源，支持 Markdown、文本 PDF 和 DOCX，当前不支持网页链接。文件夹选择递归读取其中的支持格式，过滤路径中以点开头的隐藏文件和目录；相对路径仅用于队列中辨认文件，核心接收的文件名不包含目录。上传保存原始字节，不自动整理。上传弹窗外壳随知识库页面加载，内部表单按需加载；加载与表单就绪共用同一个弹窗实例。本地仅创建通用库，不提供类型选择或项目知识库入口。

核心只初始化空库的当前 schema 或校验现有结构，不保留历史开发 schema 的迁移框架、旧索引回填或兼容分支。数据库清空属于独立离线操作，不在应用启动时自动丢弃内容；受管原件根仍核对数据库路径、目录身份与既有归属。

Wiki 正文、稳定页面身份、版本、来源证据、分块、向量、模型调用诊断和整理检查点由核心数据库保存。库配置包含 WeKnora 整理偏好、索引策略和分块配置。整理弹窗完整分页读取全库来源，通过共享可搜索多选控件默认选中待整理、失败及已取消的文件，用户可调整范围；当前列表页、搜索筛选和表格勾选不限定默认范围。单次整理可填写提取要求，与知识库长期整理偏好一同生效，随知识任务冻结，不回写库配置。整理接纳时冻结配置与来源版本，运行中的配置变化不改写该任务；未知结果重试保留原文件集合、单次要求和请求身份。

分块直接迁入固定版本 WeKnora 的算法与回归测试，包含自适应策略、Markdown、父子块、语义边界与来源位置处理。配置字段保留上游含义；解析引擎规则和表格元数据指令在当前适配未支持时明确拒绝，不能保存后静默忽略。创建表单预设与算法的默认归一规则分别沿用上游，包括重叠值为零时的归一行为。

模型选择复用共享 Runtime、账号和模型控件，按知识库存为宿主默认配置；设置与整理入口读取同一记录。接纳时将选择冻结到独立任务配置，后续修改默认配置不改变已接纳任务。整理不显示聊天权限，支持选择模型声明的推理强度；界面直接选中模型实际支持的最低档，仅展示模型真实选项；所选档位随库默认配置保存并在任务接纳时冻结。未指定强度的调用仍使用模型最低档。实际调用校验原生选项与配置回执，不支持时明确失败；适配器记录实际生效的配置。

新建与编辑使用同一编辑器、字段模型和校验。新建时选择本地或已启用远端连接，目标进入同一草稿；远端创建按连接级创建授权处理，不能从已有库的写权限推断可创建。远端请求不携带本机执行默认值或 Embedding 密钥。本地配置包含基础信息、模型配置与分块设置，自有远端编辑实际核心配置及活动；尚无远端合同的宿主模型配置明确提示不支持；编辑另有只读活动记录。弹窗外壳跨代码加载、数据加载和编辑保持同一实例，只有内部内容切换，避免重建弹窗与重复播放动效。知识库 ID 使用只读信息表面；必填字段复用统一标记，启用 RAG 向量索引时必须完成本库 Embedding 配置。

界面不提供 Wiki 编写语言选择；分块识别的语言提示位于高级选项折叠区，留空表示自动检测。分块配置直接编辑策略、大小、分隔符和高级识别参数；索引策略使用底色与勾选状态表达选择。

核心配置与宿主执行默认配置分属两个数据库，保存依靠稳定请求身份、版本比较和独立持久回执恢复部分完成状态，不承诺跨库事务。 宿主只登记连接、独立任务配置、库模型与 Embedding 偏好以及实际回执引用，不维护项目或软件库关联表。创建中断后重试补齐原库，不能重复创建。

索引策略以 RAG、Wiki 两个选项表达。RAG 统一控制向量与关键词索引，至少开启一种管线；新建默认 Wiki-only。已有内容时编辑界面锁定策略，分块配置按原保存值回填。关闭 Wiki 时只执行原件读取、真实分块索引、上游普通文档摘要及最终核查，摘要与 Profile 保存到来源元数据，不生成 Wiki 页面、主题或索引简介。该路径仍须取得对应生成调用的真实成功终态并通过发布授权检查，不能以完成向量写入冒充整次整理成功。

Embedding 地址、模型和加密密钥按知识库独立保存，与记忆配置及其他知识库互不影响。模型配置直接内嵌服务表单与连接测试，空密钥保留本库已有值，读取不回显密钥。只复用通用嵌入客户端，不读取记忆设置，也不将记忆凭据复制为知识库默认值。尚无独立配置时明确要求配置，不能静默回退。

整理与检索按同库配置冻结模型和服务地址指纹，检查批次顺序、数量、维度及有限数值后保存向量。原件检索对齐 WeKnora Lite：关键词使用 FTS5、中文 bigram 与 BM25；向量只保存在 sqlite-vec 的紧凑 vec0 虚表，不再保存 JSON 向量。库身份及向量空间参与 Top-K 过滤，关键词与向量同时启用时按默认归一化 RRF 融合，两路任一失败均明确返回。查询只回读有界候选正文，父块先去重再分批读取。来源重建、来源删除及整库删除与索引清理共用原业务事务。知识核心使用自己的无 CGO SQLite 连接、配置及生命周期，与记忆模块独立。分块失败或嵌入失败均保留真实失败状态，不把候选、关键词搜索或待处理状态表示为向量就绪。普通知识搜索在首屏附带最多五条原件命中；启用向量时真实嵌入查询并校验向量空间，返回子块定位及同版本父块上下文，读取父块使用有界身份查询。远端读取不访问本机索引，嵌入失败不静默降级。

Markdown 直接读取；文本 PDF、DOCX 使用受限文本提取。OCR 与复杂图表不属于当前阅读能力。Wiki 引用使用实际分块结果，不另建一套近似分块。

## 活动记录

活动类型、结果、游标和筛选语义迁自固定版本 WeKnora。核心保存独立审计记录，内容变更与对应活动在同一 SQLite 事务中提交；宿主执行默认配置另以稳定请求补记到同一活动流。重放不会重复记活动，也不从任务列表拼接历史记录。

活动只保存对象身份和必要安全摘要，不保存原文、提示词、候选正文或凭据。人工操作使用实际本机用户身份，后台整理沿用任务冻结的发起人。前端按时间、操作、对象、发起人和结果展示，支持操作与结果筛选、刷新和游标分页。

本地库在活动历史上方读取已有 `activeJob` 快照，展示整理文档或整理 Wiki、排队、处理、取消或宿主等待状态，以及本次尝试的接纳时间；旧任务缺少该字段时明确回退为创建时间。文档范围按任务冻结的来源数量展示，已有 Wiki 维护明确标注范围，不把范围数量当作已完成进度。终态任务退出当前区，由真实持久活动承接；刷新失败保留上次状态并明确提示。状态与历史共用库级 Query Cache 和既有 `knowledge.changed` 事件，不新增轮询。

Wiki 写入在原业务事务内按回执身份批量读取最多五个页面的名称快照，含本次软删除对象，不读取正文；界面最多预览三个标题，并展示回执的实际变更页数。旧记录缺少标题时保留类型和数量，不从当前页面反推历史名称。单次写入成功不代表整理任务完成。用户展开任务结果时才读取已有详情接口，任务尝试身份必须与活动一致；任务已重试时不以新尝试的报告覆盖历史结果。

文档整理的 Lite 发布沿真实回执记录页面写入与最终成功／部分失败／失败活动；延迟取消在最后阶段结束或恢复结算的同一事务追加唯一取消终态。来源失败在已有终态来源读取中汇总到当前任务的诊断，最多三条、每条五百字符；完整诊断继续由原件持有，活动摘要不保存错误正文。

## 聊天整理

聊天通过用户自然语言请求发起整理，输入区不提供知识库专用按钮或目标选择状态。系统 `ally` skill 识别知识查询、附件入库及整理意图，按需读取知识参考。智能体先通过 `knowledge.libraries.list` 查询目标；只有用户明确指定或已回答确认、且能在当前列表唯一匹配的知识库才可触发整理。用户未说明目标、查不到或存在重名时，必须使用已有结构化问答并等待回答，确认后重新核实目标。即使当前仅有一个知识库，也不能替用户选择。

普通伙伴通过知识能力协调工作：文档整理使用 `knowledge.jobs.start`，已有 Wiki 的跨页或目录维护使用 `knowledge.wiki.maintain`，两者复用手动入口的任务接纳、队列和执行流程。目标只能来自本轮冻结的本地通用库集合，每次调用重新核对知识库策略、伙伴、项目和实际执行身份。单页精确修订继续使用既有页面工具，不能以原件入库代替 Wiki 维护；聊天执行服务不增加知识任务分支。

附件参数是触发本轮执行的用户消息中从零开始的序号，服务端先保存相应受管附件原件，再运行统一文档管线，不接受任意文件路径。上一条消息附件不能作为本轮索引。显式选择附件时不捎带库中其他待整理来源；仅在用户要求整理库内待处理资料时省略来源选择。

知识模块从本轮 Execution 读取并冻结智能体、账号、模型与推理配置，自动保留原始用户要求并附加伙伴提供的范围、发现和证据；手动入口继续使用整理弹窗选择的配置。伙伴档案、整段历史和额外工具不进入独立维护会话，Wiki 维护注入共享维护指南并签发同库工具。请求身份绑定聊天、执行和操作，持久输入摘要拒绝同键更换目标、附件或补充要求；重复请求及未知结果通过原核心回执核对，已接纳任务继续由知识库后台拥有。

聊天通过 `knowledge.jobs.wait` 复用知识事件通道监听本地原任务，先订阅再按既有读取授权核对权威状态，等待期间不持有策略锁。每次观察最多 60 秒，窗口超时不取消任务，伙伴继续等待同一任务，直到完成、部分失败、失败或取消后再收尾；用户停止或权限、运行环境中断时明确报告已知状态和未完成步骤。`knowledge.jobs.get` 用于状态核对与响应恢复。当前成功 Wiki 维护同时返回持久报告，失败、未完成和其他尝试的正文不作为成功报告公开。伙伴根据真实结果总结检查范围、修改页面、合并去向、目录与链接调整及遗留问题，不接管后台管线。组合请求先检查文档整理的真实结果，再提交依赖它的 Wiki 维护并等待终态。远端整理不能回退本机，未提供相应 CLI 能力时明确报告边界；知识库页面原有上传与手动整理入口继续使用各自真实接口。

## Wiki 主动维护

新原件导入沿用 WeKnora 的同库内容哈希与文件类型判重：当前有效来源已存在时复用原来源身份，不重复创建原件或摘要；显式指定来源的版本更新仍沿原身份进行。相似 Wiki 候选在 SQLite 下采用上游标题三元组相似度排序，随后进入原有模型身份判断；不以关键词包含匹配代替该算法。

知识库操作区的“整理 Wiki”维护当前库的已有页面，与处理原件的“整理文档”分别发起。主动维护复用知识任务接纳、库队列、冻结模型配置和失败恢复，以独立工具 ACP 会话执行，不创建伙伴、Chat 或 Execution。确认接纳后关闭配置弹窗，结果通过活动记录查看；页面保留人工编辑与历史入口。同库存在排队、执行或取消中的整理任务时，两种整理按钮禁用，并提示查看活动记录。整理文档与整理 Wiki 的原生 CLI 均使用完全访问权限；文档生成仍只消费模型文本结果。每次维护冻结完整本地库身份，知识工具不授予原件导入、整理重试或其他库操作。结果来自实际工具写入和保存的最终报告，关闭界面不取消后台任务。远端尚无全库维护合同，入口保持禁用。

CLI 页面列表只返回目录元数据，不混入正文、证据和链关系；正文按页面单独读取。列表默认十条、最多二十条，使用返回的 `nextOffset` 和 `hasMore` 继续读取；分组索引默认每组五条、最多十条，预览不能视作全库已检查。活动记录将 Wiki 维护与文档整理区分，接纳阶段不展示完成数量，终态按本次尝试的实际写入回执去重统计变更页数。历史记录缺少可信回执时不补造数量。

全库维护采用 WeKnora `wiki_fixer` 的核查、回读原件、最小修复和结果验证流程。专属 `knowledge.wiki.auto-fix` 适配上游确定性修复，返回持久回执和剩余核查问题；语义重复、主题边界和目录调整由同一维护执行读取真实页面和来源后处理，不以重新生成整库代替维护。页面移动复用已有页面写入与目录版本保护，人工内容及人工目录保护仍生效。无法处理的问题必须留在结果中，不以核查运行成功冒充问题全部解决。

“定期整理 Wiki”复用自动任务计划表单，预填当前库、维护要求和每周一 09:00 的上海时区计划；用户保存后才创建并启用任务。计划、错过机会、运行、取消和恢复均由自动任务系统拥有，不新增知识专属计时器。每次运行继续通过已选伙伴执行，冻结 `maintain` 授权并在工具调用及回执恢复时再次核对，执行范围始终是原库。伙伴使用系统技能和实际 CLI 命令维护 Wiki。

## Lite 管线与模型接口

整理引擎以固定 WeKnora Lite 源码为依据：每批最多五份待办，同库按接纳顺序串行处理任务及其批次；批内 Map 和 Reduce 分别最多十路，单文档引用批次最多四路。流程包括真实阅读与分块、知识抽取及其上游回退、文档内去重、摘要与引用、统一目录规划、按页面合成和局部发布，最后处理索引导言与链接。业务解析、来源更新和失败重试归核心所有，CLI 只返回模型正文。

模型边界为同步 `Generator.Generate`，显式传入角色消息、生成参数与阶段身份，返回正文、原生停止原因、用量及实际能力诊断。普通调用拥有独立上下文；长度续写仅使用本次调用的消息。阶段输入、结果及失败保存为知识任务诊断，既不创建聊天会话记录，也不经过候选文件交接和智能体命令调度。

本机 API 只返回知识任务接纳回执和冻结模型配置。界面核对原请求、知识库和任务身份后关闭弹窗；缺失或不匹配的回执按结果未知处理，沿原请求核对，不换身份重复接纳。整理选择界面使用来源权威状态约束可选项；原件目录只显示图标和文件名。文档详情展示含状态的基本信息、非空摘要与原文；没有整理过程或聊天查看入口。

知识库永久删除允许目标库仍有正在进行或排队中的整理任务。删除入口先校验用户确认的库版本，逐一保存任务取消屏障、取消宿主模型调用并等待管线退出，再由核心删除全部 Wiki、历史记录、来源及索引，并按持久清单清理原始资料；等待管线退出时不持有发布锁。未知删除结果沿原请求回执恢复，不能因此把已接纳任务或部分成果标记为完成。界面不另设独立停止整理操作。

上游 Map、摘要、页面持久写入等失败按各自语义局部处理；引用批次失败保留其他批次，Reduce 生成失败保留旧页或不创建新页。成功页面与来源贡献回执同事务提交；同一任务尝试保存文档提取计划，恢复只处理未应用贡献，不重新生成成功页面。确定性的格式、长度及表格保护拒写保留具体页面诊断，不反复重跑整份资料；短暂故障沿原退避预算重试。失败来源不能回滚无关成果。知识存储仍核对当前授权、取消屏障、来源版本和目标页版本，来源撤回与重解析沿原贡献关系处理。索引和链接收尾失败不回滚已发布页面。

## CLI 调用与生命周期

主动 Wiki 整理的独立 ACP 会话使用临时受管目录、同一账号准备机制及一次任务的知识能力授权。会话只装配系统 `ally` 技能和目标库命令，不继承伙伴档案、项目目录、其他连接器或聊天历史。原生会话使用完全访问权限，允许在临时工作区准备输入文件和运行 CLI，不叠加只读或命令白名单限制。实际写入仍由知识能力、当前任务尝试和库策略的同事务校验决定。模型自述和工具发现不能证明执行成功，至少一次真实知识操作成功后才允许保存成功报告。最终助手正文随当前任务尝试持久保存为报告，活动记录和聊天读取同一正文；维护指南要求正文包含范围、修改清单、合并去向和遗留问题，临时文件链接不能替代报告。结束、失败或取消时释放授权、原生会话、账号与临时目录。

知识 CLI 复用唯一 `agentcapability/contract`、既有资源读取提供者和真实核心操作。能力覆盖库详情、来源列表和持久正文分块、页面与目录、索引、历史版本、任务、核查、活动及导出；修改覆盖 Agent 页面修订、精确替换、重命名、归档、已归并重复页的永久清理、历史恢复、目录、原件导入和任务重试。完整命令清单与使用方式见 [allycli README](../../server/cmd/allycli/README.md)，参数以当前执行的 `capabilities` 和 `describe` 为准。

来源正文读取使用已保存分块，按来源版本、块身份和位置分页，有界截断明确返回，不触发重解析或模型。写入冻结可见通用库、连接版本、库策略与活跃执行，每次调用重新授权；修改必须携带相应页面或目录版本。未知远端写入只查询原请求回执，核对操作与目标身份后才确认完成；明确拒绝持久保存并按原错误重放，不被转为未知。任务接纳与完成分开，CLI 通过任务读取观察真实终态。没有实际远端协议的操作明确不支持，不读取本机同 ID 内容。

知识生成通过 `runtimehost.GenerateText` 启动独立 CLI 会话，传入本次完整消息，只向知识核心返回最终回答。Codex 接入独立 `packages/agent-runtime`；尚未迁移的 CLI 继续使用原执行实现，路由在执行前确定，执行失败后不切换实现或重新提交。独立依赖的集成状态见[阶段 B 验收记录](../discussions/agent-runtime-codex-validation-plan-cn.md)。

宿主不主动注入 AGENTS.md、Skill 或 MCP，不增加工具禁用、原生配置净化或全局配置合并。CLI 如何加载原生配置和调用工具由 CLI 自身处理；工具活动不作为生成失败条件，也不进入知识正文。每次使用独立临时工作目录，不创建产品 Chat、Execution 或聊天日志；这不表示 CLI 不保存自己的会话记录。

Codex 的任务 system 输入通过原生 `model_instructions_file` 传入，单条 user 原文直接发送；多条 user/assistant 输入保留角色与顺序，以明确标记的文本表示，不能宣称安装了原生 assistant 历史。选择的程序、账号、模型与推理配置保持一致；不再用 `isolated_text_generation` 筛选知识模型。

账号继续使用已有配置投射和共享执行租约，OAuth 刷新复用同一凭据权威。账号准备、刷新与回收受短期协调保护，模型执行不持有整轮独占锁。原生进程停止后才回收认证投射与临时目录；清理失败保留原所有者并仅重试关闭。已取得的最终结果不因清理失败而重新生成；已提交调用后的失败向知识核心传递明确的禁止自动重试标记，避免重复工具副作用。

上游默认 `Thinking=false`；宿主显式推理选择优先于该默认值，未选择时按模型最低档执行。实际模型声明 `none/off/disabled` 且配置回执确认时才记录为关闭；只能使用较低推理或不能配置时记录真实值和限制。当前 ACP 无法设置的温度与输出 token 上限也明确记录，不能把请求参数当作已经生效的参数。

知识 Service 持有作业 Context 与后台生命周期。服务关闭取消直接模型调用；资料删除先保存不可发布屏障，迟到响应不能继续发布。重启先对账尚未确认的跨库回执，再每批读取 100 个核心库，逐库只读取核心正在执行或下一位等待的队首，不遍历已确认的全部任务历史。属于本宿主且遗留为执行中的文档或 Wiki 整理任务结算为失败，已发布成果保留，未完成来源同步标记失败，用户可重新整理或重试；已有部分成功来源时保留部分失败状态。此结算不依赖原模型配置或远端发布闸门。尚未执行的排队任务通过原接纳请求读取冻结配置并继续执行。驱动退出后只接续核心返回的下一任务，同一未结算任务不无限重启；远端队首等待发布闸门装配，已保存的取消屏障仍可先行收敛。每个任务保留原文件范围、模型选择和整理要求，宿主不保存另一套任务生命周期。等待任务开始执行时取得当前目录版本，已开始任务仍保留原有版本冲突保护。待恢复执行的排队任务必须具有同一次接纳冻结的模型配置，缺失时明确报告错误，不忽略损坏引用。整理没有额外的整批总时间预算。

原件目录与数据库绑定身份，永久删除及磁盘清理由核心持久状态约束。删除库清理知识资源与宿主引用，不调用聊天删除流程；普通用户聊天与其他知识库不受影响。

## 独立核心交付

核心在独立 [neux-knowledge 仓库](https://github.com/JieWaZi/neux-knowledge) 开发，模块路径为 `github.com/JieWaZi/neux-knowledge`。NeuxBot 通过 `server/go.mod` 和 `server/go.sum` 固定已发布版本，由 Go 下载和校验模块，不在宿主仓库保存核心源码副本或维护同步脚本。

本地联合开发可在宿主根目录执行 `go work init ./server`，再执行 `go work edit -replace=github.com/JieWaZi/neux-knowledge=/path/to/neux-knowledge`，通过未提交的 `go.work` 使用本地核心。发布与干净检出使用模块版本；提交前使用 `GOWORK=off` 验证，避免本地 workspace 掩盖未发布版本或依赖缺失。

WeKnora 是实际代码基础。核心 README 明确说明精简、微调与 Wiki 复用范围，原始版权与许可集中维护在核心 `THIRD_PARTY_NOTICES.md`。宿主仅在 [第三方说明](../../THIRD_PARTY_NOTICES.md) 声明直接依赖，构建时从所引用的模块版本复制完整许可，随桌面安装包交付。宿主保留 SQLite 存储、授权和 CLI 执行适配，不替换上游算法与提示词语义。
