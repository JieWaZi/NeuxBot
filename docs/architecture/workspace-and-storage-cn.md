# 工作区与存储

## 权威数据

业务 SQLite 保存伙伴、项目、账号、资源、团队和工作流等配置及状态；Chat JSONL 与规范原生 JSONL 共同保存聊天事实；memory.db 保存长期记忆与向量、关键词索引。生成视图、文件索引与查询投影不作为第二份权威内容。

受管根目录中的 `conversation-index.db` 是 Chat 与规范原生日志共用的派生 SQLite 索引，只保存日志覆盖、字节位置、消息／执行／输入身份、原生引用与分页关系，不保存完整消息正文。读取正文回到 JSONL，索引缺失或损坏时按日志重建；它不是聊天备份。业务配置库与该索引分别管理。

业务 SQLite 中的 `chat_execution_locations` 和覆盖游标只建立原 Chat/执行/提交身份到日志序号的查询关系，不保存执行状态、正文、配置或结果。精确状态查询回到这些位置读取原事实，正常缺失身份不遍历完整日志。定位覆盖落后只追平原日志尾部；缺失、截短或损坏按原日志恢复，删除 Chat 时一起清理定位投影。

`internal/chatstorage` 按所有者派生聊天私有目录、伙伴工作目录与团队目录。普通聊天共享伙伴固定 cwd，日志、附件原件和成果仍按 Chat 隔离。Chat 保存首次批准的规范授权根；每轮只采用仍可用且解析身份不变的子集，供原生目录、项目入口、指令及能力共同使用。附加项目离线不阻止无关追问，明确引用离线文件时准确报错；受管 cwd 必须存在且归属正确，符号链接改指向不产生新授权。

## 存储目录

产品名为 NeuxBot；应用标识与默认程序数据目录为 `com.neuxbot.desktop`，受管业务文件根为 `.neuxbot`。两者分别拥有程序状态与业务文件。

程序数据目录沿用桌面平台的应用数据位置，由 `NEUXBOT_DATA_DIR` 指定；数据库 `bot.db`、`memory.db`，技能目录 `skills/`、`system-skills/`，插件不可变原包 `plugins/content/` 与无秘密目标缓存 `plugins/targets/`，独立账号目录 `ai-accounts/`、`account-workspaces/`，受管程序目录 `runtime-installations/`，执行授权描述 `agent-contexts/`，以及 Electron 数据、程序日志和 `integration-api.json` 均保留于此。

受管业务文件默认位于用户主目录的 `~/.neuxbot/`，可以通过 `NEUXBOT_MANAGED_FILES_DIR` 独立指定，不改变数据库和程序数据位置。一级受管目录统一使用 PascalCase，当前共 12 类，按实际使用创建；下面的文件和内部子目录不参与一级目录计数：

| 路径 | 职责 |
| --- | --- |
| `Agents/<waker-id>/` | 伙伴固定 cwd 与空间目录，普通聊天共享并自由组织成果 |
| `Conversations/<chat-id>/{log,attachments,file-results}/` | 普通与团队聊天各自的日志、附件原件及不可变文件成果 |
| `NativeConversation/<00..3f>.jsonl` | 规范原生输出、工具过程、终态与用量，按原生会话散列到最多 64 个共享分片 |
| `Plugins/{catalog,details,archives}/` | 插件目录、公开资料及完整包的持久分发缓存 |
| `Knowledge/raw/` | 知识库上传原件；知识数据库位于程序数据目录 |
| `Workspaces/<thread-id>/{leader,members,shared}/` | 团队负责人、成员 cwd 与真实共享文件目录 |
| `WorkflowWorkspaces/<workflow-id>/` | 工作流脚本、状态、缓存和运行文件的固定根目录 |
| `WorkflowFiles/` | 上传原件与 `metadata.json` 归属信息 |
| `IM/{inbox,deliveries}/` | IM 接收附件与交付快照 |
| `Forks/` | 聊天分叉操作记录与暂存文件 |
| `Deletions/` | 删除操作记录与暂存文件 |
| `Provisioning/` | 团队创建过程的暂存文件 |

伙伴或执行 cwd 下的 `.neuxbot/plugin-views/<集合摘要>/<CLI>/<插件ID>/` 是当前资源租约持有的无秘密插件视图；`projects/<chat-id>/` 只在 CLI 不支持原生附加目录时提供受管项目链接入口。这两类目录属于 cwd 内部布局。

技能投影按内容摘要存放在 cwd 的 `.neuxbot/skills/`。原生发现目录保持原有名称，每个受管技能链接到已核验的对应版本。Windows 未授予软链接权限时，使用已核验的目录副本。系统技能投影只含文档和参考资料，Core 统一发布 `botcli`。存储统计根据工作区的物化记录与内置文档摘要识别程序文件，分别计量快照及实际目录副本，跳过符号链接。

公开日志 `Conversations/<chat-id>/log/<chat-id>.jsonl` 保存用户消息、业务生命周期、原生绑定、输入接纳及原生消息／终态引用；智能体输出正文和工具过程在 `NativeConversation` 中保存，公开日志不重复复制正文。相同正文的终态继续引用已保存的原生正文。独立文本生成、交接总结等没有公开 Chat 的调用也使用该规范原生存储。分片属于受管根，不是一聊一文件。

CLI 还可能在自己的原生目录保存厂商历史。因此一次聊天可能涉及公开日志、规范原生日志、厂商历史三层持久记录，但应用内前两层按职责拆分，不是三份完整聊天 JSONL。厂商历史由对应 CLI 管理；删除聊天按原生会话引用清理本应用分片中的独占记录，保留仍被其他 Chat 引用的内容。

工作区使用 `workspace-owner.json` 标记实际所有者。Agent 在固定空间内按任务组织成果，宿主无需为普通执行预建 `outputs`、`tmp` 或每轮子目录。临时处理使用原生客户端支持的系统临时目录，成果采集覆盖业务文件。原生输入携带当前 Chat 明确引用的附件原件路径，聊天私有目录不加入原生授权根。全权限执行中的实际文件访问由所选 CLI 决定。账号配置与授权描述保留在程序数据目录，文件服务排除这些私有内容。智能体约定的 `.agents/`、`.claude/` 等技能发现目录保持原名，不作为空间业务成果。

文件工作台以“空间目录”展示伙伴固定 cwd 中的业务文件，隐藏内部配置与归属文件；用户另选真实目录时显示“空间目录／工作目录”两个 Tab，工作目录保留真实目录结构。未选择工作目录时直接展示空间内容，不显示目录 Tab。当前 Chat 的上传与交付文件仍使用原会话文件入口。

插件视图按实际执行 cwd 创建：普通聊天属于伙伴，团队成员和工作流 worker 使用各自 cwd。CLI 通过明确目录参数或隔离配置加载多个独立插件根，不假定 `.agents/plugins/` 能被所有 CLI 自动发现。视图不保存凭据或安装状态；最后一个消费者退出后释放，启停与版本仍以数据库为准。Codex 原生缓存和 marketplace 索引位于受管账号的租约目录，系统账号沿 Skill/MCP 路径交付。

项目入口只指向已冻结的真实目录，按 Chat 隔离，不替换或扫描删除其他聊天的入口；文件授权和成果身份仍以真实路径为准。Chat 删除通过既有删除记录清理自己拥有的入口，团队或伙伴聚合删除时由所属父目录一次清理。链接入口不等于额外的原生沙箱能力。

目录按当前布局直接读写，不执行旧目录迁移或旧名称回退；旧安装的目录和数据库不会被自动移动或删除。当前代码不创建旧的 `chat/` 或 `conversation-index-v3.sqlite`。用户选择的真实项目目录与智能体自行管理的原生目录保留原位置。

`Conversations/<chat-id>/file-results/` 保存该 Chat 独有的文件成果记录、私有 Git 对象与有界差异计划，不写用户仓库的 index、refs 或对象目录。分叉复制所需附件与不可变成果，父 Chat 删除后仍可读取；删除 Chat 只清理其私有内容，不删除共享伙伴 cwd。默认采集空间业务文件和本轮重新核验的授权工作目录中的净变更。采集排除内部技能、原生配置、归属文件和带有效归属标记的受管项目入口，空间里自行创建的 `projects/` 文件仍可采集。授权根外本轮显式引用的旧成果保留原路径，精确到文件参与采集与交付，父目录和同级文件不因此获得授权；只有用户要求另存时才复制。共享空间或项目上的差异不证明某个执行独占修改。

本轮明确引用旧成果时，修订保留原文件路径，只有明确要求另存才复制新成果。经来源校验的引用文件进入同一执行的精确采集和能力交付范围，不授权其父目录或同级文件；普通编辑和原子替换按实际净变化比较，未变化不生成编辑成果。

目录采集使用仓库及祖先 `.gitignore`、有界 `.git/info/exclude` 和调用方显式排除；已跟踪文件遵循 Git 的跟踪语义。非 Git 范围应用目录内同类规则。精确文件采集不枚举父目录或读取旁文件，仍应用内部路径和调用方显式排除。为隔离宿主配置，不读取全局/系统 Git 配置，也不跟随本地配置 include 或 `core.excludesFile`；额外应用或用户忽略须显式传入，不声称已经导入宿主全局忽略列表。

## 工作流目录

工作流内部文件只使用 `WorkflowWorkspaces/<workflow-id>/`。`scripts/` 保存草稿与从不可变版本物化的脚本，`state/` 保存跨运行配置和状态，`cache/` 保存缓存，`tmp/` 保存验证和进程临时文件，`runs/<run-id>/` 隔离每次运行的默认业务文件。Core 在专用 `.workflow-input-staging/` 中暂存接纳前的输入，接纳时将冻结输入移交给 `workflow-inputs/<run-id>/`。Core 启动后按原接纳尝试的运行 ID 核对持久运行，回收暂存及尚未接纳的已发布副本。目录由宿主创建并限制私有权限，内部软链接不能把这些目录改绑到根外。源码和版本 Bundle 仍是权威，磁盘脚本副本不能覆盖版本内容。

`workflow.authoring.prepare` 的 `workflow.workspace` 与 `workflow.source.get` 的 `workspace` 返回同一真实绝对目录；`flowContext.workspace` 再提供本次 `runDirectory`。这些路径来自配置的受管根，智能体不得猜测主目录或临时目录，也不得把脚本、缓存或状态路径作为业务参数让用户填写。创作与 worker 通过本次执行上下文获得目录约束；worker cwd 位于工作流临时根的 `workers/<effect-id>/`，由工作流拥有，固定工作流根作为冻结的额外授权目录。删除技术 Chat 不删除该领域工作区。

脚本与 Python 函数的进程工作目录为 `runs/<run-id>/`；宿主注入 `NEUXBOT_WORKFLOW_ROOT`、`NEUXBOT_WORKFLOW_SCRIPTS_DIR`、`NEUXBOT_WORKFLOW_STATE_DIR`、`NEUXBOT_WORKFLOW_CACHE_DIR`、`NEUXBOT_WORKFLOW_TEMP_DIR`、`NEUXBOT_WORKFLOW_RUN_DIR`，并固定 `TMPDIR`、`TMP`、`TEMP` 与 `XDG_CACHE_HOME`。动作不得通过环境配置覆盖保留目录变量。该机制约束宿主布局并给脚本明确存储契约；受信本地 Python 的任意绝对路径访问仍由实际 Runtime/平台权限管理。

业务成果默认放本次 `runDirectory`。运行文件的相对引用只按所属运行的 `runDirectory` 解析，再校验目录授权；缺失时不查找业务目录或工作流根下的同名文件。子流程参数按父运行解析，子流程成果按子运行解析；CLI 文件输入仍按 CLI 的当前目录冻结。用户明确选择的知识同步目录、报告目录等仍属于业务输出范围；这一选择不会移动脚本、缓存和辅助状态。文件结果只允许该工作流内部根或已批准的业务范围，其他目录不能仅凭路径字符串获得权限。此布局直接用于新执行，不增加历史路径回退或迁移。

## 团队目录

团队对话拥有 `Workspaces/<thread-id>/`。`shared/` 保存真实共享文件；负责人使用 `leader/`，其他成员使用 `members/<waker-id>/`，各自在既有 cwd 内组织文件，不自动创建每轮成果或临时目录；各 Chat 的日志仍位于独立 Conversations 目录。外部项目保持真实路径；支持附加目录的 CLI 直接使用原生入口，不支持的 CLI 使用当前 Chat 独立的 projects 链接入口。

共享项目仍可能被多成员并发修改，调用方需协调冲突。成员 cwd 隔离不表示真实项目文件隔离。

## 文件授权

文件服务规范化真实路径，分别校验 cwd、冻结的真实项目根与当前 Chat 附件根。缓存包含 Chat 身份，不能因多个聊天共享 cwd 而混用私有附件权限。越界软链接不能扩大权限。预览、下载、编辑和执行分别校验，不把可预览等同于可执行。

显式文件根按真实目录解析，空间中自行创建的 `attachments/` 是普通文件夹。当前 Chat 的逻辑 `attachments/` 引用使用空基准解析到私有附件根，后续文件操作沿用真实身份。会话附件删除只作用于原件。为兼容历史 Markdown，相对附件链接只在工作空间候选路径均缺失时回退到当前 Chat 的附件根。

上传附件在接纳时复制到受管目录，生成文件使用原 Chat 或 Run 身份定位。文件标签按真实规范路径与明确所有者复用，不能在成员切换时重新解释旧文件权限。

## 存储设置

「设置 → 存储」显示总占用、磁盘剩余容量、伙伴占用和占用最多的会话。总览把底层分类汇总为工作文件、会话、知识与记忆、应用与资源。会话占用包含受管会话目录与共享原生记录。应用与资源包含程序、应用数据、缓存、日志和其余内部数据。总览按常规文件的逻辑字节计算，去重相同或重叠根与硬链接，跳过内部符号链接。伙伴和会话的占用及文件明细按各自路径计算逻辑占用，同一硬链接可在多个归属项中分别出现。读取受限时展示已知小计。手动重算绕过 60 秒快照，清理完成使原快照失效。

总览列出占用最多的十个会话。伙伴详情可在「文件」和「会话」之间切换。文件页签展示归属可核验的伙伴工作文件和普通会话的上传副本，支持按名称搜索、按修改时间或大小排序。会话页签按占用大小降序分页。排行和文件明细复用同一代的归属与排序结果，续页时若统计已更新，页面从新一代补取。两处会话列表均可打开原会话，也可逐项确认删除。单条会话的容量为其私有目录中常规文件的逻辑字节，包括 JSONL、上传附件、成果快照和私有元数据。附件数只计通过归属核验的上传副本。逐文件删除绑定已测量的文件实例，在原有操作门内复核归属、执行占用和文件版本。伙伴空间仍有普通会话或后台任务使用时拒绝删除。真实项目目录、原生记录、内部配置和成果快照由各自的领域入口管理。

清理区将当前可回收的项目归为缓存、诊断日志和未使用的程序，并显示预计可释放的空间。清理由各文件所有者独立执行和反馈。Core 以对应的清理请求回执确认运行状态和分项结果，另一项维护运行时返回忙碌。资源清理回执只在当前 Core 进程中用于对账。插件分发管理资料及安装包缓存，程序维护围栏保护当前和配置引用的 CLI，Electron 分别检查自身 HTTP 与代码缓存以及日志，串行截短活动日志并清理已轮转日志。Web 与 Native 的字节上传共用 Core 暂存租约。Core 持有程序数据根与受管文件根的进程锁，同一真实目录只锁一次。

闲置会话清理默认关闭，默认保留 15 天。Core 在 `storage-policy.json` 持久化策略和下次检查时间。首次启用后 24 小时检查，重启后按已保存时间补做到期检查。过期比较使用最近有效会话活动，阅读和标题编辑不延长期限。用户在设置中开启自动清理或缩短期限时，确认删除影响后保存。会话菜单中的「保留此会话」随 Chat 权威日志持久化。

Core 的定期检查与批量清理接口共用同一条件删除。进入删除前复查活动执行、未决请求、保留选择、领域引用和策略版本。未完成分叉复用分叉恢复建立的索引。旧会话活动时间由现有后台修复按批回填，缺少活动时间时排除出自动候选。自动范围限普通伙伴会话。符合条件的会话清理私有日志、附件副本和成果快照，伙伴空间里的业务文件及真实项目继续由用户管理。

手动批量清理过期会话返回运行 ID。调用方可用该 ID 核对存储维护状态中的进行中任务和完成回执。完成回执包含删除、跳过和失败数量，待回收数量属于已删除会话。Core 只在进程内保留最近一份手动回执，自动检查不会覆盖该回执。

## 删除与恢复

删除 Chat 先关闭会话拥有的原生连接，再暂存私有 Conversations 目录和专属项目入口。数据库提交后，按暂存日志里的会话绑定清理 NeuxBot 共享分片中的独占记录，保留分片游标和其他 Chat 仍引用的会话记录。日志或分片损坏导致归属无法核验时，保留受影响的原生记录并完成已提交的 Chat 删除。用量投影在下次查询时按剩余终态重建。实际 I/O 错误按已提交的删除记录重试。伙伴共享 cwd、真实项目里的业务文件和厂商 CLI 自己管理的历史文件由各自的生命周期管理。

删除团队对话另清理所属 Workspaces 聚合，删除伙伴清理伙伴 cwd 及其聊天。共享 Chat 删除入口先结束关联领域任务，规则见[工作流](workflows-cn.md#授权与失败)，再释放实际执行并校验目录归属。伙伴删除与新接纳互斥，普通聊天之间仍可并行接纳。文件暂存和进程关闭位于可重试数据库事务之外，数据库失败按原删除记录回滚。删除项目配置始终保留真实目录。

权威写入与数据库投影的跨存储窗口通过明确提交顺序、补偿和恢复测试约束。应用启动恢复依赖持久事实，不把进程内状态当成耐久接纳。日志和文件的恢复不扩大原授权范围。
