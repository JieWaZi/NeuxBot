# 伙伴资源与记忆

## 伙伴与项目

创建伙伴时保存名称、头像、概要和可选默认模型。Core 通过普通 Chat 和 Execution 发起建档对话，依据该伙伴的默认模型或全局默认配置启动首轮。普通新聊天采用伙伴默认模型，已有聊天恢复自己的执行选择。

建档对话由伙伴生成核心职能、工作风格和工作方式的选项，Core 使用交互问答卡呈现。每题允许多选，也可同时填写「其他」。用户回答后，伙伴结合创建概要和回答生成角色名称、简介及三个展示字段，通过本轮授权的 allycli 和英文档案一并提交，Core 在同一事务中保存。伙伴概览预览 `AGENTS.md` 开头，编辑弹窗读取完整正文，Execution 使用同一正文作为伙伴长期指令。

伙伴档案的生成和编辑统一按 `cl100k_base` 校验 1,300 token 正文上限。普通伙伴聊天通过现有执行授权读取和修订该伙伴的档案。档案弹窗的 AI 优化入口为首条消息附加修改意图，沿用普通聊天的智能体配置和能力。智能体按需读取档案和版本，依据用户要求提交正文、核心职能、工作风格和工作方式的变化。Core 在同一事务中检查档案版本、保存变更与回执。手工编辑正文或概览时使用打开编辑器时的对应版本，保存冲突会保留草稿。省略的字段沿用当前值。

系统启动时幂等补建私人助理 lumi 和维基研究员 nova。旧伙伴档案按身份、风格和方法的顺序合并，已保存的 `AGENTS.md` 优先。内置伙伴的档案覆盖和已有概览资料随伙伴保存。

复制伙伴在同一事务写入新伙伴资料和解析后的档案，复用请求标识处理重放。聊天、项目、记忆、工作目录和资源安装归属原伙伴。侧栏分组是本地导航偏好。

项目由伙伴拥有，至少包含一个本地目录及一个默认目录。项目删除清理配置，保留真实目录和已冻结聊天；目录可用性在新工作接纳时校验。

## 资源库

插件、技能和连接器聚合在同一入口。全局资源与伙伴安装分别保存；系统插件只从自有插件库安装，包内组件随插件版本派生，外部 CLI 原生插件不进入本资源库。固定目录、共享认证及执行快照见 [插件资源](plugin-resources-cn.md)。

## 技能

技能包具有全局或伙伴范围、资源文件及版本。导入在安装前完整校验路径、内容和批次；全局资源通过明确安装关系对伙伴生效。版本恢复形成新版本，更新不覆盖用户定制。

技能列表在同一读取事务中返回完整安装人数与最多四位实际安装伙伴的名称、头像预览，停用关系仍计入安装。预览按技能批量截取，再批量读取伙伴资料，不逐卡请求，也不以预览数量替代总人数。

Runtime 在受管工作区交付当前技能与原生指令，不向项目真实源码写入应用配置。系统技能单独随应用构建，不依赖普通技能启停关系。

## MCP 连接器

连接器具有全局或伙伴归属，共享配置与伙伴安装、启用关系分别存储。STDIO、Streamable HTTP 和 SSE 按 Runtime 真实能力交付；连接测试由 Core MCP 客户端执行，不需要模型调用。

敏感环境值和请求头由 Controller 加密保存，查询只返回是否配置。当前密钥与密文同库，该机制不能替代设备访问安全边界。编辑空值保留已有凭据，显式清除由独立操作表达。

首次执行或配置变化按现有信任契约确认实际命令或远程目标。测试结果与发现工具在配置变化后失效，测试成功不是永久授权或可用性保证。

## 记忆

长期知识归伙伴或其项目范围。应用通过 allycli memory entries 的明确操作读取、创建、更新或遗忘；不自动把完整聊天抽取成长期知识。

memory.db 使用独立 SQLite、FTS5 和 sqlite-vec 保存内容、变更记录及索引。相同内容按范围精确去重；配置 Embedding 后执行语义搜索，未配置时使用关键词检索并报告实际模式。

模型和维度指纹校验保护向量一致性，索引需要重建时不将不匹配向量当作有效结果。记忆内容按需检索，不整库拼入每轮指令。
