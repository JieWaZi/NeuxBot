# 智能体与账号

知识模型生成使用独立临时会话，复用 ACP 适配与账号事实，直接返回正文、停止原因、用量和实际配置诊断，不进入 Execution 或聊天 JSONL。具体约束见[知识库](knowledge-cn.md#cli-调用与生命周期)。

## Runtime 边界

执行能力归在 `server/internal/agent`，其中 `core` 负责技术调用与会话，`host` 负责产品请求、资源、日志和交互适配，`environment` 负责安装、Profile、探测、启动与认证资源。三者属于 `server` 主 Go 模块，执行内核通过包依赖边界保持独立，不单独维护 Go module。

Runtime 是技术会话、原生句柄、配置兼容性、活动调用及资源释放栈的唯一所有者。Host 只关联业务工作区与 Runtime，不另存会话摘要、活动标志或资源副本。聊天和独立任务都先通过 `Runtime.Prepare` 占用会话并判断复用。热路径沿用已有资源；冷路径由调用方顺序取得领域资源，再通过 `Bind` 交给 Core。`PreparedRun.Run` 才打开原生连接并提交本轮输入，未提交的准备通过 `Close` 回收。Core 不再调用资源 Factory。账号和插件的闲置消费者回收也由 Runtime 在同一会话锁下检查并执行。

`SessionPlan` 描述稳定配置和能力，`TurnInput` 描述新增消息、选择及交互，`SessionResources` 描述实际账号和插件等资源及释放能力。三者不再通过完整请求回填。静态目标和连接器声明采用窄类型，实际环境、刷新回调、关闭策略和秘密连接配置只归 SessionResources。本轮软件授权通过 LaunchEnvironment 在冷准备交付，热轮只更新稳定连接文件。Core Runtime 直接实现生命周期，取消沿 Context 传播，不再保留身份预留、纯转发或自制 Checkpoint。Host 共用启动装配，普通聊天声明可留存，独立任务声明执行后关闭；两者使用同一个 Core 准备及执行入口。业务层读取具名资源事实完成日志和范围提交，不保存第二份热资源生命周期。完整调用与所有权见 [Agent 子系统](../../server/internal/agent/README.md)。

11 个 CLI 的工厂、完成策略、语义模式候选、配置 ID 和技术能力只在 `core/driver/acp/native` 的 Descriptor 注册表维护，宿主通过 `native.Lookup` 选择产品已授权的语义能力。聊天、独立任务与 Probe/Fork 均由 `environment/launch.PreparedAgent` 冻结启动与认证资源，再调用同一个原生工厂，不向 Chat 暴露私有协议。Probe 和 Fork 使用独立的 ACP Management 短连接，不进入模型调用引擎。

`host/contract` 与 `host/workspace` 保存产品执行契约及工作区资源投射；`environment/config` 提供安装、探测和启动的中立值类型，`environment/diagnostic` 归一原生错误，`environment/catalog` 解释本地目录与探测结果。这些环境模块不导入宿主业务请求。具体入口见[执行内核说明](../../server/internal/agent/core/README.md)。

普通聊天在原生会话和静态配置一致时复用热连接，账号与插件交付资源随消费者持有。账号凭据的持久化并发修订不属于静态配置身份，正常保存或刷新凭据不会因此重建连接；账号修改、重新登录和撤销通过原有独占边界先回收闲置消费者。伙伴档案按身份、人格、行动手册的固定业务顺序组装，随后追加项目指令；相同内容不得因无序集合遍历而改变配置摘要。资源首次物化和会话准备分别记录耗时及复用原因，便于区分插件加载、原生启动和模型响应。

界面支持 Codex、Claude Code、Cursor、Kimi、Pi、OpenCode、Gemini CLI、Grok Build、WorkBuddy、Qoder、Qoder CN。是否可用由本机安装、版本、登录、模型及真实 initialize 能力决定。

各绑定共用宿主 SDK、Invocation 交付与消息投影，原生传输仍由对应 Adapter 管理，不能只检查公共队列：

| 绑定                                                               | 原生输出到公共接入层的路径                                                    |
| ------------------------------------------------------------------ | ----------------------------------------------------------------------------- |
| Codex                                                              | 共享 app-server 同步通知回调 → 宿主 SDK                                       |
| Claude Code                                                        | Session 所属进程的 stream-json 同步回调 → 宿主 SDK                            |
| Kimi、OpenCode、Gemini CLI、Grok Build、WorkBuddy、Qoder、Qoder CN | 原生 ACP stdio → nativeacp SDK → 宿主 SDK                                     |
| Cursor                                                             | nativeacp 控制面；正文由 PTY 与数据库检查点每 100ms 读取并同步通知 → 宿主 SDK |
| Pi                                                                 | 原生 RPC → Pi 事件队列 → 宿主 SDK                                             |

注册绑定的公共契约回归替换 Agent 工厂，验证各绑定进入公共层后的工具更新、取消与关闭；原生 stdio、RPC 和进程隔离另用测试进程验证。两者均不代表逐个安装版本、真实账号与模型的端到端验收。

ACP initialize 不声明尚无请求合同的原生 Schema 输出能力；宿主能力接收结构化候选与原生 Schema 输出分别判断。

聊天标题由 NeuxBot 管理。WorkBuddy 原生工厂仅为本应用启动的 CLI 进程设置官方 [`CODEBUDDY_CODE_DISABLE_TERMINAL_TITLE=1`](https://www.workbuddy.ai/docs/zh/cli/env-vars)，关闭重复的自动标题模型任务，避免该辅助任务阻塞 Prompt 回执；执行完成仍等待真实 `session/prompt` 响应，不以正文或标题通知推断终态。该环境在 CLI 启动时交付，已有热连接需由用户重启 Core 后重新创建，才会使用新策略。

Execution 只交付业务资源与工作范围；原生 HOME、插件目录和命令环境由 `agent/host/workspace` 统一投射，再交给统一启动生命周期。厂商选项的错误分类由 acp-go 对应 CLI 适配器归一化，公共 ACP 驱动按标准类别消费，不根据某个 CLI 的自定义选项 ID 猜测含义。附加目录只在原生能力声明支持时交付，宿主授权范围与原生扩展能力分别维护。

普通聊天的 ACP 事件通过宿主 SDK 通知队列与每 Invocation 交付队列串行交付；原生 ACP Runtime 在 CLI stdio 到 Adapter 的边界同样使用受控 SDK 通知队列。每个队列分别限制为 256 项和 16 MiB 待处理载荷，SDK 预算包含消费者正在处理的通知；解码对象、当前交付项和最终消息另有自身内存开销，不能把这些预算当作整个进程的内存上限。各边界满载均向生产端施加背压，不能在外层等待时让 SDK 的隐藏队列先断连。等待预算不持有序号锁、消费者快照锁或全会话路由锁；路由移除与回调引用共同保证队列关闭后不再写入。

Pi 自有 RPC 事件队列沿相同的 256 项与 16 MiB 预算等待真实消费，停止或取消由独立进程所有者解除，不以固定 1 秒的宿主暂停判定模型故障。正常消费者尚未接管的初始化阶段若超出预算，则明确返回启动资源错误以免控制响应被堵住；已接纳启动片段另有相同驻留预算，不截断。

只合并不含工具正文、输出或非空元数据的相邻累计输入快照，省略字段保留。元数据可能承载终端、MCP 或未知进度，统一按 `tool_update` 保序批写；只有所属 Runtime 明确证明是纯输入后才可在归属层归一化优化，通用层不能猜测。正文、执行输出、文件 Diff、其他工具、状态切换及终态保持原顺序。累计输入归一为独立的 `tool_input_snapshot`，其他非终态工具更新归为 `tool_update`，均不表示新的工具执行。持续交付失败取消当前 Prompt 并停止后续交付，保存首个失败，清理失败另记诊断；队列资源不足记录为事件交付失败，不归为 Runtime 程序不可用。已取消的交付在修改消息前拒绝；已经开始的耐久文件提交完成后再写终态，不能承诺 Context 可以强制中断操作系统文件 I/O。

ACP SDK 与原生 stdio Adapter 的修复统一在 acp-go 仓库维护，宿主只通过 `server/go.mod` 引用固定版本，不保存源码副本。SDK 位于该仓库的独立 `sdk` 子模块，保留上游协议类型，以 `github.com/JieWaZi/acp-go/sdk` 独立模块路径直接固定版本，宿主与 Adapter 使用同一份类型，无需 replace。通知队列显式启用条数、字节预算和独立传输关闭所有者，生成协议类型保持原样。响应之前的通知屏障仍由 SDK 维护，不在业务层另写 JSON-RPC 排序。ACP Driver 为每个会话创建独占连接，支持时可保留热会话；不同会话不共享原生进程。独立所有者取消直接关闭 Pipe 解除阻塞，不依赖拥塞连接发送关闭请求。桌面和 Web 打包从实际依赖模块目录复制原有许可及 NOTICE。

独立文本生成只返回最终正文、停止原因、用量与实际能力诊断。CLI 的正文片段直接由本次调用的收集器汇总，思考、过程与中间用量不进入聊天事件队列、消息投影或持久化；忽略过程内容仍更新活动时间。宿主不主动注入 AGENTS.md、Skill 或 MCP；CLI 自有工具与配置加载由 CLI 负责。取消、超时及进程收尾复用 Runtime 生命周期。

软件能力通过系统 `ally` Skill 交付。Core 将同包技能资源和当前平台的受管 CLI 一起准备到不可变目录，入口为 `scripts/allycli`（Windows 为 `scripts/allycli.exe`），知识指南为同目录下的 `references/wiki-guide.md`。CLI 字节与执行位参与内容摘要，程序更新后生成对应的新目录。执行指令提供 `SKILL.md`、CLI 和知识指南的明确绝对路径；`ALLYCLI_BINARY_PATH` 与进程 `PATH` 指向 Skill 内入口。智能体从 Skill 所在目录解析资源，无需搜索工作区或全局安装目录。

Qoder 与 Qoder CN 的项目技能目录均为 `.qoder/skills`；两者分别使用 `QODER_CONFIG_DIR`、`QODERCN_CONFIG_DIR` 用户配置根。安装探测同时检查 PATH 和官方用户级原生程序位置；不主动扫描仅用于桌面命令分发的 `entry` 目录。

探测保存可查询的安装证据与能力快照。启动后台、手动刷新、设置及显式账号能力查询触发探测；普通配置准入不隐式 Detect 或每次探测，读取已有事实。实际执行时初始化握手确认模型、档位和权限；未完成探测不能解释为未安装。多安装路径需明确选择实际版本。

## 账号隔离

系统配置使用 CLI 的原生登录。受管账号按身份与修订准备独立配置与原生状态；不会修改用户真实 CLI 主目录。凭据通过当前 Runtime 支持的配置、环境或文件交付，隔离目录只属于受管工作区。

普通对话、知识整理与能力查询共享账号执行租约，可在同账号下并发；登录和修改账号配置仍需独占。准备与回收凭据只占用短期凭据锁，模型生成期间不持有该锁。各执行独立投射认证文件，回收时比较原始凭据快照，已被其他执行更新的账号不接受旧投射覆盖。

`environment/launch` 统一管理原生消费者的认证资源，显式区分系统原生认证与受管账号；没有 Refresh 回调不表示系统账号。AIAccount 准备和冻结受管账号租约，启动器只接收刷新与可重试释放端口，不读取产品数据库。

Codex 原生令牌刷新通过随机能力路径的回环端点交给宿主。受管账号以加密保存的数据库凭据为权威，系统文件账号以原生认证文件为权威；刷新在同账号或同认证文件内协调，已轮换的旧令牌直接取得最新结果，不重复请求认证服务。已收到并成功解析的轮换结果使用独立的有界保存窗口，调用方取消也不能丢弃新凭据；持久化后才返回 CLI。原生消费者退出后，启动器先停止刷新入口并等待已接纳请求完成持久化，再对账系统文件、释放账号及受管目录；任一阶段失败都保留原所有者，后续只重试关闭。准备或原生构造的部分失败也交回可关闭对象。刷新不经过公开业务 API，不进入模型上下文或日志。系统文件账号同时识别本进程原生进程延迟写入的旧令牌，在后续凭据访问和进程收尾时恢复同身份的已知最新结果，不覆盖外部新登录或恢复已删除的认证；外部 CLI 进程不受宿主锁约束。

一个 API Key 账号选择一个请求协议、服务地址及可用模型。Responses、Chat Completions、Anthropic Messages、Google GenerateContent 的支持范围由 Runtime 与所选服务共同决定，不进行透明协议转换。

模型 ID、显示名称、上下文与思考菜单分别保存。菜单来自所选账号和模型的真实能力；不把其他模型的选项当作当前能力。切换账号后重新校验模型、权限和原生会话可续接条件。

## 权限与交互

产品三级权限由 Runtime 映射到原生策略。Qoder 与 Qoder CN 通过官方 `--acp` stdio 入口接入，按会话实际声明的模式提供默认、自动审批与完全访问；旧版未声明自动审批时不展示，不提供只读模式。自动审批仍受模型风险审查、原生规则和能力限制；完全访问也不能代替用户回答业务问题。

结构化审批和用户问答通过所属 Execution 的精确身份路由；取消、断线与会话结束必须释放等待。MCP 传输、附加目录、分叉和流式追加各自声明能力，不以运行时名称推断支持。

进程、Pipe、Session 与应用生命周期有明确归属。受控退出取消调用并回收进程树；正常关闭与实际协议失败分别记录。依赖版本以 server/go.mod 为准，升级后执行受影响包的定向检查及对应真实 CLI 验证。

资源物化后的任务授权环境在统一启动器的最终构造边界复制并交付，包含本轮能力连接、受管 CLI 和 PATH；只验证 Driver 请求中的环境不足以证明原生进程已收到。隐藏交接的只读消费者由 Core 在结束后强制回收，随后普通回合重新按原策略准备。冷准备部分失败仍交回资源租约，账号回收失败保留释放入口，不仅记录日志后丢弃所有权。
