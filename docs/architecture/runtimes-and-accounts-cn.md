# 智能体与账号

## Runtime 边界

普通聊天及通过 Execution 发起的团队、自动任务和 IM 使用 `Execution → ThreadLifecycle/Turn → ProviderRuntime → acp-go 原生 Client`。应用装配一个 ProviderRuntime 和一个 ThreadLifecycle；执行实现位于 `server/internal/agent`，ConversationStore 位于 `server/internal/chat/conversation`，均属于 server 主 Go 模块。

Execution 拥有业务接纳、执行状态、工具授权与交付；ThreadLifecycle 拥有公开聊天的原生绑定、配置兼容与历史接力；Turn 拥有一次输入的准备、耐久接纳、提交和结算。ProviderRuntime 独占原生连接、账号及物化资源租约。失败关闭保留原所有者供重试，不能先释放仍被原生进程使用的凭据和文件。

每个公开会话连接独立拥有原生进程。ThreadLifecycle 分别判断进程复用与原生历史兼容：启动环境、认证代次或实际资源配置变化可重开进程，主体、历史根与授权仍兼容时恢复原 SessionID，只提交新增输入。确需替换会话时才播种最近五个完整轮次或既有总结。模型选项由实际 setter 回执确认；目录与诊断刷新不作为会话身份。

| CLI                          | 传输及所有者                                                            |
| ---------------------------- | ----------------------------------------------------------------------- |
| Codex                        | `acp-go/pkg/codex` 的 app-server                                        |
| Claude                       | `acp-go/pkg/claude` 的 stream-json                                      |
| Cursor                       | 共享 `acpclient` 独占官方 ACP 执行，Cursor 专有钩子补充单轮结束后的用量 |
| WorkBuddy、Qoder             | 独立协议配置接入共享 `acp-go/pkg/acpclient`                             |
| Kimi、Gemini、Grok、OpenCode | `acp-go/pkg/standardacp` 配置启动和已证实差异，共用 ACP 生命周期        |
| Pi                           | `acp-go/pkg/pi` 的原生 RPC、事件队列与会话文件身份                      |

`agent.Catalog` 与原有注册描述保留程序定位、安装与静态资源事实。欢迎页的启动探测保存各运行环境默认账号的模型目录，聊天查询使用统一 Runtime 模型目录 API，按运行环境、账号和配置隔离数据库快照。系统账号先确认当前可观察主体，再复用该主体目录；没有快照时等待一次原生探测。同一配置的并发探测共用结果，模型弹层可手动刷新当前账号。

探测状态、认证诊断和模型目录只说明最近观察并提供候选，不作为实际执行的准入条件。探测失败或目录刷新中仍保留用户选择，不能禁用智能体、替换默认项、清空模型参数或降低权限。用户启用、账号配置及适配器支持范围按当前配置校验；进程启动、认证、模型设置与权限支持由本次原生调用确认。首次引导可在明确保存合法默认配置后结束，空模型使用原生默认。

聊天模型弹层用左侧智能体列表预览账号目录，选定模型后一次提交智能体、账号和模型。弹层内可继续调整所选模型的强度和 Fast。普通聊天将上下文窗口与强度并排放在弹层底部，原生目录至少确认两个档位时才显示窗口选择器。窗口选择按模型保存到执行事实，并在重新打开聊天时恢复。默认模型取当前账号适用的配置或原生目录声明。显式选择系统账号时，仅当它也是智能体默认账号才继承环境默认模型，否则保留原生空模型。已接纳的空模型保持原选择。当前档位与最大上下文分别展示。原生会话设置在提交消息前以回执确认。目录声明了可选强度时使用下拉框，旧式模型值固定强度时显示只读值。

独立知识生成、Wiki 维护和工作流输出修复使用同一 ThreadLifecycle。当前独立调用要求能验证工具范围，由 Claude 原生客户端提供。工作流创作和节点执行在 Runtime 无法证明指定工具范围时，于获取原生账号租约之前拒绝。

## 工作范围与资源

Execution 解析本轮有效业务选择与授权目录，读取已发布资源声明。系统 ally 技能在执行服务初始化时发布；用户技能和插件版本提供内容摘要及目标元数据，热续聊不重新物化系统技能、遍历整包或计算源目录摘要。ProviderRuntime 冷获取时核对版本与配置、解密实际交付的 MCP 并发布技能；共享目标保护与冷内容完整性检查继续执行。

Execution 直接构造现有 ThreadRequest、TurnRequest 和 TurnPorts。伙伴档案、稳定角色及能力说明由 `developer_instructions.go` 组合后交给原生指令入口；本轮路径、引用、节点结果与团队模式只随新增输入发送，不重写工作区 AGENTS.md／CLAUDE.md。技能清单只登记受管目标，不清空用户技能目录。CLI 调用使用明确程序路径与本轮 `--context`；账号和插件原生环境由实际租约交付。附加目录、MCP、指令、分叉、steering 与压缩依实际能力确认。Claude 新进程可重新读取资源；指令替换另按原生版本能力判断。Codex 的不可重载工具配置变化仍替换会话，不泛化其他 CLI 的能力。

共享 cwd 的技能预约由同一个 ProviderRuntime 连接索引持有，按物理发现目标、内容摘要与固定插件版本判定兼容。同内容消费者共享；冲突的活动或准备中消费者拒绝新接纳，闲置消费者先关闭再替换。关闭失败保留原预约与文件。清单按发现目标合并，只管理已归属副本；文件事务锁不串行执行任务。

WorkBuddy 仅对本应用子进程设置 `CODEBUDDY_CODE_DISABLE_TERMINAL_TITLE=1`，聊天标题由 NeuxBot 管理。Prompt 的终态仍由原生回执决定。它的部分版本会对丢失会话返回空成功，因此冷 load 必须取得真实恢复证据，否则明确失败。该校验不改变会话替换的历史接力机制。

OpenCode 同目录 MCP 注册的冲突域在原生进程内。宿主对不同聊天使用独立进程与租约，不共享 MCP 凭据。Pi 的 MCP 通过受管扩展桥接；扩展注册就绪与各 MCP 服务连接成功是不同证据。

## 设置与账号归属

设置的智能体列表是程序、账号和模型配置的统一入口，账号不再使用独立顶级设置页。进入具体智能体详情后管理订阅登录、API 账号、程序状态及默认账号／模型／推理／Fast。原生系统账号继续读取该 CLI 的原生配置；受管账号归属于一个完整的实际 `runtimeId`，包含 Profile 身份，不以相同协议推断跨智能体共享。

AIAccount 在所属智能体内以名称唯一。创建必须指定已存在且协议兼容的智能体，修改不能转移归属；读取可按智能体筛选。默认账号绑定、原生模型与推理目录、普通聊天接纳和独立生成都校验相同归属。账号凭据、登录工作与活动租约仍由原账号模块负责，不并入程序安装或运行环境记录。当前数据结构不对旧无归属账号进行转换或兼容回填。

未显式指定模型时，所选账号等于该智能体默认账号才继承智能体默认模型，随后使用账号默认模型与原有目录回退。推理强度只继承当前模型适用的默认值。界面切换智能体清除旧账号、Fast 和上下文档位，再读取目标智能体适用的配置；其他同协议配置的账号不会进入其选择器。

Qoder 统一发现 `qoder`、`qodercli` 和 `qoderclicn`，不注册独立 CN 条目。所选程序决定原生配置及账号范围；模型目录直接读取 ACP，不再合并 SDK 目录或添加“新模型”分组。

版本行在发现多个可用安装实例时提供下拉选择，按已核实路径保存；切换后重新读取安装、账号与模型目录，后续执行使用所选程序。重新探测保留已选择的版本。

智能体详情不提供手动程序路径、前置参数、配置目录或额外运行时模型设置。这些启动参数仅由 Catalog 静态定义及已核实的检测／受管安装快照恢复，不读取旧用户设置列。欢迎引导使用同一份只读程序发现结果，不再保存或切换用户路径。

设置里的安装和更新由 Core 的运行时服务管理，每个基础 CLI 只有一个任务，Profile 共用程序、分别保留账号和执行身份。任务独立于 HTTP 请求和页面；显式取消与 Core 关闭会回收下载／验证进程，发布前核验官方制品和实际版本。程序以完整、不可变版本保存在 `runtime-installations/<base>/version-...`；失败与取消不删除旧可用版本。当前任务在 Core 内存中保存，重启后只读恢复完整已发布记录，不把暂存目录视为已安装，也不在 GET 请求中检查网络更新。

安装器提供 Codex、Claude、Cursor、Kimi、Gemini、OpenCode、Pi、Grok、Qoder 与 WorkBuddy 的官方来源。支持 macOS arm64／amd64、Linux glibc arm64／amd64 和 Windows amd64；Linux musl 仅使用已明确发布的 Codex 静态制品。Gemini 需要 Node.js 20+ 和 npm，依赖安装限于受管目录并禁用生命周期脚本。具备发布方摘要的制品按其摘要验证；Cursor、Grok 上游未提供相同摘要时使用官方 TLS 来源与实际程序版本验证，不伪造发布方校验。实际平台验收与合成 HTTP／运行器测试分别记录。

下载进度使用 `runtime.installation.changed` 只唤醒对应安装快照；终态另发 `runtimecontract.changed`。智能体列表和模型目录不因每段下载进度重新探测。

版本快照区分所选程序的本机版本、受管或系统来源，以及最近一次官方检查结果。显式检查同时读取程序的真实版本和官方元数据，不下载制品；未知、检查失败与已确认无需更新分别表达。只有确认更高可用版本后才提供更新，安装接纳前复核本机状态，完整性通过的当前版本或更高版本不重复下载。受管收据有效但程序文件损坏或丢失时允许同版本重新安装，重新校验官方制品并发布新版本目录，不执行已知损坏的旧程序，也不复用其他健康副本跳过修复。重启通过 ThreadLifecycle 与 ProviderRuntime 的维护围栏阻止新消费者，活动或准备中的任务拒绝重启；闲置原生连接确认关闭后重新探测，失败关闭保留原所有者供重试。

自动安装失败保留安全的原因分类与上游状态，不把带签名 URL、代理认证或命令输出带到界面。网络与上游限流／临时故障使用有界重试，官方 GitHub 资产可在同一发布元数据和摘要下使用官方资产 API 备用入口；摘要不匹配不能改走备用来源掩盖。界面保留对应官方下载页面，手工安装完成后由原检测流程发现，不保存另一套程序配置。

维护以当前选中的程序路径和真实安装来源为准。应用自装版本保留在应用数据目录；当前使用用户已有的 CLI 时，不能下载另一份私有版本冒充对原安装的更新。有证据的包管理器安装沿用原安装方式，无法确认归属或维护方式时明确返回不支持自动维护。更新后的实际程序路径和解释器入口在围栏释放前同步到同一基础 CLI 的全部 Profile，重新探测保留该只读启动事实；原静态配置参数只附加一次。删除应用自装 CLI 会清理该基础 CLI 的全部可验证程序版本，避免删除后回退到旧版本；账号、原生登录配置、伙伴及默认执行设置保留。

安装替换、删除和重启共享程序维护准入。ProviderRuntime 先排空空闲消费者，随后阻止账号服务启动新的原生管理进程；系统只读能力握手、Claude 状态／登录进程和 Kimi 登录子进程同样属于真实程序使用者。活动任务拒绝维护，关闭失败保留原进程所有者，不能提前替换或删除仍在使用的程序。

## 账号隔离

系统账号使用所选 CLI 的原生认证；受管账号按账号身份、认证代次和实际原生配置准备目录。账号只有一个请求协议与服务地址。名称、默认模型及强度等普通设置保存不取得进程独占；凭据、端点、重新登录与撤销仍通过实际身份边界协调消费者。Revision 只用于配置并发，AuthGeneration 隔离旧凭据。单一 home 随认证轮换的 CLI 不承诺恢复旧历史；没有可验证真实主体的登录继续保守隔离。

发送、续聊、steering、恢复与分叉的账号 Resolve／Acquire／提交校验只核对本地选择，不启动独立 status、账号身份或远端 GetMe 诊断。真实 CLI 执行决定登录是否可用，并通过既有错误通道报告认证、额度或权限失败。Codex 已知文件凭据在新物理连接上保留不开网络、不刷新令牌的模式／配置根／摘要证明，不再重复 account/read；热续聊复用连接。独立适配库遵守同一[后端硬约束](../development/backend-cn.md#82-执行关键路径禁止诊断探测)。用户显式登录、检查账号和额度／模型管理的生命周期仍独立保留。

系统账号认证由运行时服务拥有独立原生管理会话，不创建受管订阅账号，也不搬运系统凭据。能力握手只读取真实认证广告；可执行的 agent 方法允许网页登录，终端／环境变量方法不能冒充登录。Kimi 内置账号通过所选 CLI 的 `login --help` 确认设备授权能力，调用同一程序的 `login`，将原生授权地址和验证码交付已有登录弹窗。命令成功后启动新的 ACP 管理进程，复用现有隔离模型发现流程：Kimi 2.x 在创建空探测会话前执行原生认证门禁，成功后关闭该会话，不提交 Prompt 或创建公开聊天。连接状态以这一原生门禁回执为依据，不以本地凭据或静态模型列表存在作为登录证明。失败的能力读取保留结果，用户显式重试才重新握手。真正授权由 Core 生命周期持有，状态通过 `runtime.authentication.changed` 对账，完成后发布原运行时合同变化；取消匹配精确任务身份，关闭失败保留同一原生进程和维护围栏。

认证结果区分既有登录确认、连接确认和新授权完成。Codex 原生客户端可复用已有 ChatGPT 登录，不保证重新打开浏览器；现有身份仍须经过原生认证中的刷新验证，空成功响应后继续查询原生账号确认身份，API Key 或缺失账号不能当作订阅登录成功。当前公开管理端口不支持强制重新授权，不通过删除系统凭据模拟该能力。

Kimi 分别识别 `KIMI_SHARE_DIR` 和 `KIMI_CODE_HOME`；Gemini 的 `GEMINI_CLI_HOME` 包含 `.gemini`；Pi 使用 `PI_CODING_AGENT_DIR`；Grok 使用 `GROK_HOME`；OpenCode 分别固定 XDG 配置、数据、缓存及状态根。Qoder 使用 `QODER_CONFIG_DIR` 指定配置根，默认沿用 `~/.qoder`。仅改变 OpenCode 配置目录不能被当作凭据隔离。

ProviderRuntime 对照账号租约校验原生数据根。模型探测在账号管理接口缺失时继续读取原生目录，明确的登录失败仍单独记录。

面向用户的错误说明使用智能体、模型和对话等产品概念；Runtime、Adapter 等内部名称保留在稳定错误码和诊断中。模型选项不受支持、原生拒绝设置或回执未确认所选模型时，在相应失败边界保留模型选择原因；认证、额度和限流原因继续独立表达。

系统账号的本地身份摘要用于发现可观测的切换，不等于服务器认证成功。凭据快照排除已确认的 OAuth access/expiry 更新；存在可信账号标识时绑定该标识，否则保守绑定保存的授权凭据。CLI 自行持久化的默认模型不应使正常续聊误报账号变化。

Cursor 与 Claude 的系统选择不为证明登录调用 Keychain 或原生 CLI；原生私有存储／内存中的外部换号无法由宿主完整观察。Qoder 不透明加密文件变化按保守身份变化处理，可能重建连接，不以身份状态缓存掩盖这一边界。未观察到系统登录不表示已认证，也不单独阻止实际调用；损坏、不安全的本地配置和明确失配的所选凭据仍拒绝。托管 Claude 的执行准备、提交校验与退出只同步所选配置根的本地凭据，继续按账号、认证代次及 CAS 防止旧进程覆盖新凭据；显式登录仍核验原生授权结果。

Codex 令牌刷新继续经随机能力路径的回环端点协调。受管账号以加密数据库凭据为权威，系统文件账号以原生文件为权威。成功轮换后即使请求取消，也必须完成有界持久化；原生消费者退出后先停止刷新入口，再释放账号与目录。旧投射不能覆盖其他执行已更新或外部重新登录的凭据。

受管 API 账号选择请求协议、服务地址和可用模型，不做透明协议转换。Codex、Claude 与 Kimi 订阅账号使用各自原生授权和独立目录。Claude 复用官方原生浏览器登录，成功回执与同一受管根的凭据快照一起加密保存；macOS 只操作该显式配置根派生的精确 Keychain 项，其他平台及原生回退使用受管文件。恢复、令牌刷新和注销遵守同一账号租约及认证世代，旧进程不能覆盖新的登录凭据；不读取或搬运系统账号根。OpenCode 与 Pi 的受管命名空间在边界转换，其他原生服务商的同名模型不能混入。模型、强度和 Fast 以原生回执为准，未知菜单不借用其他模型的选项。已列出模型可在支持的权限下使用原生默认配置；可选设置未知不等于模型不可用，显式设置仍独立校验。WorkBuddy 在随进程回收的独立配置根内探测每个模型的强度。

Qoder 适配器并行读取 SDK 目录和 ACP 可选项，按原生模型 ID 合并两份目录。聊天弹层展示新模型和自定义模型。已确认的 ACP 强度优先，缺失的逐模型强度使用 SDK 明确提供的选项。启动会话时向 Qoder 传入所选模型，执行前核对原生回执。合并目录移除 SDK 标记不可用的模型，保留可用的 SDK 模型与 ACP 独有模型。运行时拒绝所选模型时显示账号不可用提示。上下文档位来自同账号的 SDK 目录，经校验后通过原生启动参数传入，档位变化时重新打开进程并恢复同一个原生会话 ID。缺少 SDK 查询能力的 CLI 沿用旧的账号通道和 ACP 可选项。Qoder 和 WorkBuddy 在原生目录提供 Credits 倍率时显示该倍率。

## 用量快照

规范原生终态 JSONL 是消费权威，SQLite 只保存可重建的 Token 查询投影。流式观察用于当前展示，不能因交付失败丢弃已有终态消费。调用身份负责去重；模型明细和调用总计分开，不能重复记账。日期、智能体、模型和伙伴分组及分页共享查询快照。模型分组保留原生模型 ID，界面按所属智能体的已有模型目录解析显示名；未知或已不在目录的模型保留原始 ID。

产品不提供价格表、Token 计价、费用字段或费用界面。原生返回的金额只可保留为原始技术证据。旧费用投影升级后重建，不把只有费用的模型行保留为 Token 消费。

输入、缓存读取、缓存写入和输出是互斥的加法分量；推理属于输出子集。每类计数区分未知与明确零，覆盖完整与字段完整分别判断。原生上下文大小不能作为消费量。整轮、已观察请求和不明范围的计数分别归属，不以数字相同判断重复请求，也不把未知数据补成零。

缓存命中率用缓存读取量除以普通输入、缓存写入和缓存读取之和。存在覆盖缺口时，已记录的命中率只使用三项计数均已知的调用。查询投影不完整且没有读到调用记录时，概要和趋势保留未知。

Token 完整性统一由原生覆盖事实和加法分量判断：规范用量声明覆盖完整调用，且普通输入、缓存读取、缓存写入与输出四项均已知，才有完整总量。任何计数都没有时记录为用量缺失；有计数但覆盖不完整或缺少上述任一分量时记录为用量不完整。推理是输出子集，缺少独立推理计数不影响总量完整性。原生协议明确规定省略等于零时由对应适配器归一化，其他缺失值保留未知。来源、账号或模型归属未知与 Token 字段完整性分别记录。

聊天的耗时浮层只展示耗时与已确认的计数，不展示用量缺失、用量不完整或仅覆盖末次请求等说明；这些覆盖缺口统一在用量统计页展示，聊天展示不改写底层完整性事实。普通输入尚不能安全拆分时，来源和本次范围均已核实的原生输入通过 `reportedInput` 单独展示，不与缓存重复求和；末次请求、未知范围、累计会话及相互矛盾的观察不升级为本次原生输入。统计投影升级后从规范终态重建该字段，单一实际模型可继承同轮原生输入，多模型不分摊未知明细。

CLI 用量采集不以程序版本白名单启停。适配器尝试当前 ACP 回执和原生历史，以字段结构、计数关系、会话与请求身份确认消费；兼容格式在新版本继续读取，格式不兼容或证据缺失时保留未知。版本号用于诊断和已核实口径的说明，不代替数据校验。

Qoder 在同一 ACP 调用后按原生用户 UUID、会话、父链和工具结果身份读取本轮历史追加区间，补充输出、实际模型、正值缓存与独立原生输入观察；未保留可用性标志的零缓存不表示已测零。消息模型仍为 `auto` 时，可用同一原生会话、本轮输入之前且无冲突的 `runtime-config` 快照确定具体模型；具体响应模型优先，缺少快照时不借用宿主当前选择改写归属。WorkBuddy 通过原生会话、请求和模型响应标识核对本轮写入的用量，在已证实的 Chat Completions 计数形状下拆分普通输入、缓存与输出，缓存明细中的正值优先于顶层零占位。缓存写入零值的来源不能独立确认时，写入和依赖它拆分的普通输入保持未知；其他形状只保留已核实的原生输入观察。Gemini 直接读取本轮 ACP 用量账本，普通输入扣除缓存，输出加回独立思考计数；单一实际模型的原始输入和候选输出均与本轮账本一致时，才将整组规范计数归到该模型。ACP 的末次请求样本仅供聊天展示，已有输出小计时展示小计。

Cursor 保持原生 ACP 的实时执行，专有用量钩子在子进程加载唯一匹配结构的模块时挂接 `turnEnded`，不修改安装文件或项目配置。单轮结束后，以本轮 nonce、原生会话、请求和输入身份核对计数，再进入既有聊天和统计投影；模型来自同一原生 run 收到的模型参数，缺失或一轮出现不同模型时保留未知，不用宿主选择补写旧记录。重复事件不累加，冲突或缺失保持未知。原生输入包含缓存，缓存分类齐全时才拆出普通输入。用量钩子不决定成功、失败或取消，也不缓存文本增量。已核对模块使用固定摘要；其他版本按唯一结构定位采集点，并验证编译内容与磁盘模块一致。结构不兼容、匹配冲突或摘要不一致时，ACP 继续执行，Token 保持未知。OpenCode 的计数范围见 [CLI 迁移核对](../discussions/agentruntime-rebuild/native-cli-completion-cn.md#token-产品合同)。

新迁移 CLI 的具体来源和完整性边界见 [CLI 迁移核对](../discussions/agentruntime-rebuild/native-cli-completion-cn.md#token-产品合同)。真实模型、安装版本和平台验收与合成协议测试分开记录。

## 权限与交互

权限菜单只展示当前智能体及模型能表达的权限。Cursor 的完全访问使用原生 `--force`。Cursor 的官方 ACP 管理会话保持伙伴或领域 cwd，所选项目通过独立 projects 入口访问。目录交付优先使用已经核实的原生启动参数或握手附加目录能力；明确不支持时才创建项目入口，缺少能力证据仍保持未知。Gemini 通过 `--include-directories` 接收授权的项目目录。Gemini、OpenCode 和 Grok 不展示尚未确认的自动风险审批。Claude 的自动审批取决于模型，完全访问取决于原生进程。Kimi、WorkBuddy 和 Qoder 以原生模式菜单为准。Pi 只有配备受管桥接组件时才提供自动审批。

只读工作区是额外的执行约束，不能用默认审批替代。当前只接受有明确隔离合同的 Codex 路径；其他 CLI 在接纳前拒绝只读请求。

结构化审批和用户问答按所属 Execution 的精确身份路由，取消与关闭释放等待。原生输入确认、执行终态、事件交付和持久化失败分别保存：Pi 的 prompt ACK 不代表执行完成，原生终态也可以先于 ACK 到达。无法确认原生终态时不制造失败或成功，不自动重放可能已执行的输入。

acp-go 与 acp-go-sdk 分别在独立仓库维护；宿主固定已发布版本，`GOWORK=off` 可独立构建，不以本机 replace 替代发布依赖。生成协议和公开 API 通过对应生成器更新；合成测试不代替用户的 CLI、模型与界面验收。
