# 智能体与账号

知识模型生成使用 `GenerateText` 独立入口，复用 ACP 适配与账号事实，直接返回正文、停止原因、用量和实际配置诊断，不进入 Execution 或聊天 JSONL。具体约束见[知识库](knowledge-cn.md#cli-调用与生命周期)。

## Runtime 边界

internal/runtimes 提供数据库无关的探测、能力与执行适配。它复用 acp-go 的公共适配器，将智能体事件、审批、问答、会话与错误归一给 Execution。增加智能体通过现有注册和能力边界完成，不向 Chat 暴露私有协议。

界面支持 Codex、Claude Code、Cursor、Kimi、Pi、OpenCode、Gemini CLI、Grok Build、WorkBuddy、Qoder、Qoder CN。是否可用由本机安装、版本、登录、模型及真实 initialize 能力决定。

各绑定共用宿主 SDK、Invocation 交付与消息投影，原生传输仍由对应 Adapter 管理，不能只检查公共队列：

| 绑定                                                               | 原生输出到公共接入层的路径                                                    |
| ------------------------------------------------------------------ | ----------------------------------------------------------------------------- |
| Codex                                                              | 共享 app-server 同步通知回调 → 宿主 SDK                                       |
| Claude Code                                                        | Session 所属进程的 stream-json 同步回调 → 宿主 SDK                            |
| Kimi、OpenCode、Gemini CLI、Grok Build、WorkBuddy、Qoder、Qoder CN | 原生 ACP stdio → nativeacp SDK → 宿主 SDK                                     |
| Cursor                                                             | nativeacp 控制面；正文由 PTY 与数据库检查点每 100ms 读取并同步通知 → 宿主 SDK |
| Pi                                                                 | 原生 RPC → Pi 事件队列 → 宿主 SDK                                             |

注册绑定的公共契约回归替换 Agent 工厂，验证各绑定进入公共层后的工具更新、取消与关闭；原生 stdio、RPC 和进程隔离另用测试进程验证。两者均不代表逐个安装版本、真实账号与模型的端到端验收。

ACP initialize 不声明尚无请求合同的原生 Schema 输出能力；宿主能力接收结构化候选与原生 Schema 输出分别判断。

普通聊天的 ACP 事件通过宿主 SDK 通知队列与每 Invocation 交付队列串行交付；原生 ACP Runtime 在 CLI stdio 到 Adapter 的边界同样使用受控 SDK 通知队列。每个队列分别限制为 256 项和 16 MiB 待处理载荷，SDK 预算包含消费者正在处理的通知；解码对象、当前交付项和最终消息另有自身内存开销，不能把这些预算当作整个进程的内存上限。各边界满载均向生产端施加背压，不能在外层等待时让 SDK 的隐藏队列先断连。等待预算不持有序号锁、消费者快照锁或全会话路由锁；路由移除与回调引用共同保证队列关闭后不再写入。

Pi 自有 RPC 事件队列沿相同的 256 项与 16 MiB 预算等待真实消费，停止或取消由独立进程所有者解除，不以固定 1 秒的宿主暂停判定模型故障。正常消费者尚未接管的初始化阶段若超出预算，则明确返回启动资源错误以免控制响应被堵住；已接纳启动片段另有相同驻留预算，不截断。

只合并不含工具正文、输出或非空元数据的相邻累计输入快照，省略字段保留。元数据可能承载终端、MCP 或未知进度，统一按 `tool_update` 保序批写；只有所属 Runtime 明确证明是纯输入后才可在归属层归一化优化，通用层不能猜测。正文、执行输出、文件 Diff、其他工具、状态切换及终态保持原顺序。累计输入归一为独立的 `tool_input_snapshot`，其他非终态工具更新归为 `tool_update`，均不表示新的工具执行。持续交付失败取消当前 Prompt 并停止后续交付，保存首个失败，清理失败另记诊断；队列资源不足记录为事件交付失败，不归为 Runtime 程序不可用。已取消的交付在修改消息前拒绝；已经开始的耐久文件提交完成后再写终态，不能承诺 Context 可以强制中断操作系统文件 I/O。

ACP SDK 与原生 stdio Adapter 的修复统一在 acp-go 仓库维护，宿主只通过 `server/go.mod` 引用固定版本，不保存源码副本。SDK 位于该仓库的独立 `sdk` 子模块，保留上游协议类型，以 `github.com/JieWaZi/acp-go/sdk` 独立模块路径直接固定版本，宿主与 Adapter 使用同一份类型，无需 replace。通知队列显式启用条数、字节预算和独立传输关闭所有者，生成协议类型保持原样。响应之前的通知屏障仍由 SDK 维护，不在业务层另写 JSON-RPC 排序。Claude 连接沿已有每 Session CLI 归属保持独占和热复用。Codex 保留共享 app-server 的热复用与既有进程数量；同连接上的其他会话可能短暂等待背压，当前会话超时或取消不能使它们失败。独立所有者取消直接关闭 Pipe 解除阻塞，不依赖拥塞连接发送关闭请求。桌面和 Web 打包从实际依赖模块目录复制原有许可及 NOTICE。

独立文本生成只返回最终正文、停止原因、用量与实际能力诊断。CLI 的正文片段直接由本次调用的收集器汇总，思考、过程与中间用量不进入聊天事件队列、消息投影或持久化；忽略过程内容仍更新活动时间。意外工具与交互继续拒绝，取消、超时及进程收尾复用 Runtime 生命周期。

软件能力通过系统 `ally` Skill 交付。Core 将同包技能资源和当前平台的受管 CLI 一起准备到不可变目录，入口为 `scripts/allycli`（Windows 为 `scripts/allycli.exe`），知识指南为同目录下的 `references/wiki-guide.md`。CLI 字节与执行位参与内容摘要，程序更新后生成对应的新目录。执行指令提供 `SKILL.md`、CLI 和知识指南的明确绝对路径；`ALLYCLI_BINARY_PATH` 与进程 `PATH` 指向 Skill 内入口。智能体从 Skill 所在目录解析资源，无需搜索工作区或全局安装目录。

Qoder 与 Qoder CN 的项目技能目录均为 `.qoder/skills`；两者分别使用 `QODER_CONFIG_DIR`、`QODERCN_CONFIG_DIR` 用户配置根。安装探测同时检查 PATH 和官方用户级原生程序位置；不主动扫描仅用于桌面命令分发的 `entry` 目录。

探测保存可查询的安装证据与能力快照。查询使用持久事实，连接测试与能力刷新是明确操作；未完成探测不能解释为未安装。多安装路径需明确选择实际版本。

## 账号隔离

系统配置使用 CLI 的原生登录。受管账号按身份与修订准备独立配置与原生状态；不会修改用户真实 CLI 主目录。凭据通过当前 Runtime 支持的配置、环境或文件交付，隔离目录只属于受管工作区。

普通对话、知识整理与能力查询共享账号执行租约，可在同账号下并发；登录和修改账号配置仍需独占。准备与回收凭据只占用短期凭据锁，模型生成期间不持有该锁。各执行独立投射认证文件，回收时比较原始凭据快照，已被其他执行更新的账号不接受旧投射覆盖。

Codex 原生令牌刷新通过随机能力路径的回环端点交给宿主。托管账号以加密保存的凭据为权威，系统文件账号以原生认证文件为权威；刷新在同账号或同认证文件内协调，已轮换的旧令牌直接取得最新结果，不重复请求认证服务。已收到并成功解析的轮换结果使用独立的有界保存窗口，调用方取消也不能丢弃新凭据；持久化后才返回 CLI。刷新入口随原生 Agent 关闭，不经过公开业务 API，不进入模型上下文或日志。系统文件账号同时识别本进程原生进程延迟写入的旧令牌，在后续凭据访问和进程收尾时恢复最新结果；外部 CLI 进程不受宿主锁约束。

一个 API Key 账号选择一个请求协议、服务地址及可用模型。Responses、Chat Completions、Anthropic Messages、Google GenerateContent 的支持范围由 Runtime 与所选服务共同决定，不进行透明协议转换。

模型 ID、显示名称、上下文与思考菜单分别保存。菜单来自所选账号和模型的真实能力；不把其他模型的选项当作当前能力。切换账号后重新校验模型、权限和原生会话可续接条件。

## 权限与交互

产品三级权限由 Runtime 映射到原生策略。Qoder 与 Qoder CN 通过官方 `--acp` stdio 入口接入，按会话实际声明的模式提供默认、自动审批与完全访问；旧版未声明自动审批时不展示，不提供只读模式。自动审批仍受模型风险审查、原生规则和能力限制；完全访问也不能代替用户回答业务问题。

结构化审批和用户问答通过所属 Execution 的精确身份路由；取消、断线与会话结束必须释放等待。MCP 传输、附加目录、分叉和流式追加各自声明能力，不以运行时名称推断支持。

进程、Pipe、Session 与应用生命周期有明确归属。受控退出取消调用并回收进程树；正常关闭与实际协议失败分别记录。依赖版本以 server/go.mod 为准，升级后执行完整检查和受影响的真实 CLI 验证。
