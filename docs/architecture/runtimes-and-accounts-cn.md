# 智能体与账号

## Runtime 边界

普通聊天及通过 Execution 发起的团队、自动任务和 IM 使用 `Execution → ThreadLifecycle/Turn → ProviderRuntime → acp-go 原生 Client`。应用装配一个 ProviderRuntime 和一个 ThreadLifecycle；执行实现位于 `server/internal/agent`，ConversationStore 位于 `server/internal/chat/conversation`，均属于 server 主 Go 模块。

Execution 拥有业务接纳、执行状态、工具授权与交付；ThreadLifecycle 拥有公开聊天的原生绑定、配置兼容与历史接力；Turn 拥有一次输入的准备、耐久接纳、提交和结算。ProviderRuntime 独占原生连接、账号及物化资源租约。失败关闭保留原所有者供重试，不能先释放仍被原生进程使用的凭据和文件。

每个公开会话连接独立拥有原生进程。同一会话的热续聊沿用连接；原生恢复只提交新增输入；会话替换才播种最近五个完整轮次，或使用既有总结接力。模型 setter 支持热更新时，单纯模型选择不替换历史；进程级权限、账号身份、工作范围和资源版本改变则重新判断兼容。

| CLI | 传输及所有者 |
| --- | --- |
| Codex | `acp-go/pkg/codex` 的 app-server |
| Claude | `acp-go/pkg/claude` 的 stream-json |
| Cursor、WorkBuddy、Qoder、Qoder CN | 独立协议配置接入共享 `acp-go/pkg/acpclient` |
| Kimi、Gemini、Grok、OpenCode | `acp-go/pkg/standardacp` 配置启动和已证实差异，共用 ACP 生命周期 |
| Pi | `acp-go/pkg/pi` 的原生 RPC、事件队列与会话文件身份 |

`agent.Catalog` 与原有注册描述保留程序定位、安装与静态资源事实。普通模型与 Thinking 查询读取按运行环境、账号和配置隔离的数据库快照。Core 启动时在后台刷新各运行环境的默认账号目录，模型弹层右上角可手动刷新当前账号。没有对应快照的账号可在弹层发起首次探测。探测通过独立的 ProviderRuntime 管理连接进行，探测结果包含原生提供的模型及可选设置。

独立知识生成、Wiki 维护和工作流输出修复使用同一 ThreadLifecycle。当前独立调用要求能验证工具范围，由 Claude 原生客户端提供。工作流创作和节点执行在 Runtime 无法证明指定工具范围时，于获取原生账号租约之前拒绝。

## 工作范围与资源

Execution 冻结工作目录、附加目录、伙伴和项目指令、技能、插件与连接器授权。WorkspacePreparer 负责物化；账号服务负责原生根目录和凭据；ProviderRuntime 在子进程构造前组合这些资源。运行目录与原生配置目录互不替代。

指令和技能复用现有原生文件约定；软件能力通过受管 `ally` Skill 交付。附加目录、MCP 传输、原生 developer instructions、分叉、steering 和压缩分别依据原生能力声明，不能按 CLI 名称统一假设支持。资源准备或进程构造部分失败时，同一所有者负责回收已经取得的资源。

WorkBuddy 仅对本应用子进程设置 `CODEBUDDY_CODE_DISABLE_TERMINAL_TITLE=1`，聊天标题由 NeuxBot 管理。Prompt 的终态仍由原生回执决定。它的部分版本会对丢失会话返回空成功，因此冷 load 必须取得真实恢复证据，否则明确失败。该校验不改变会话替换的历史接力机制。

OpenCode 同目录 MCP 注册的冲突域在原生进程内。宿主对不同聊天使用独立进程与租约，不共享 MCP 凭据。Pi 的 MCP 通过受管扩展桥接；扩展注册就绪与各 MCP 服务连接成功是不同证据。

## 账号隔离

系统账号使用所选 CLI 的原生认证；受管账号按账号身份、认证世代和配置修订准备独立目录。实际配置与秘密环境由账号租约交付，不能被普通插件或运行时环境覆盖。模型运行期间不持有短期凭据锁；账号修改、重新登录和撤销通过独占边界协调活跃消费者。

Kimi 分别识别 `KIMI_SHARE_DIR` 和 `KIMI_CODE_HOME`；Gemini 的 `GEMINI_CLI_HOME` 包含 `.gemini`；Pi 使用 `PI_CODING_AGENT_DIR`；Grok 使用 `GROK_HOME`；OpenCode 分别固定 XDG 配置、数据、缓存及状态根。Qoder 与 Qoder CN 保持各自用户配置根。仅改变 OpenCode 配置目录不能被当作凭据隔离。

系统账号的本地身份摘要用于发现可观测的切换，不等于服务器认证成功。凭据快照排除已确认的 OAuth access/expiry 更新；存在可信账号标识时绑定该标识，否则保守绑定保存的授权凭据。CLI 自行持久化的默认模型不应使正常续聊误报账号变化。

Codex 令牌刷新继续经随机能力路径的回环端点协调。受管账号以加密数据库凭据为权威，系统文件账号以原生文件为权威。成功轮换后即使请求取消，也必须完成有界持久化；原生消费者退出后先停止刷新入口，再释放账号与目录。旧投射不能覆盖其他执行已更新或外部重新登录的凭据。

受管 API 账号选择请求协议、服务地址和可用模型，不做透明协议转换。Kimi 原有订阅账号保留隔离登录目录。OpenCode 与 Pi 的受管命名空间在边界转换，其他原生服务商的同名模型不能混入。模型、强度和 Fast 以原生回执为准，未知菜单不借用其他模型的选项。已列出模型可在支持的权限下使用原生默认配置；可选设置未知不等于模型不可用，显式设置仍独立校验。WorkBuddy 在随进程回收的独立配置根内探测每个模型的强度。

Qoder 适配器按原生模型 ID 合并 SDK 展示目录和 ACP 可选项。SDK 控制通道同时提供账号身份和目录，ACP 提供执行权限和设置选项。目录可见但当前无法通过 ACP 执行的模型在聊天弹层中禁用。缺少 SDK 查询能力的 CLI 沿用旧的账号通道和 ACP 可选项。

## 用量快照

规范原生终态 JSONL 是消费权威，SQLite 只保存可重建的 Token 查询投影。流式观察用于当前展示，不能因交付失败丢弃已有终态消费。调用身份负责去重；模型明细和调用总计分开，不能重复记账。日期、模型和伙伴分组及分页共享查询快照。

产品不提供价格表、Token 计价、费用字段或费用界面。原生返回的金额只可保留为原始技术证据。旧费用投影升级后重建，不把只有费用的模型行保留为 Token 消费。

输入、缓存读取、缓存写入和输出是互斥的加法分量；推理属于输出子集。每类计数区分未知与明确零，覆盖完整与字段完整分别判断。原生上下文大小不能作为消费量。整轮、已观察请求和不明范围的计数分别归属，不以数字相同判断重复请求，也不把未知数据补成零。

新迁移 CLI 的具体来源和版本限制见 [CLI 迁移核对](../discussions/agentruntime-rebuild/native-cli-completion-cn.md#token-产品合同)。真实模型、安装版本和平台验收与合成协议测试分开记录。

## 权限与交互

产品默认、自动审批和完全访问分别映射到真实原生策略。Gemini/OpenCode 不展示缺少原生合同的自动风险审批；Kimi、WorkBuddy 和 Qoder 以原生模式菜单为准。Pi 在受管工具扩展中执行相应审批。Grok 的权限请求仍受原生要求限制，未确认的模式不能显示为已生效。

只读工作区是额外的执行约束，不能用默认审批替代。当前只接受有明确隔离合同的 Codex 路径；其他 CLI 在接纳前拒绝只读请求。

结构化审批和用户问答按所属 Execution 的精确身份路由，取消与关闭释放等待。原生输入确认、执行终态、事件交付和持久化失败分别保存：Pi 的 prompt ACK 不代表执行完成，原生终态也可以先于 ACK 到达。无法确认原生终态时不制造失败或成功，不自动重放可能已执行的输入。

acp-go 继续在独立仓库维护；SDK 是其独立子模块。本地开发用 Go workspace 绑定两个仓库及 SDK，提交不修改已发布依赖为本机路径。生成协议和公开 API 通过对应生成器更新；合成测试不代替用户的 CLI、模型与界面验收。
