# 自动任务与 IM

## 自动任务

自动任务保存执行目标、定时或本机 API 触发条件，以及工作范围和执行配置。每次新机会接纳时保存有效配置，再创建相应 Chat、团队对话或 Workflow Run，并记录触发与结果关系；配置本身不提前创建空工作。独立伙伴任务在接纳时解析模型、强度和 Fast，pending 恢复沿用已存选择，合法空值不重新继承默认。团队任务保存当次完整成员选择，包含 Fast 的未指定、关闭和开启三态；未覆盖成员沿用团队已保存配置，任务专属覆盖在接纳时解析，pending 恢复使用原机会快照。

调度器负责到期、恢复、并发准入和应用生命周期。定时计划包括一次性与重复规则；任务忙碌、配置失效和设备休眠等结果按真实运行事实记录，不补造成功。

普通聊天、团队负责人及固定主会话工作记录通过当前主体授权读写自己的规则，保存回执打开同一管理详情。规则的来源工作与结果收件位置分别保存。伙伴和团队的报告默认投递到各自主会话，可改为规则专属话题。同一规则的专属话题按规则标识稳定复用。每次运行冻结指令、报告位置与报告策略。

新接纳的伙伴与团队报告由本次运行的伙伴或团队负责人调用 `conversations.messages.post` 提交一次。Core 先登记原请求和正文，再沿冻结的地址投递，同一请求重试以及重启补投使用原消息身份。只报变化的成功运行没有发言时仅保留运行记录。每次报告的成功运行没有发言时，详情显示报告未交付。实际执行失败由 Core 按真实终态交付失败提示。最终聊天答复留在工作记录，旧版本已接纳的机会继续使用原结算规则。运行槽忙时，报告规则把同一计划机会或独立手动请求排在已有工作之后。

定时规则创建和修改与本次确认的计划回执同事务保存。对话按原命令标识投影任务卡片，重复读取或重试共用该回执。卡片打开原规则标识对应的管理详情。后续编辑更新当前规则，已展示的历史卡片保留当次计划。

订阅监控使用定时任务。简单检查由伙伴按指令执行，包含跨次比较、固定参数或多步处理的检查可选工作流。聊天先取得可信的工作流版本，再保存定时规则，固定工作流版本、参数和主会话收件人。聊天签发的计划沿用已选权限，节点和子运行受同一上限约束。每次接纳记录工作流运行，已结算的回件引用该次运行。成功运行返回空结果或完整的 `[NEUX_NO_CHANGES]` 文本值时静默结算。工作流失败仍报告实际终态。工作流可用最终 Markdown 文本作为报告正文。

存量事件规则使用 Core 已登记的来源字段和匹配条件。GitHub 来源通过本机已有 GitHub CLI 账号读取所授权仓库最近至多三十个 PR，观察新建、评审已提交和当前提交检查通过。定期检查默认间隔五分钟。首次成功检查记录基线，后续先按来源身份去重，再应用标题、草稿和可选语义条件。检查游标与观察同事务提交。规则忙时保留待派工观察，后续继续接纳。检查失败保留已有基线与稳定错误。手动检查只接纳真实新匹配；测试可在没有新匹配时采用样本或示例，按独立测试运行记录并标注公开结果。受信推送入口在适配器验签和持久接纳后返回确认，当前 GitHub 来源使用轮询。

团队首发已写入负责人 Chat 且对话发布待补齐时，原机会查询和调度扫描调用团队发布恢复。现有调度扫描继续处理仍需对账的一次性机会。恢复使用原首发回执绑定机会和对话，沿用正常终态检查释放运行槽。

工作流参数逐项选择固定值、API 输入或适用默认值，Schema 与版本在接纳时校验。API Key 在集成设置中授权明确任务，支持轮换；幂等键同内容返回既有接纳，同键异内容拒绝。

输入文件通过所属任务的上传入口保存原件，调用方使用受管引用。最终结果与可下载文件从已确认运行读取，下载不接受任意本机路径。

## IM

连接模块处理平台登录、收发、重连和电源策略，授权绑定处理具体外部聊天可调用的伙伴／团队、目录、配置和工作流权限。消息进入既有执行内核，不建立平行的聊天执行系统。

连接成功不代表任意聊天有权执行。群聊、私聊、发送目标和文件交付分别根据实际授权检查，身份绑定由服务器维护。发送者身份保留在 IM 收件记录中用于权限与追溯，提交伙伴或团队执行时不将群成员 ID 拼入正文或上下文指令。

外部消息接收与结果投递使用持久身份和幂等关系。接纳、执行完成与平台送达分别记录。恢复先按原收件身份核对 Chat 日志或负责人队列，再决定是否需要准备新输入。负责人排队和 IM 收件接纳在同一事务提交。队列输入在进入 Chat 前明确失败时，团队结算与原已授权会话的失败 Outbox 回执在同一事务提交，保留原收件接纳。删除 Chat 日志前保存仍待挂接的原收件关联。平台拒绝和送达不明分别进入对应的投递状态。

对话关联只保存执行目标、项目或目录和已解析选项。最后一次成功保存的聊天配置用于后续接纳。单独授权和撤销只更新已保存的授权状态。工作在提交接纳事实时核对当前授权，附件和执行准备在提交边界外完成。活动对话指针独立更新。排队输入、切换已有对话和缺失对话替换保留原工作配置与提交身份。对话列表按原团队对话的所属团队生成跳转信息。平台交付继续保存原目的地、正文、文件与未知结果事实。

IM 工作消息与桌面伙伴聊天共用执行输入组装。收件接纳时冻结原 IM 会话，交付依据随执行日志、团队任务尝试和成员报告保存。终态回复及待处理的工具审批和问答只交付给发起对应工作的 IM 会话。引用消息发送 `/approve` 或 `/answer` 时，Core 在同一绑定内定位原会话并核对交互来源。没有引用时，命令使用当前会话。团队负责人按回复来源依次处理成员报告，桌面发起的回合和报告汇总保留在本地。

伙伴和团队成员可省略文件投递目标，Core 按本次工作的原 IM 会话查找并重新校验授权。文件回执关联原会话，平台引用回执时可定位原对话。其他目标仍需显式选择并通过授权校验。发送内容和附件遵守用户范围，平台回执只确认对应交付状态。

配置 IM 连接后，结果投递通过 Core 提交后的 Chat、团队和 IM 配置事件唤醒对应会话。首发关联提交时补读已经完成的执行。启动和订阅缺口恢复按会话关联分页，从原持久游标继续读取。过长的自动回复投递预览，完整正文保存在原 Chat。已终态且没有对应投递通知的成员报告结束等待，尚待团队决定交付方式的报告只重试所属会话。游标或待定报告发生变化时才更新投递检查点。成员或伙伴 Chat 的已提交变化通过 `im.conversations.changed` 刷新相关连接的对话列表。投递候选先按连接就绪状态筛选，再按每个聊天的原顺序领取。平台连接维护只读连接配置，历史对话计数由连接列表按需查询。

实现入口为 services/schedule、apis/automatic_tasks、services/im、internal/im、modules/automatic-task 与 modules/im。

### 企业微信传输与扫码

`internal/im.Wecom` 使用企业微信官方智能机器人 WebSocket 协议，和微信、飞书共用 `Platform`、持久收件、聊天授权、执行接纳与 Outbox。传输复用仓库已有的 Gorilla WebSocket，不增加 Node 进程或另一套聊天、授权与交付状态。协议来源见 [第三方说明](../../THIRD_PARTY_NOTICES.md)。

二维码注册沿用官方 `wecom-openclaw-cli` 的 HTTPS 生成与查询流程；扫码会话仍由 `services/im` 管理，公开 API 仅包含二维码和安全进度。Core 每三秒查询当前未完成会话，最多等待五分钟，确认、失败、关闭弹窗或 Core 退出时结束查询。Bot ID 与 Secret 只在 Core 读取，Secret 通过原凭据存储保存。已绑定的机器人身份不允许被扫码结果替换；更换机器人需要新建连接和聊天授权。

每份启用配置仅拥有一条长连接；订阅成功回执后才报告已连接，应用层心跳维护活性，普通断线交由既有 Service 恢复。平台 `disconnected_event` 表示被另一客户端替换，记录稳定错误并停止自动抢连；用户保存设置后恢复连接。取消、系统休眠和配置变更关闭原 socket 并释放读协程及未完成请求。

单聊使用发送者 userid，群聊使用 chatid，按机器人连接及平台消息 msgid 复用耐久去重。企微没有客户端消费确认接口，收到消息后先提交本地收件，再交给既有执行队列；不能据此承诺平台离线补发或断线前未提交消息的重放。平台不提供群名时展示会话身份，管理员可在原聊天授权中命名。

群文本和混排消息进入收件与命令路由前，移除正文开头以空白分隔的首个 `@唤起词`；例如 `@测试机器人 你好` 提交执行的正文为 `你好`。单聊、语音转写、正文中的后续提及及邮箱保留。仅含唤起词且没有附件的消息不触发执行。官方回调不提供机器人昵称或提及身份字段，当前按第一个空白边界处理，不能可靠识别含空格的完整昵称。

长任务和工作流结果通过官方主动发送命令交付，不依赖短时有效的回调 URL。发送请求关联唯一回执；尚未建立认证连接的待发结果保留在原 Outbox 等待恢复，已入队的明确回执不会被随后的断线覆盖。平台明确拒绝可标记失败，发送后超时或断线按原 Outbox 规则标记不确定，不自动重发。媒体限量下载，校验腾讯媒体域名并按 AES-256-CBC 解密；输出复用已有冻结文件，按官方分片协议上传。图片超过平台图片限制时作为文件发送，整体预算服从既有 IM 文件限制。

## 统一 API 集成

自动任务与知识库共享应用级 API Key、明确资源授权、一次性密钥签发及发布监听，调用入口为 `/api/v1/automatic-tasks/{id}/runs`。任务页面只读取服务状态并提供任务身份、调用地址和示例；监听地址、端口、服务启停及凭据授权统一在“设置 → 集成 → API”管理。对外接口不能替换伙伴、账号、工作流定义或权限配置。

新入口继续调用既有接纳、限流、Chat／团队／Workflow Run 与结果管线。幂等身份按 Key 与任务隔离；运行和受管文件绑定原 Key，轮换不改变结果归属，同任务的其他 Key 不可借用输入或读取成果。

若任务配置了知识整理，原运行冻结调用 Key 代次和任务授权，受信 AutomaticRunID 沿执行日志、团队和工作流链路传递，不由模型参数提供。知识任务按原任务范围执行，无须另授直接知识 API 权限；撤销 Key、停用任务或缩减其知识范围阻止后续知识提交。定时任务不依赖 API Key。团队对话保留首发的 `AutomaticRunID` 用于历史追溯；后续派发读取原自动运行的整体封闭事实。原运行尚未封闭时，内部成员任务与负责人结果汇总继续携带自动来源；新用户工作提交前冻结已结束的原运行，封闭后的负责人续聊、成员任务及结果汇总使用普通工作身份和知识能力，不继承原调用身份。

删除自动任务先封闭新触发，完成运行与活跃工作检查后，在既有授权写入屏障内执行最终聚合删除。Chat 索引、团队对话和任务删除共用传递可重入 Context 的同一事务，统一采用授权屏障先于数据库写锁的顺序；失败时回滚聚合事实并恢复任务删除标记。
