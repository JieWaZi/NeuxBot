# 自动任务与 IM

## 自动任务

自动任务保存执行目标、定时或本机 API 触发条件、工作范围及执行配置。实际接纳后创建相应 Chat、团队对话或 Workflow Run，并记录触发与结果关系；配置本身不提前创建空工作。

调度器负责到期、恢复、并发准入和应用生命周期。定时计划包括一次性与重复规则；任务忙碌、配置失效和设备休眠等结果按真实运行事实记录，不补造成功。

工作流参数逐项选择固定值、API 输入或适用默认值，Schema 与版本在接纳时校验。API Key 在集成设置中授权明确任务，支持轮换；幂等键同内容返回既有接纳，同键异内容拒绝。

输入文件通过所属任务的上传入口保存原件，调用方使用受管引用。最终结果与可下载文件从已确认运行读取，下载不接受任意本机路径。

## IM

连接模块处理平台登录、收发、重连和电源策略，授权绑定处理具体外部聊天可调用的伙伴／团队、目录、配置和工作流权限。消息进入既有执行内核，不建立平行的聊天执行系统。

连接成功不代表任意聊天有权执行。群聊、私聊、发送目标和文件交付分别根据实际授权检查，身份绑定由服务器维护。发送者身份保留在 IM 收件记录中用于权限与追溯，提交伙伴或团队执行时不将群成员 ID 拼入正文或上下文指令。

外部消息接收与结果投递使用持久身份和幂等关系。接纳、执行完成与平台送达分别记录；平台错误不能伪装成已送达，丢失回执不能无条件重发。

allycli im 能力只面向当前获准连接与目标，发送内容和附件遵守用户范围。平台审批和原生工具授权保持独立，平台回执不代表应用成果已读。

实现入口为 services/schedule、apis/automatic_tasks、services/im、internal/im、modules/automatic-task 与 modules/im。

### 企业微信传输与扫码

`internal/im.Wecom` 使用企业微信官方智能机器人 WebSocket 协议，和微信、飞书共用 `Platform`、持久收件、聊天授权、执行接纳与 Outbox。传输复用仓库已有的 Gorilla WebSocket，不增加 Node 进程或另一套聊天、授权与交付状态。协议来源见 [第三方说明](../../THIRD_PARTY_NOTICES.md)。

二维码注册沿用官方 `wecom-openclaw-cli` 的 HTTPS 生成与查询流程；扫码会话仍由 `services/im` 管理，公开 API 仅包含二维码和安全进度。Core 每三秒查询当前未完成会话，最多等待五分钟，确认、失败、关闭弹窗或 Core 退出时结束查询。Bot ID 与 Secret 只在 Core 读取，Secret 通过原凭据存储保存。已绑定的机器人身份不允许被扫码结果替换；更换机器人需要新建连接和聊天授权。

每份启用配置仅拥有一条长连接；订阅成功回执后才报告已连接，应用层心跳维护活性，普通断线交由既有 Service 恢复。平台 `disconnected_event` 表示被另一客户端替换，记录稳定错误并停止自动抢连；用户保存设置后恢复连接。取消、系统休眠和配置变更关闭原 socket 并释放读协程及未完成请求。

单聊使用发送者 userid，群聊使用 chatid，按机器人连接及平台消息 msgid 复用耐久去重。企微没有客户端消费确认接口，收到消息后先提交本地收件，再交给既有执行队列；不能据此承诺平台离线补发或断线前未提交消息的重放。平台不提供群名时展示会话身份，管理员可在原聊天授权中命名。

群文本和混排消息进入收件与命令路由前，移除正文开头以空白分隔的首个 `@唤起词`；例如 `@测试机器人 你好` 提交执行的正文为 `你好`。单聊、语音转写、正文中的后续提及及邮箱保留。仅含唤起词且没有附件的消息不触发执行。官方回调不提供机器人昵称或提及身份字段，当前按第一个空白边界处理，不能可靠识别含空格的完整昵称。

长任务和工作流结果通过官方主动发送命令交付，不依赖短时有效的回调 URL。发送请求关联唯一回执；尚未建立认证连接的待发结果保留在原 Outbox 等待恢复，已入队的明确回执不会被随后的断线覆盖。平台明确拒绝可标记失败，发送后超时或断线按原 Outbox 规则标记不确定，不自动重发。媒体限量下载，校验腾讯媒体域名并按 AES-256-CBC 解密；输出复用已有冻结文件，按官方分片协议上传。图片超过平台图片限制时作为文件发送，整体预算服从既有 IM 文件限制。

## 统一 API 集成

自动任务与知识库共享应用级 API Key、明确资源授权、一次性密钥签发及发布监听，调用入口为 `/api/v1/automatic-tasks/{id}/runs`。任务页面只提供任务身份和示例；凭据在“发布集成 → API 集成”创建与授权。对外接口不能替换伙伴、账号、工作流定义或权限配置。

新入口继续调用既有接纳、限流、Chat／团队／Workflow Run 与结果管线。幂等身份按 Key 与任务隔离；运行和受管文件绑定原 Key，轮换不改变结果归属，同任务的其他 Key 不可借用输入或读取成果。

若任务配置了知识整理，原运行冻结调用 Key 代次和任务授权，受信 AutomaticRunID 沿执行日志、团队和工作流链路传递，不由模型参数提供。知识任务按原任务范围执行，无须另授直接知识 API 权限；撤销 Key、停用任务或缩减其知识范围阻止后续知识提交。定时任务不依赖 API Key。团队对话保留首发的 `AutomaticRunID` 用于历史追溯；后续派发读取原自动运行的整体封闭事实。原运行尚未封闭时，内部成员任务与负责人结果汇总继续携带自动来源；新用户工作提交前冻结已结束的原运行，封闭后的负责人续聊、成员任务及结果汇总使用普通工作身份和知识能力，不继承原调用身份。

删除自动任务先封闭新触发，完成运行与活跃工作检查后，在既有授权写入屏障内执行最终聚合删除。Chat 索引、团队对话和任务删除共用传递可重入 Context 的同一事务，统一采用授权屏障先于数据库写锁的顺序；失败时回滚聚合事实并恢复任务删除标记。
