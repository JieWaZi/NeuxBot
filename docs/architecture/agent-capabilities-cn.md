# 系统技能与软件能力

## 职责

系统 bot 技能教授任务方法，内部 MCP 与 botcli 共用能力发现、参数和调用契约，Core 负责身份、授权、领域规则与真实回执。技能与命令名称是当前技术契约，产品名称为 NeuxBot。

`server/internal/agent/capability` 统一维护命令目录、Schema、解析、精确执行授权、有界观察及回执协议，`agent/cli/cli.go` 提供 botcli 的参数解析与客户端。主会话、记忆、IM、团队、工作流与知识业务状态仍由各自领域拥有。所有领域的当前命令、完成语义和调用示例统一见 [botcli README](../../server/cmd/botcli/README.md)。

## 授权与请求

Core 在受管聊天首次使用工具时发布私有连接文件。同一 Chat、Runtime、账号及 MCP 工具目录在当前 Core 生命周期内复用凭据，普通伙伴聊天、IM、团队和工作流共用该入口。CLI 从宿主环境取得文件路径。获得工作流或主会话发言授权且运行时支持 stdio 时，由宿主连接 `botcli mcp serve`，桥接启动时一次读取凭据与工具目录。连接在消息接纳后激活，后续由原执行占位确认当前回合。团队工具校验本轮团队租约和成员角色。回合结束时停止接入并清理等待中的调用，Core 关闭时删除连接文件。桥接只做传输，领域服务提供业务授权与回执。

CLI 执行将 Core 当前发布的 `botcli` 目录放在原生进程 PATH 首位。Shell 自行覆盖或过滤 PATH 时，宿主指令提供同一程序的确切路径。系统技能在原生发现目录交付文档，执行使用 Core 发布的程序。各平台的终端安装与用法见 [botcli README](../../server/cmd/botcli/README.md#开始使用)。

Codex 可从 Shell 环境过滤连接路径。Core 在回合接纳时为实际原生线程发布指向同一私有连接文件的入口。随应用交付的 CLI 从 Codex 提供的线程标识定位该入口。同一原生线程续聊复用入口，切换原生线程时撤回旧入口，Core 关闭时清理剩余入口。

原生 Session 初始化可能早于执行的持久接纳。MCP 桥准备期间只可读取工具目录，业务查询、写入和回执在接纳后启用。闲置连接不可读取目录或调用工具。

CLI 和内部 MCP 提交公开发言或外部操作时，从本机 Core 取得本次请求所属执行的标识。Core 只在该执行仍持有接纳范围时处理请求，文件回传沿用该执行的 IM 来源。连接文件和凭据按原生连接复用。

主会话入口为本次工作 Chat 的活动执行签发 `conversations.messages.list` 和 `conversations.messages.post`。前者按需读取同一公开会话中的消息，使用返回的游标可向前翻阅。工作 Chat 的目录、执行和私有历史保留在来源记录中。执行绑定冻结工作 Chat、执行和原公开交办，主会话服务据此校验会话归属并写入完整正文。每次新调用产生一条可独立查看的消息。原生 CLI final 随工作 Chat 存档。用户直接提问时，宿主按[主会话交付规则](chat-and-execution-cn.md#主会话和来源工作记录)处理遗漏的最终答复。

写命令及收据查询的 request-id 由同一 Core 约束校验，MCP 从该来源发布输入 Schema。写命令使用稳定 request-id，保存内容摘要和领域回执。同键同内容重放原回执，同键异内容冲突；响应不确定时沿原请求查询收据，避免生成新请求重复副作用。能力桥负责授权、派发和未知结果观察；实际写入及 Commit 由原领域在同一事务内核对授权、版本和回执，不在 Registry 建立第二份业务状态。

命令身份摘要、协议路径、botcli 名称、环境变量及私有连接文件的 Unix/Windows 权限边界共同构成既有调用合同。返回区分同步完成、耐久接纳与候选提交。查询或有限 wait 的超时不改变业务状态；真正完成以所属资源终态为准。

外部 Agent 通过发布服务的 HTTP MCP 调用同源知识合同；内部 CLI/stdio MCP 使用 Execution 身份，外部 HTTP MCP 使用现有 API Key。两者共享知识操作、版本检查和回执逻辑，入口分别注入授权上下文。外部 HTTP MCP 不发布其他领域的内部命令；接入、能力映射和后台撤权边界见 [知识库](knowledge-cn.md#api-集成与指定库接入)。

## 知识分发

skills/bot 是产品技能源，与个人开发技能安装环境分别维护。Core 按内容摘要准备系统目录，每次受管执行获得当前构建携带的资源。普通用户技能不覆盖系统保留身份。

修改资源运行 pnpm skills:generate 与 pnpm skills:check。直接 Go 命令使用已提交 bundle；重新构建并启动 Core 后，新执行才使用新打包内容。

指南按场景解释决策与验证，不静态重复所有命令 Schema。工作流 SDK、参数及结果 Schema 优先通过实时发现获取。

知识查询参考固定 WeKnora 的渐进式 RAG 和公共来源规则，统一维护在系统技能知识参考中。普通伙伴按问题语境选择简单事实、机制实现或跨资料研究的深度；搜索无效时调整术语，摘要不足时读取正文，精确数字与代码回读持久原件，回答前检查请求覆盖与来源依据。具体知识读取与维护边界见 [知识库](knowledge-cn.md)。

知识维护继续使用同一系统技能与 CLI，`knowledge.maintenance` 指南适配固定 WeKnora 的修复流程。页面维护会话固定原库与原页，实际存储、历史及回执由知识核心拥有；授权与远端边界见 [知识库](knowledge-cn.md)。
