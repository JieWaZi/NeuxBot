# 桌面生命周期与信任边界

## 进程

Electron 主进程管理唯一窗口、Core、托盘、原生网页视图、系统文件交互及统一事件连接。React Renderer 负责交互，Go Core 负责业务规则、文件/Git 操作、终端和持久执行。

首帧无需等待 Core。主进程并行启动 Core 和窗口加载，认证健康检查完成后提供回环地址与令牌。外部指定 Core 不属于桌面进程，应用退出不终止它。

关闭窗口隐藏主窗口，Core、托盘与工作继续运行；系统激活或再次启动恢复已有窗口。真正退出按所有权释放订阅、原生资源与 Core，超时后有界回收；系统会话结束及父进程监控覆盖异常退出。

## 欢迎与引导

首帧使用现有伙伴形象与 NeuxBot 字标，等待实际品牌入场完成再交接工作区。已有安装证据时后台核验智能体；首次无安装证据时展示探测与配置，明确选择实际版本和可用模型后保存默认设置。

界面提供安装命令复制和官方地址，不自动执行安装。模型探测与真正计费调用分别处理。主题、减少动态、图形失败和重试均保留稳定界面及可读错误。

## Bridge 与网页

preload 仅暴露逐方法白名单，不暴露原始 IPC、Node 或 Electron 对象。每个调用校验主框架来源、参数 Schema 和真实文件范围。Renderer 使用沙箱、隔离上下文并关闭 Node 集成。

内嵌 WebContentsView 使用独立会话，不安装桌面 preload。远程导航限制于 HTTP／HTTPS，HTML 文件预览校验原 Chat 或批准目录。原生视图随内容身份管理，与 Renderer 浮层通过共享 presence 协调。

终端由 Core 管理的 stdio 子进程承载 PTY 和 xterm 屏幕；子进程不监听网络。终端绑定认证主体、已接纳 Chat 的冻结目录和内容身份；关闭内容立即回收，视图断线保留 60 秒恢复窗口，注销与 Core 退出回收终端。Native 用 Electron 的 Node 模式运行同一 worker；Web 使用启动器的 Node。上传暂存只接受文件名和字节，不能指定任意写入目录。

## 软件更新

安装更新仅支持打包后的 macOS arm64／x64 与 Windows x64 桌面程序。Linux、其他原生架构及开发版本不发起安装更新请求；Web 关于页展示部署端更新说明，不访问 Electron 或提供桌面安装操作。Web 升级通过替换部署包、重启 Core 并刷新浏览器完成。

下载安装包并校验完整性后，用户先保存工作并真正退出应用，再手动覆盖安装并重新启动。关闭窗口只隐藏主窗口，不能替代退出。打开安装包仅交给系统安装器，不自动退出、安装或重启应用；macOS 使用 DMG 覆盖应用，Windows 使用 EXE 安装器。

Electron 主进程拥有软件版本、公开发行探测、安装包下载和校验状态；设置中的“关于软件”和 Shell 下载入口共享带单调 revision 的同一快照。Renderer 通过固定白名单方法查询、检查、下载和打开已校验安装包，不能指定仓库、地址、文件路径或执行参数。事件与快照按 revision 合并，重新订阅时补读快照，窗口重载不取消主进程下载。

更新源固定为 JieWaZi/NeuxBot 的 GitHub Release，只接受正式版本并按数字比较 X.Y.Z。安装包匹配当前系统与架构，下载只允许 GitHub 的 HTTPS 发行地址与资产重定向；SHA256 优先来自发行资产摘要，缺失时读取同一发行的 SHA256SUMS。下载写入独立缓存的临时文件，通过大小及摘要校验后才成为可打开安装包，打开前再次校验；失败清理临时文件。外部网络地址和临时令牌不进入日志。

现有发行使用 DMG/NSIS 整包安装，更新入口只打开系统安装包，不静默退出、执行替换脚本或改写用户数据。安装前需完成工作并从菜单或托盘真正退出，替换应用后重新启动；下载完成不表示已经安装。当前 macOS 为临时签名发行，未接入[要求正式代码签名的自动替换机制](https://www.electron.build/v26/docs/features/auto-update/)。

更新探测定时器及网络请求归主进程所有，频率和退出规则见 [通知与工作看板](notifications-and-work-board-cn.md)。应用退出取消请求并释放定时器与订阅；开发模式及未支持的平台不发起更新请求。

下载完成不阻止后续检查。候选版本、文件名、大小和明确摘要不变时保留可安装状态；新发行、发行撤回或当前版本已不低于发行时废止旧安装入口。重新检查失败保留此前已校验的安装包并展示错误，允许重试。非成功 HTTP 响应及时释放响应体，临时文件创建失败也释放已经取得的下载流与读取器。

## 事件

主进程拥有一条 Core WS，Bridge 只接受固定主题、资源与领域游标。令牌不进入 URL 或诊断正文。连接缺口、队列超限和重启要求原快照恢复，普通业务操作保持 HTTP。

## 发布集成监听

Core 装配知识、任务与统一授权后显式启动集成监听，退出或初始化回滚时由同一所有者关闭。唯一设置文件为 `integration-api.json`，默认只监听回环；API 集成页内的 MCP 设置与任务页面共用服务器状态。HTTP MCP 挂载在同一监听的 `/mcp`，与 REST 共用 Key 和 Core 生命周期，不另开端口或进程。API 服务总开关与 MCP 子开关默认关闭，持久化到同一设置文件。仅开启 API 服务才绑定监听；MCP 还要求子开关开启。关闭 API 服务释放监听并停止新请求接入，保留 MCP 子开关偏好；只关闭 MCP 不影响 REST。切换地址先验证绑定，失败保留原有效监听；停用对外 API 不停止定时扫描或已接纳的执行。知识 API 不再另外加载环境变量中的旧 Token 配置，也不创建兼容监听。

## 本机 Web

Web 静态资源由同一 Core 回环监听器提供，开发时 Vite 代理 `/api` 到 Core。启动终端只打印网页地址，打开页面即在精确 Host/Origin 校验后自动建立 HttpOnly、SameSite=Strict 会话 Cookie，无需配对码，也不提供连接管理按钮。页面刷新复用有效会话，写请求仍需同源和 CSRF 令牌；会话到期或 Core 重启后重新加载页面并自动建立新会话。桌面 Bearer 令牌不会返回浏览器。

同一数据目录只允许一个 Core 进程持有锁；Web 与 Native 若要独立同时运行，需显式使用不同数据目录。首期不提供远程监听、多用户登录或浏览器内模拟原生窗口控制。Web 外部网页使用系统浏览器标签，本地 HTML 默认隔离静态预览。
