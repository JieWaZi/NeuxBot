# 桌面生命周期与信任边界

## 进程

Electron 主进程管理唯一窗口、Core、托盘、原生网页视图、系统文件交互及统一事件连接。React Renderer 负责交互，Go Core 负责业务规则、文件/Git 操作、终端和持久执行。

首帧无需等待 Core。主进程并行启动 Core 和窗口加载，认证健康检查完成后提供回环地址与令牌。外部指定 Core 不属于桌面进程，应用退出不终止它。

关闭窗口隐藏主窗口，Core、托盘与工作继续运行；系统激活或再次启动恢复已有窗口。真正退出按所有权释放订阅、原生资源与 Core，超时后有界回收；系统会话结束及父进程监控覆盖异常退出。

## 欢迎与引导

首帧使用现有伙伴形象与 NeuxBot 字标，等待实际品牌入场完成再交接工作区。已有安装证据时后台核验智能体；首次无安装证据时展示探测与配置，明确选择实际版本和可用模型后保存默认设置。

欢迎引导保留官方安装参考入口。设置中的安装和更新需用户明确触发，由 Core 通过官方制品下载、校验和受管发布完成；请求断开和页面关闭不取消后台任务，用户取消与 Core 关闭负责回收。模型探测与真正计费调用分别处理。主题、减少动态、图形失败和重试均保留稳定界面及可读错误。

## Bridge 与网页

preload 仅暴露逐方法白名单，不暴露原始 IPC、Node 或 Electron 对象。每个调用校验主框架来源、参数 Schema 和真实文件范围。Renderer 使用沙箱、隔离上下文并关闭 Node 集成。

通用设置的主题、语言和界面大小保存在当前宿主的本机偏好中。桌面透明开关由主进程持久化到 `window-appearance.json`，在构造首个窗口前读取；Renderer 先读回该偏好，再同步当前外观，不能用初始关闭状态覆盖已保存的开启状态。macOS 在 BrowserWindow 构造参数中传入 `under-window` vibrancy，避免仅在页面加载后追加材质导致合成器保留旧画面；材质只随开关变化重设。Windows 11 22H2 及以上使用 acrylic，其他平台禁用透明窗口。

外观 Bridge 只接受跟随系统／浅暗主题、中英文、布尔透明开关和 80%–150% 缩放，沿用主框架来源与严格 Schema 校验，不授予文件、网络或执行权限。主进程应用原生缩放、菜单语言及材质。透明开启时原生主题跟随应用选择，关闭后恢复跟随系统；系统主题更新监听随窗口关闭释放。原生网页视图的窗口坐标按 Renderer 缩放转换。

窗口框架、正文、卡片和控件通过工作台范围内的语义表面色调透出原生模糊，文字和图标不降低透明度。根主题保留实色快照；菜单、弹窗、提示和遮挡连接线的工作流节点恢复实色，窗口框架避免重复叠加底色。网页、iframe 和原生视图保留自身内容表面。Web 使用页面缩放并禁用透明窗口。来源及适配见[第三方声明](../../THIRD_PARTY_NOTICES.md)。

内嵌 WebContentsView 使用独立会话，不安装桌面 preload。远程导航限制于 HTTP／HTTPS，HTML 文件预览校验原 Chat 或批准目录。原生视图随内容身份管理。阻塞型浮层打开时暂时隐藏原生视图。应用通知与原生预览重叠时，预览使用未被覆盖的一侧中面积最大的矩形，通知撤下时恢复原尺寸和会话。

终端由 Core 管理的 stdio 子进程承载 PTY 和 xterm 屏幕；子进程不监听网络。终端绑定认证主体、已接纳 Chat 的冻结目录和内容身份；关闭内容立即回收，视图断线保留 60 秒恢复窗口，注销与 Core 退出回收终端。Native 用 Electron 的 Node 模式运行同一 worker；Web 使用启动器的 Node。上传暂存只接受文件名和字节，不能指定任意写入目录。

## 事件

主进程拥有一条 Core WS，Bridge 只接受固定主题、资源与领域游标。令牌不进入 URL 或诊断正文。连接缺口、队列超限和重启要求原快照恢复，普通业务操作保持 HTTP。

## 发布集成监听

Core 装配知识、任务与统一授权后显式启动集成监听，退出或初始化回滚时由同一所有者关闭。唯一设置文件为 `integration-api.json`，默认只监听回环；集成中的 API／MCP 设置与任务页面共用服务器状态。HTTP MCP 挂载在同一监听的 `/mcp`，与 REST 共用 Key 和 Core 生命周期，不另开端口或进程。API 服务总开关与 MCP 子开关默认关闭，持久化到同一设置文件。仅开启 API 服务才绑定监听；MCP 还要求子开关开启。关闭 API 服务释放监听并停止新请求接入，保留 MCP 子开关偏好；只关闭 MCP 不影响 REST。切换地址先验证绑定，失败保留原有效监听；停用对外 API 不停止定时扫描或已接纳的执行。知识 API 不再另外加载环境变量中的旧 Token 配置，也不创建兼容监听。

## 原生交付资源

Vite 配置显式区分 Native 与 Web。原生前端文本资源经现有 Brotli 链无损编码，协议层解码后按原始 MIME 提供；启动预算仍读取原始构建依赖图，不能以交付压缩隐藏实际初始化成本。原生 KaTeX 仅交付 WOFF2，Web 保留原字体回退；未接入的 PDF 表单脚本沙箱不随原生包交付，其余解码、回退、字符映射、标准字体及许可保留。

安装包、展开应用和前端资源的测量分别记录；当前组成、必要性与优化证据见[交付体积分析](../discussions/desktop-size-performance-cn.md)。安装包只包含当前平台需要的原生资源，实际加载的 PTY／侧车与 Electron 动态库不能仅按文件名重复直接删除。

## 本机 Web

Web 静态资源由同一 Core 回环监听器提供，开发时 Vite 代理 `/api` 到 Core。启动终端只打印网页地址，打开页面即在精确 Host/Origin 校验后自动建立 HttpOnly、SameSite=Strict 会话 Cookie，无需配对码，也不提供连接管理按钮。页面刷新复用有效会话，写请求仍需同源和 CSRF 令牌；会话到期或 Core 重启后重新加载页面并自动建立新会话。桌面 Bearer 令牌不会返回浏览器。

同一数据目录只允许一个 Core 进程持有锁；Web 与 Native 若要独立同时运行，需显式使用不同数据目录。首期不提供远程监听、多用户登录或浏览器内模拟原生窗口控制。Web 外部网页使用系统浏览器标签，本地 HTML 默认隔离静态预览。
