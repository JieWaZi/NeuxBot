# 工作流

## 源码与版本

Workflow Definition 保存稳定身份、当前版本、创作关系和批准范围；Revision 不可变保存完整源码、Manifest、编译结果及参数和产出契约。画布与表单是源码的投影，编辑后重新编译并以 CAS 保存完整新版本。完整源码与精确文本补丁共用保存入口；补丁必须匹配基准摘要且搜索片段唯一。每次新的显式保存请求产生新版本，相同请求重放原回执。

恢复选定版本时读取其源码，经当前编译器验证后形成新 Revision。已有运行固定原版本与输入，不被定义后续编辑改写。

## 创作与运行

创作复用普通 Chat、Composer、Runtime、受管目录和系统技能。宿主按每次 Execution 注入当前工作流身份和创作模式；普通短句修改仍处理绑定工作流，不要求模型猜测 ID。具有工作流能力绑定且支持 stdio 的 Runtime 挂载内部 MCP，提示只引导该传输，不要求同时探测 CLI；不支持 stdio 时保留同一会话稳定路径、每轮轮转授权的 CLI 上下文，工具调用失败不能自行切换传输。普通伙伴聊天暂不提供工作流选择或调用入口；工作流创作与 worker 的能力仍由各自入口精确签发。团队聊天不会仅因加载系统技能而获得工作流能力。会话与画布组合在主容器，文件、浏览器和终端继续使用独立工作台。首次输入前保持本地草稿，发送后保留同一聊天实例。

系统技能的 [创作指南](../../skills/ally/references/workflow-authoring.md) 负责目标分解、数据依赖、用户决定、验证与恢复方法，按需读取编排模式及可编译示例。prepare 返回当前源码、资源和生成 SDK；参数契约、授权、版本校验及业务成功条件由宿主执行，不依赖模型自觉遵守。伙伴的结构化结果使用当前 attempt 的结果工具提交；成功接纳的候选内容不可覆盖，候选接纳与节点执行成功分别确认。

画布默认从空白区域拖出矩形框选阶段；按住空格或切换平移模式可移动视野。节点及浮层表单保持各自交互。背景和左下缩放控件与知识图谱共用，提供缩小、当前比例、放大和适应画布。

创作消息以执行接纳回执确定发送结果；回执直接交付已取得的 Chat 与 Execution 快照，不为组装响应再读取执行，也不丢弃快照后只保留 Chat ID。后续详情由原查询加载，读取失败不会改写已接纳结果或恢复为待重发输入。创作会话接纳、定义、批注、版本和运行历史变化分别由提交后事件更新各自查询，接纳与聊天终态不无条件重读版本和运行目录。

创作权限绑定当前执行，不设置独立有效期；等待用户回答期间仍有效。每次能力调用及保存事务都校验当前身份和执行终态，执行结束或被新执行接替后停止旧调用。失效响应区分执行结束与权限被接替，并引导通过创作对话的新消息继续；版本冲突仍通过重新读取源码处理。

运行接纳校验 Revision、参数、权限、资源和冻结目录。手动运行优先保留当前会话选择的执行配置；没有创作会话且伙伴步骤缺少 Runtime 绑定时，表单直接复用共享执行配置解析，不依赖展开聊天。纯本地流程不要求模型配置。手动、自动任务、使用者 CLI 与子流程复用接纳规则。Run、节点实例、Attempt 和 Effect 分别标识本次运行、分支／轮次中的节点、真实尝试及外部效果。

Go Runner 依据持久检查点推进并行、管道、循环、人工请求与子运行；状态提交与租约使用共享协调。外部调用在事务外执行，回执按效果身份与尝试代际核验。

画布采用编译器生成的 V2 Manifest，公开节点判别联合、控制结构和数据依赖，运行状态从持久实例叠加。创作时的结构化澄清问题与普通伙伴对话一样，显示在聊天输入框区域，复用原请求身份和答案处理器；运行中的 askUser 决策显示在画布节点内。运行选择题冻结候选、摘要及问题版本；回答必须带 CAS，过期回答不能作用于新问题。

每个阶段纵向排列多个步骤，卡片以中性背景、紧凑排版和最多两行的说明组织信息。处理类型通过业务文字与 Lucide 图标区分，伙伴使用实际头像与姓名；颜色集中用于选中、运行中和状态标签，已完成步骤不持续播放动画。详情使用紧凑画布浮层，呈现业务标题、行为说明、处理类型和用户问题，不展示内部身份、摘要或调用代码。拖框选择的阶段成为输入框内部的引用标签，删除标签同步取消画布选中状态。引用固定原 Revision 和目标身份，由服务端验证归属并补充权威标题，后续修改仍以当前源码的 CAS 保存。
同一 Tick 复用已经确认的聚合用于派发，不紧接着重新加载全部子表；提交后以窄运行状态核对取消等协调结果。worker 只观察其固定首次执行，状态和最终正文按准确执行位置读取，不从最新聊天页倒找。列表摘要只取得实际展示列，不解码后丢弃整份 Manifest。

页面的定义、运行、实例和日志查询沿统一事件调度各有所有者。日志事件只更新日志窗口，不重新读取整份 Run 或所有实例；实例由自身查询消费相关状态变化。隐藏 Scene 的变化只标记所属查询陈旧，不主动读取；恢复可见时权威对账，后台运行不随页面关闭而停止。

## 授权与失败

业务问答、Runtime 工具审批与确定性操作许可分别校验。未经许可不扩大范围。失败和缺失可靠外部结果停止后续步骤，保留原调用与错误证据，不盲目重发。

用户通过当前运行入口查看结果和授权，通过优化创作读取运行证据调整源码。优化携带可见、可移除的原 Run、Revision 和可选实例引用，服务端校验归属。失败及已取消的执行记录提供直接重试入口，与运行详情共用重试计划。计划使用原运行的业务标题，按原实例创建顺序展示，固定原 Revision 创建新 Run；仅复用配置、输入与依赖一致的安全结果，确认题、文件产物与结果未知的外部效果不能盲目复用或重做。用户停止与实际失败始终有效，后台恢复根据持久状态决定可安全推进的步骤。

## 执行返回值与文件

worker 无 Schema 时返回文本，声明 Schema 时直接返回符合 Schema 的值。节点间传递真实业务返回值，普通详情阅读业务正文和答案。独立产出页、查看产出卡片、页面声明和专用渲染接口均不提供。action 返回 data、durationMs 和可选 process，业务成功由 successCondition 检查 data，不能只凭进程退出码判定。Schema 中 type:string、format:file 声明真实文件；普通字符串不自动解释为文件。产出依据已确认 Effect.Result，候选提交不等于节点成功。

结构不合法的 worker 结果通过共享 `AgentManager.GenerateText` 独立文本调用做至多两次格式修正，次数持久化。输入只包含 Schema 和已有候选，不注入工作流业务能力、不重新派发 worker、不补造缺失业务数据；原生 CLI 的工具配置沿用独立文本调用边界，修正结果仍须通过 Schema 校验。

输入表单由 inputSchema 自动生成。运行返回值与效果身份固定，不被重试覆盖。

文件在所属 Run 的冻结范围中创建。上传通过 Core 保存原件，接纳时准备独立输入目录；本机 API 调用不能以任意本机路径代替上传。授权的自动任务文件交付仍检查真实文件及范围。

已结束运行可以确认后从可见历史移除。默认保留上限 30 条，超限时移除最早一半的已结束记录；活跃运行可以暂时超限。保留文件及幂等、固定版本和交付所需事实。

语言与生成入口见 [工作流语言](workflow-language-cn.md)。
