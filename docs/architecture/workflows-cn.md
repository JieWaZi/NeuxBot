# 工作流

## 源码与版本

源码、保存请求与画布统一使用 `sdk: "bot.workflow"` 标识当前契约；画布不携带格式版本字段。旧 SDK 标识和旧格式字段不提供兼容或迁移。

Workflow Definition 保存稳定身份、当前版本、创作关系和批准范围；Revision 不可变保存完整源码、Manifest、编译结果及参数和产出契约。画布与表单是源码的投影，编辑后重新编译并以 CAS 保存完整新版本。节点表单只提交编辑过的字段。伙伴步骤继承伙伴和原生智能体的连接器与工具配置，节点策略使用 `inherit`。完整源码与精确文本补丁共用保存入口；补丁必须匹配基准摘要且搜索片段唯一。每次新的显式保存请求产生新版本，相同请求重放原回执。

目录分类属于 Definition 的独立元数据，复用资源分类表与多选标签字段。分类词库、标签与定义变更事件在同一事务保存，清空标签不删除词库，不生成源码版本或修改已接纳运行。目录在服务端先按分类和搜索过滤，再按原时间与身份游标分页；未分类使用空数组，列表与其他资源共享分类图标和颜色。

恢复选定版本时读取其源码，经当前编译器验证后形成新 Revision。已有运行固定原版本与输入，不被定义后续编辑改写。

## 创作与运行

创作复用普通 Chat、Composer、Runtime、受管目录和系统技能。创作页提供当前工作流与工作区，首条裸业务目标表示创建或修改可复用工作流。普通伙伴聊天按用户输入决定读取、修改或运行。用户可以在普通对话用 `#` 指定默认目标，也可以按工作流名称或本聊天的运行记录定位后直接修复。原生会话指令交付创作角色和启动约定，`workflow.authoring.prepare` 按需提供指南、源码和 SDK。画布和运行引用随本轮选择冻结，仅在有选择时发送。Chat 权威用户正文保持原样。

本地伙伴聊天与创作聊天通过共用执行入口获得同一组工作流读取、保存和运行工具，使用同一个 Core 生命周期内的 botcli token。受管连接 ID 定位各自对话和当前执行。支持 stdio 的 Runtime 挂载内部 MCP，其余使用宿主交付的常驻 CLI 连接。团队聊天、自动任务和节点结果继续按各自业务范围装配。会话与画布组合在主容器，文件和浏览器使用独立工作台。终端入口归伙伴和团队对话。首次输入前保持本地草稿，发送后保留同一聊天实例。

聊天里的指代和执行意图由当前伙伴结合对话判断。已知来源运行 ID 时，伙伴可直接查询或重新执行，来源不清时按接纳时间与运行标识分页查询该聊天可见的历史。重跑命令校验来源、固定版本和输入文件摘要。本地伙伴的取消命令只作用于同一聊天发起的运行，团队使用者的取消授权绑定到发起回合。工作台发起的运行由用户在运行界面操作。

Workflow 拥有已声明文件的确认、不可变快照与成果收据。聊天、手动运行、工作台重试和子流程在同一确认入口处理文件；Core 在写事务外复制快照，再核对运行或节点状态并提交收据。子流程向父流程传递已确认的文件，聊天只按收据复制和交付，不决定是否冻结成果，也不清理 Workflow 的节点成果。原始快照缺失或校验失败时会保留对应错误，其他已确认的文件继续交付。读取快照或写入会话文件副本遇到存储错误时，可以重试交付。历史入口被清理后，已接纳的原回复交付仍可完成。原回合中断时，补写只使用该回合的输入、本次结果和已确认的部分成果。

系统技能的 [创作指南](../../skills/bot/references/workflow-authoring.md) 负责目标分解、数据依赖、用户决定、验证与恢复方法，按需读取编排模式及可编译示例。prepare 返回当前源码、所需类别的资源和生成 SDK。Python 可用性检查随语言目录查询或实际运行需求触发。宿主负责参数、授权、版本和业务成功条件的校验。伙伴使用当前 attempt 的结果工具提交结构化结果，成功接纳的候选内容保持固定，节点执行结果另行确认。

画布默认从空白区域拖出矩形框选阶段；按住空格或切换平移模式可移动视野。节点及浮层表单保持各自交互。背景和左下缩放控件与知识图谱共用，提供缩小、当前比例、放大和适应画布。

创作新输入在保存回执时解析并保存有效账号、模型、强度和 Fast；同一回执重试沿用原值，普通续聊沿用 Chat 最近有效选择，用户显式修改仍生效。创作消息以执行接纳回执确定发送结果；回执直接交付已取得的 Chat 与 Execution 快照，不为组装响应再读取执行，也不丢弃快照后只保留 Chat ID。后续详情由原查询加载，读取失败不会改写已接纳结果或恢复为待重发输入。创作会话接纳、定义、批注、版本和运行历史变化分别由提交后事件更新各自查询，接纳与聊天终态不无条件重读版本和运行目录。

命令与回执共用 botcli 入口。发送时选中的工作流定义和 Revision 约束本轮普通启动。源码保存检查默认目标与显式标识一致，事务内复核当前执行和源码版本，保存形成新的 Revision。本轮取得同一定义的保存回执后，可以按用户要求显式启动回执中的版本。运行接纳冻结该次输入，节点结果提交事务核对当前尝试与运行状态。版本冲突通过重新读取源码处理。

运行接纳校验 Revision、参数、权限、资源和冻结目录。手动运行优先保留当前会话选择的执行配置；没有创作会话且伙伴步骤缺少 Runtime 绑定时，表单直接复用共享执行配置解析，不依赖展开聊天。节点只在相同智能体下继承运行账号，在相同智能体和账号下继承模型，在模型也相同时继承思考强度和 Fast。显式留空的账号、模型和强度由现有 Execution 默认规则解析。纯本地流程不要求模型配置。手动、自动任务、使用者 CLI 与子流程复用接纳规则。伙伴节点保存接纳时解析的配置和 Fast，派发与重新运行使用该节点配置，不能在执行时重新读取应用默认。Run、节点实例、Attempt 和 Effect 分别标识本次运行、分支／轮次中的节点、真实尝试及外部效果。

聊天发起的 Run 保存来源 Chat、Execution、用户消息及调用时名称。聊天按可见回合批量读取状态和对应问题，沿 joined 父子关系定位真实请求，通过统一事件连接在提交后重新读取。工作台以 Run ID 打开执行画布。后续消息要求重跑时，新的运行保存其来源 Run ID，并绑定新回合。正式输出文件由后台按来源回合交付，正常结论由发起伙伴在原回合给出。原回复中断或早于运行结束时，用户可在两者结束后手动补写。同一次补写按运行身份去重。若原智能体无法补写，则向原回复交付运行保存的终态、正式结果和失败原因。

团队普通续聊按 Chat 身份查询是否存在来源运行，再装配历史工具；每次读取持久来源，不维护启动恢复索引或另一套回合停止标记。历史可见性由原运行记录决定。能力有效期与撤销由实际 Execution 生命周期决定，持久停止记录只负责停止与运行接纳之间的事务栅栏；单回合保存回执只在该能力作用域内授权后续版本调用。

聊天来源的工作目录和其他已授权目录分别冻结，节点、子流程与重跑沿用该范围。接纳在全局命令锁外准备和验证输入文件，获胜的请求以目录移交已准备好的文件，再在短事务内提交运行和回执。创作准备读取源码时复用已绑定的定义目标校验。

Go Runner 依据持久检查点推进并行、管道、循环、人工请求与子运行；状态提交与租约使用共享协调。外部调用在事务外执行，回执按效果身份与尝试代际核验。

画布采用编译器生成的 Manifest，公开节点判别联合、控制结构和数据依赖，运行状态从持久实例叠加。创作时的结构化澄清问题与普通伙伴对话一样，显示在聊天输入框区域，复用原请求身份和答案处理器；运行中的 askUser 决策可以在画布节点和发起聊天的提问卡作答。聊天卡与画布按运行、请求和冻结摘要共享当前窗口内的答案草稿与提交状态，任一处均可提交同一份答案。运行选择题冻结候选、摘要及问题版本；回答必须带 CAS，过期回答不能作用于新问题。

每个阶段纵向排列多个步骤，卡片以中性背景、紧凑排版和最多两行的说明组织信息。处理类型通过业务文字与 Lucide 图标区分，伙伴使用实际头像与姓名；颜色集中用于选中、运行中和状态标签，已完成步骤不持续播放动画。详情使用紧凑画布浮层，呈现业务标题、行为说明、处理类型和用户问题，不展示内部身份、摘要或调用代码。拖框选择的阶段成为输入框内部的引用标签，删除标签同步取消画布选中状态。引用固定原 Revision 和目标身份，由服务端验证归属并补充权威标题，后续修改仍以当前源码的 CAS 保存。
同一 Tick 复用已经确认的聚合用于派发，提交后以窄运行状态核对取消等协调结果。worker 使用已冻结的配置进入 Execution 接纳，随后按固定的执行身份读取状态和最终正文。工作流等待以同一份运行快照判断终态并返回结果。运行详情读取成果文件的存在和大小，下载与交付按冻结收据核验内容。聊天工具和总结依据已有附件交付收据引用部分成果，附件交付独立结算。列表摘要只取展示需要的列。

页面的定义、运行、实例和日志查询沿统一事件调度各有所有者。日志事件只更新日志窗口，不重新读取整份 Run 或所有实例；实例由自身查询消费相关状态变化。隐藏 Scene 的变化只标记所属查询陈旧，不主动读取；恢复可见时权威对账，后台运行不随页面关闭而停止。

## 授权与失败

业务问答、Runtime 工具审批与确定性操作许可分别校验。聊天启动的工作流及其子流程以发起回合冻结的权限为节点权限上限。聊天重试和重跑同时受原运行及当前回合约束，接纳时按实际节点校验。失败和缺失可靠外部结果停止后续步骤，保留原调用与错误证据，不盲目重发。

删除工作流直接移除定义入口，不因聊天、活跃运行或自动任务引用而拒绝，也不自动解绑或修补引用；后续访问按实际资源是否存在返回结果。不可变版本和已有运行事实仍由原领域保存。

worker 的 Chat 身份在准备 Effect 时确定并持久保存。删除来源会话或 Workflow 节点会话时，共享 Chat 删除入口先按来源及 Effect 的 Chat 归属，将未结束 Run、跟随的子运行和未完成节点直接设为失败。短事务提交后取消实际工作与节点执行，再删除会话；已有终态保留，原会话交付到此结束。此路径不等待 Run 经过 cancelling 收敛，不安排重跑、补交或恢复任务。

用户通过当前运行入口查看结果和授权，通过优化创作读取运行证据调整源码。优化携带可见、可移除的原 Run、Revision 和可选实例引用，服务端校验归属。失败及已取消的执行记录提供直接重试入口，与运行详情共用重试计划。计划使用原运行的业务标题，按原实例创建顺序展示，固定原 Revision 创建新 Run；仅复用配置、输入与依赖一致的安全结果，确认题、文件产物与结果未知的外部效果不能盲目复用或重做。用户停止与实际失败始终有效，后台恢复根据持久状态决定可安全推进的步骤。

## 执行返回值与文件

worker 无 Schema 时返回文本，声明 Schema 时直接返回符合 Schema 的值。节点间传递真实业务返回值，普通详情阅读业务正文和答案。独立产出页、查看产出卡片、页面声明和专用渲染接口均不提供。action 返回 data、durationMs 和可选 process，业务成功由 successCondition 检查 data，不能只凭进程退出码判定。Schema 中 type:string、format:file 声明真实文件；普通字符串不自动解释为文件。产出依据已确认 Effect.Result，候选提交不等于节点成功。worker 同时核验指定 Execution 的终止原因与交付失败事实；只有正常结束且没有原生失败时才确认产出。截断、回合上限、拒绝或缺失终止证据会保留失败详情并阻止下游，已有候选不能覆盖该结论，也不触发格式纠正或自动重跑。

结构不合法的 worker 结果通过共享 `AgentManager.GenerateText` 独立文本调用做至多两次格式修正，次数持久化。输入只包含 Schema 和已有候选，不注入工作流业务能力、不重新派发 worker、不补造缺失业务数据；原生 CLI 的工具配置沿用独立文本调用边界，修正结果仍须通过 Schema 校验。

输入表单由 inputSchema 自动生成。运行返回值与效果身份固定，不被重试覆盖。

文件在所属 Run 的冻结范围中创建。上传通过 Core 保存原件，接纳时准备独立输入目录；本机 API 调用不能以任意本机路径代替上传。授权的自动任务文件交付仍检查真实文件及范围。

已结束运行可以确认后从可见历史移除。默认保留上限 30 条，超限时移除最早一半的已结束记录；活跃运行可以暂时超限。保留文件及幂等、固定版本和交付所需事实。

语言与生成入口见 [工作流语言](workflow-language-cn.md)。
