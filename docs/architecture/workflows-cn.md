# 工作流

## 源码与版本

Workflow Definition 保存稳定身份、当前版本、创作关系和批准范围；Revision 不可变保存完整源码、Manifest、编译结果及参数和产出契约。画布与表单是源码的投影，编辑后重新编译并以 CAS 保存完整新版本。

恢复选定版本时读取其源码，经当前编译器验证后形成新 Revision。已有运行固定原版本与输入，不被定义后续编辑改写。

## 创作与运行

创作复用普通 Chat、Composer、Runtime、受管目录和系统技能。会话与画布组合在主容器，文件、浏览器和终端继续使用独立工作台。首次输入前保持本地草稿，发送后保留同一聊天实例。

画布默认拖动空白区域平移，节点及表单操作保持各自交互，不再提供移动模式按钮。背景和左下缩放控件与知识图谱共用，提供缩小、当前比例、放大和适应画布。

创作消息以执行接纳回执确定发送结果；回执直接交付已取得的 Chat 与 Execution 快照，不为组装响应再读取执行，也不丢弃快照后只保留 Chat ID。后续详情由原查询加载，读取失败不会改写已接纳结果或恢复为待重发输入。创作会话接纳、定义、批注、版本和运行历史变化分别由提交后事件更新各自查询，接纳与聊天终态不无条件重读版本和运行目录。

创作权限绑定当前执行，不设置独立有效期；等待用户回答期间仍有效。每次能力调用及保存事务都校验当前身份和执行终态，执行结束或被新执行接替后停止旧调用。失效响应区分执行结束与权限被接替，并引导通过创作对话的新消息继续；版本冲突仍通过重新读取源码处理。

运行接纳校验 Revision、参数、权限、资源和冻结目录。手动、自动任务、使用者 CLI 与子流程复用接纳规则。Run、节点实例、Attempt 和 Effect 分别标识本次运行、分支／轮次中的节点、真实尝试及外部效果。

Go Runner 依据持久检查点推进并行、管道、循环、人工请求与子运行；状态提交与租约使用共享协调。外部调用在事务外执行，回执按效果身份与尝试代际核验。

同一 Tick 复用已经确认的聚合用于派发，不紧接着重新加载全部子表；提交后以窄运行状态核对取消等协调结果。worker 只观察其固定首次执行，状态和最终正文按准确执行位置读取，不从最新聊天页倒找。列表摘要只取得实际展示列，不解码后丢弃整份 Manifest。

页面的定义、运行、实例和日志查询沿统一事件调度各有所有者。日志事件只更新日志窗口，不重新读取整份 Run 或所有实例；实例由自身查询消费相关状态变化。隐藏 Scene 的变化只标记所属查询陈旧，不主动读取；恢复可见时权威对账，后台运行不随页面关闭而停止。

## 授权与失败

业务问答、Runtime 工具审批与确定性操作许可分别校验。未经许可不扩大范围。失败和缺失可靠外部结果停止后续步骤，保留原调用与错误证据，不盲目重发。

用户通过当前运行入口查看结果和授权，通过优化创作读取运行证据调整源码。用户停止与实际失败始终有效，后台恢复根据持久状态决定可安全推进的步骤。

## 产出与文件

worker 输出明确选择结构化页面、实际文件或具有理由的内部省略。Schema 中 type:string、format:file 声明真实文件；普通字符串不自动解释为文件。产出依据已确认 Effect.Result，候选提交不等于节点成功。

只读页面使用封闭 Catalog、Registry 和页面政策，复用共享组件；输入表单使用独立输入能力。Agent 不提供任意 DOM、style 或可写动作。产出与消息共同使用不可变身份，不被重试覆盖。

文件在所属 Run 的冻结范围中创建。上传通过 Core 保存原件，接纳时准备独立输入目录；本机 API 调用不能以任意本机路径代替上传。预览和下载分别检查真实文件与权限。

已结束运行可以确认后从可见历史移除。默认保留上限 30 条，超限时移除最早一半的已结束记录；活跃运行可以暂时超限。保留文件及幂等、固定版本和交付所需事实。

语言与生成入口见 [工作流语言](workflow-language-cn.md)。
