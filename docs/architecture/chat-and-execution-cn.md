# 聊天与执行

## 数据与职责

Chat 是消息与原生会话的容器。用户输入、结构化执行事件和终态结果写入追加式 JSONL；查询索引与当前消息投影可以重建。SQLite 保存聊天聚合摘要、查询定位和其他业务数据，不另存一套 Execution 状态或可编辑聊天正文。

Execution 负责中立工作意图、权限和配置校验、业务接纳、执行终态及取消。`ThreadLifecycle` 按 Chat 维护原生绑定和配置兼容；`Turn` 拥有本轮输入；`ProviderRuntime` 独占原生进程、账号与资源租约。共享 cwd 不合并聊天身份或原生进程。

`agent.Catalog` 保留 CLI 安装、Profile 与程序定位，acp-go 拥有原生协议和客户端。Chat 与运行时共用 ConversationStore，查询投影不复制执行权威。职责详见[智能体与账号](runtimes-and-accounts-cn.md)。

## 输入与接纳

草稿在首次发送前保持本地。服务在真实接纳点形成执行身份与消息事实；未接纳输入不能伪装成已发送。客户端请求身份区分正在接纳、成功接纳与结果不确定，避免重复首次发送。

客户端先按实际请求内容准备已有幂等身份，再创建临时消息和提交请求。用户与助手消息、安全事件及接纳回执复用同一 `submissionId` 关联；首发映射创建请求的 `clientRequestId`，续聊从发送入口传递原提交身份。持久事实可以先于 HTTP 回执抵达，前端按明确关联接管临时输入，不比较正文或猜测下一个消息。

点击发送后，界面立即沿本次提交状态显示“工作中”和停止入口，不等待 Chat ID 或后端接纳；准备失败后恢复输入并显示对应错误。该交互反馈不提前生成已接纳的服务端消息事实。

续聊使用原 Chat 的工作范围和可用原生会话。运行中输入按能力进入即时输入或临时队列；输入未被接纳前仍可编辑。队列不作为已提交消息权威。

执行准备分开读取当前 Chat/原生续接、精确提交收据、指定执行和明确历史交接，不使用完整消息聚合作为通用上下文。一次已有 Chat 接纳在原操作占位中读取一次当前上下文；热续发不读取历史窗口。新原生会话才按配置选择最近可交接的完整成功轮，再读取所需正文并应用总量上限；失败、取消和内部消息不占用完整成功轮的数量，正文超限按既有规则裁剪。

指定执行、首次执行与原提交收据通过可重建定位索引找到 JSONL 的准确位置。定位索引只保存原身份、序号及已覆盖游标，不拥有状态或消息；覆盖落后只追平日志尾部，缺失和损坏走原权威恢复。详情文件差异、真实分叉和显式摘要继续按各自需求读取，不进入普通热续聊。

聊天目录只返回游标页，不附带默认项目的全历史查询。普通伙伴与团队草稿在所属伙伴确定后按需查询最近可用项目；候选按活动游标有界推进，失效项目不会令有效的更早候选被任意截断。已有 Chat、运行中发送和终态不重新查询草稿默认项目。

Execution 解析一次有效选择，直接构造 ThreadRequest、TurnRequest 与 TurnPorts，再调用 ThreadLifecycle.Prepare。稳定档案、角色与能力说明交给原生指令入口；本轮目录、引用与业务上下文进入新增输入。普通聊天共享伙伴固定 cwd，私有日志与附件始终按 Chat 隔离，具体目录见[工作区与存储](workspace-and-storage-cn.md)。

准备阶段判断原生绑定是否兼容。冷准备通过既有端口取得账号和资源，由 ProviderRuntime 接管实际及部分取得的租约，再初始化原生会话；热续聊保留连接和租约。输入提交前，Turn 通过 Admit 端口提交接纳事实，再发送同一输入。持久编排入口可先提交待执行事实，后续规范接纳批次补充原生输入身份；资源准备成功不能代替输入接纳。

热续聊读取不可变版本摘要、发布目标和必要共享配置声明，不执行完整插件准备、源内容摘要或秘密解密。冷获取核对实际交付与声明一致，并取得资源租约；外部篡改源内容在冷获取或显式刷新时发现。共享技能和账号的所有权见[工作范围与资源](runtimes-and-accounts-cn.md#工作范围与资源)。

每轮审批、提问与软件能力授权独立激活和撤销，不提前释放热会话文件。活动消费者不能被管理操作替换；闲置消费者关闭确认后才能释放资源。关闭失败保留原所有者供重试。执行使用独立 Context，后台工作不随接纳请求结束而取消；放弃的准备和迟到的部分资源由同一所有者清理。

## 实时与恢复

持久事件使用领域游标，临时流式事件只描述当前过程。事件通过统一资源通道交付；连接中断、序号缺口和缓冲超限后读取权威历史或快照。恢复期间保留已有内容及未知状态，不假定执行结束。

聊天查询各有明确用途：接纳回执提供已经提交的聊天事实，实时流展示尚未持久化的过程；连续持久消息事件携带完整安全消息快照；独立文件成果事件携带目标消息及轻量引用。两者合并原消息 Query Cache 并推进持久游标。正常终态不重复读取最近五十条；首次进入、刷新、断线、缺口及无法证明连续性时才补读权威快照或增量。只取最新一条不能替代完整恢复。插件输入候选按所选伙伴读取轻量固定版本引用，只随相关安装、启停、版本或展示资料变化更新；共享配置、授权与使用变化不重取候选。分叉能力随消息窗口和原持久事件增量投影，不另读全历史候选；忙碌条件由会话事实决定，仅末轮能力使用最新窗口的目标身份，旧分页不提供该全会话身份。伙伴聊天活动不触发无关团队目录刷新。同查询的事件合并与隐藏恢复遵守[查询与事件所有权](notifications-and-work-board-cn.md#查询与事件所有权)。

消息所有者统一处理初始窗口、连续事件、分页、游标和临时消息接管。页面只装配输入、路由和元数据刷新，不在执行完成回调中决定是否重读消息；不保存另一份需要被动同步的权威历史。原始持久事件先完整投影，渲染批次才可按消息合并；临时流不推进持久游标，迟到快照不能覆盖较新事实。

首发接纳保留已有消息、头像和聊天组件的呈现身份；草稿转真实 Chat 时不以身份同步或后台补读为由切回骨架屏。没有内容的首次加载仍显示骨架。运行标记服从执行终态，正文已显示不等于 CLI 已结束；CLI 返回前可能仍有工具或原生收尾，不能由最后一个文本片段推测终态。

Scene 或嵌入工作区既有身份拥有消息视图生命周期，服务器 Chat ID 只绑定数据源。首发交接沿用原呈现身份；真正切换聊天时重建对应消息所有者及 assistant-ui view，不能先显示上一会话再通过 Effect 修正。

ConversationStore 按当前批次格式写入 JSONL。Execution 的终止结论从该执行绑定的原生结果读取，缺少持久结果时返回 unknown。普通聊天的 Completed 表示业务执行已完成。要求完整结果的调用方还必须检查原生停止原因和失败状态。

运行中的追加指令（steer）沿用取消原调用后继续提交的执行机制；接纳事实记录其接续的原执行标识。界面只连接相邻且身份匹配的取消段，保留追加输入与各段过程、文件成果，在末段统一展示耗时、用量及复制操作；普通停止和之后独立发送不合并。队列交接期间暂时隐藏原段取消提示与收尾操作，追加发送被拒绝后恢复原段状态。刷新与历史重放从同一接纳事实恢复关系。

最近一条助手消息使用动态头像，更早的消息保留头像列占位，以保持正文对齐。末尾追加用户消息时继续显示最近一条助手消息的头像。

过程投影按发生顺序组合说明、思考与工具活动。最终正文独立显示，工具名称、输入和结果经过统一语义摘要；文件、敏感值与原始诊断遵守展示边界。

工具开始、累计参数快照、执行进度与终态分别归一为 `tool_use`、`tool_input_snapshot`、`tool_update` 和 `tool_result`。工具展示身份由 Invocation 与原生工具标识共同确定，原生标识仍用于审批与原生定位，前端按展示身份区分重试中重复的原生标识。同一调用更新现有部件，不表示再次执行；开始事实立即持久化，连续参数只保留最新字段，到正文、其他工具、执行进度或调用结束时提交。

工具展示按当前安全事实重新派生，不能把部分路径或命令的早期推断固化为最终值。省略字段沿用，显式空输入清除旧参数；ACP Content 与 Locations 按完整集合替换，显式 `[]` 清除旧集合，传输编码不能抹去这一区别。Content 更新保留原始顺序，终端或 MCP 的增量依其明确协议字段解释，不把所有工具正文猜成累计快照或 Token 增量。同一工具的进度达到 128 项或 256 KiB 时提交，消息边界与取消时提交余量；单条超过阈值的更新不截断。ConversationStore 在差量更小时压缩连续工具快照，读出时按已校验的基准还原。消息投影按工具身份应用更新。Execution 与 MessageView 不持有差量基准、不解释文件补丁；规范工具身份统一使用 Runtime 输出的 `toolCallId`，不再猜测原生字段别名。公开历史和实时投影只持有当前有界安全事实，完整工具参数由权威日志按需重放；历史文件差异只读取独立快照。压缩前后必须产生相同的最终公开投影。

原生正文、说明与推理从规范化事件直接进入实时投影。实时窗口从首个待发增量计时，达到 12ms 或 128 项即交付，每帧以 64 KiB 新增载荷为目标。前端继续按显示帧合并渲染。原生权威日志按 2 秒或 8 KiB 写入文本段，部件切换、原生完成及收尾立即写入。工具快照、正文替换与阶段定性通过即时持久检查点交付；若这些事实改变展示部件的边界，后续实时追加从更新后的部件位置接续。

临时流拥有独立代次与连续帧号。实时文本和权威检查点共享正文覆盖版本，持久 sequence 只由权威日志推进。独立审批等事实只推进各自版本。重连先恢复权威消息，再回放检查点尚未覆盖的有界增量；超限关闭订阅并触发权威恢复。缺帧对账失败时保留已显示的内容，成功恢复后重建临时流消费状态。最终用量随规范终态持久化。

连续文本只解码新片段并追加到唯一文本缓冲，类型切换或持久化边界才编码完整语义段；实时正文和展示段引用缓冲的不可变前缀，追加不能改写已经交付的旧快照。不能逐 Token 反复解码、拼接和重编码已经累积的全文，否则即使广播限频，文本分配仍随长度平方增长。

审批、问答与 Core 命令提交后沿原业务事件通道发布。原生交互使用本轮事件端口给出的调用身份，同一工具标识在其他调用中的迟到响应不能作用于当前调用。收尾先提交剩余正文并停止实时窗口，再交付业务终态。

```mermaid
flowchart LR
  Runtime[规范化原生事件] --> Text[正文、说明与推理增量]
  Text --> State[短窗口实时投影]
  Text --> Batch[有界文本段]
  Runtime -->|工具、替换、定性| Log[权威日志]
  Batch --> Log
  State -->|临时消息增量| UI[统一事件通道与界面]

```

历史消息按索引窗口单次折叠权威事件，不另存一份消息正文或持久消息快照缓存。文件成果由明确采集范围的前后快照产生，摘要与按需差异使用同一不可变来源，不从 CLI 工具输入、状态或 oldText/newText 推导，也不从目录可访问性推断已修改。

共享 Execution 在资源准备完成、提交本轮原生输入前，保存空间业务文件、明确冻结项目及本轮已核验精确文件的基线；原生返回后先发布真实执行终态，再由同一后台工作冻结结束侧内容并比较不可变快照。文件收尾有自己的 pending/ready/partial/unavailable/incomplete 状态，不能让模型继续显示运行中。后台所有者及删除等待覆盖文件收尾；下一轮执行可在前轮模型终态后预留，但写入共享工作区的附件和上下文准备、保存本轮基线与提交原生输入须等待前轮结束侧冻结，避免后续写盘混入前轮历史。技术屏障在冻结后释放，差异计算与成果发布继续收尾；私有快照库的读写仍遵循原有锁约束。成果内容和差异先耐久保存，日志随后提交轻量引用；晚到引用推进原消息；确认有净变更的文件交付同时推进成果阅读版本，不重新打开执行或待办。精确文件阅读身份与无净变更行为遵守[阅读与提示](notifications-and-work-board-cn.md#阅读与提示)。

未接纳且未预提交的准备通过专用 Discard 回收无引用采集记录及孤立对象，Close 则保留中断恢复语义。真实新 Chat 尚无 JSONL、且没有其他采集记录时，同时清理其独有文件成果目录；已有 Chat 只回收本次未发布记录，保留历史与其他采集。

启动时只将遗留 pending 恢复为 incomplete，不以重启后的文件冒充结束快照；普通摘要读取不执行恢复。分叉只复制被继承记录及其对象闭包，引用提交前完成复制，原授权根随继承记录冻结。来源删除后子 Chat 的历史成果继续从自己的归属目录读取。

消息列表首屏只读取最近五十条，上滚接近顶部时按创建游标加载更早窗口，并保留手动加载入口。滚动、按钮和成果定位共用在途翻页，前插消息补偿滚动位置；失败停止自动重试，切换会话后旧请求不能恢复新会话的滚动位置。最新窗口始终向服务端对账，已加载且游标完全匹配的旧窗口复用 Query Cache；新消息改变分页边界时按新游标读取，避免历史缺口。隐藏会话暂停历史查询和实时消费，恢复可见后按原游标对账。

实时投影从当前执行的事实范围建立，能力鉴权只追平并读取 Chat 身份与活动执行。日志身份和版本未变化时复用已恢复的索引作用域，仍校验索引锚点；事件恢复在游标前只折叠状态，游标后才生成公开快照。订阅交付完积压后释放中间快照，前端持久游标在事件批次实际投影后推进，避免隐藏或切换时丢弃未显示批次却跳过恢复。

## 错误与重试

配置、发送错误和最新执行失败复用 Composer 的目录／权限顶栏：错误出现时以红色语义背景和可关闭提示替换目录与权限，点击关闭后恢复原顶栏，输入文档保持挂载。同一失败不在消息正文重复展开；历史失败保留收起的详情入口。关闭提示只影响展示，不删除失败事实。应用错误由 `status_error` 唯一定义稳定身份与中英文模板，HTTP、执行终态、实时消息和历史回放传递同一身份及安全模板参数，界面通过共享错误展示入口按当前语言呈现。所有 CLI 只有在协议边界明确标记为公开的可读原因才原样展示；HTTP 的 `messageSource` 与执行消息的 `errorMessageSource` 明确区分公开原因和应用本地化正文。私有包装、类型名、枚举标识及诊断正文不进入展示，未知错误使用本地化兜底，技术原因保留在日志。本地 i18n 提示由原构造或调用明确声明可展示来源；发送、历史与知识通知保留同一错误元数据，旧持久提示缺少来源时统一兜底，不从标识或正文猜测信任。消息与执行回放只消费终态显式保存的身份、参数和原因来源；未声明公开来源时使用安全兜底，规范原生回执中的原因不能替代终态来源。原生失败分类与应用展示身份分开保存，不把交付失败解释为原生工作已停止或允许安全重试。错误恢复成功后清除对应操作错误。输入区只展示最新错误，新错误覆盖旧提示，关闭或恢复后不回退到旧提示。

普通聊天不提供重新运行历史失败执行的接口或按钮。网络重传沿原提交身份核对既有回执；未知外部效果不自动重放。历史接力已登记但缺少原生消费确认时，若所属执行已经持久记录为失败，用户切换智能体可在旧连接关闭后继续；新会话只提交当前输入，不补写旧消费关系。没有明确失败终态的接力继续等待确认。团队和工作流保留各自真实控制与重试入口。

原生流异常结束但未提供终态时，保留已接纳输入、已观察片段及原操作错误，不伪造原生结果、消费关系或确认。原进程成功关闭后，该异常观察本身不再阻塞资源释放；真实结果的持久化失败、确认失败及进程或租约释放失败仍由原所有者负责重试。后续准备先重试遗留清理，只操作捕获的原所有者，不能关闭同一 Chat 后来建立的连接，也不自动重发旧输入。

会话分叉通过同一 Store 的输入消费关系找到原生结果，读取实际协商的分叉精度与位置，并从原输入对应的 Binding 核对历史身份。继承消息只保存必要的原生边界；不维护另一张原生续接表。消息投影只公开可用性、末轮约束和禁用原因，句柄与位置留在 Core。实际 POST 重新核验权威目标、当前历史根与原生能力，未知或不支持时准确拒绝。

分叉由现有 Thread 席位和 ProviderRuntime 管理账号及资源，不创建 Turn 或提交模型输入。冷准备失败可沿原请求重试；实际原生调用前耐久记录副作用边界，调用结果未知时只沿原回执对账。发布子 Chat 时同时保存实际分叉 Binding，首次续聊直接恢复该原生会话；关闭失败仍由原所有者保留租约。

## 阶段耗时

新建聊天发起 create 或已有聊天续发 send 时，乐观助手消息先以伙伴头像表达准备状态，收到可展示内容后再显示消息卡片。最终展示耗时从 Execution 收到本轮输入开始，包含资源准备、CLI 初始化、输入接纳和实际运行；起点随执行创建事实持久化，历史重放保持同一口径。服务端持久耗时不包含请求到达 Execution 之前的客户端与传输时间；没有起点的旧历史仍从原生接纳计时。

代码入口为 `services/chat`、`services/execution`、`internal/agent`、`internal/chat/{conversation,eventlog,eventstream,messageview,changes}` 及前端 `modules/chat`。

## 头像与工作反馈

头像由通用形状、材质、颜色和默认表情组成，既有 avatar 字段保存版本化配置。旧头像标识稳定映射为通用组合，不再加载专属身体资源。共享选择器、消息、列表与欢迎页使用同一 Bloub 渲染层，通过 `@neuxbot/bloub` 依赖自维护 fork 的 `main` 分支，根锁文件固定解析提交；框架无关核心与材质在 fork 维护，主仓库负责 React 集成与业务状态编排，不复制库源码。形状与表情来自固定开源核心，毛绒使用原创完整立体身体图集，粒子由三维体积内细光尘投影成 SVG 图集并作为单张纹理解码，保留体积光照与透明边缘，不裁空眼周。外观选择只显示选中背景，不叠加勾选图标；切换保持旧完整外观，待新纹理换色和解码完成才整体交接，首次未准备好保留透明占位。眼睛沿用上游整脸向内增长算法放大至 1.3 倍，保留边距和眨眼。来源见[第三方声明](../../THIRD_PARTY_NOTICES.md#bloub-头像动画核心)。

最近一条助手消息使用动态头像。准备、思考和工具执行共用 Bloub 的思考动作，正文输出使用眨眼，等待审批或问答、停止中和取消使用空闲姿态。失败保留警示，完成保留带主题色圆点的通知姿态。侧栏伙伴头像保持空闲，业务状态由独立状态入口表达。可交互头像空闲时，悬停或键盘聚焦临时显示友好表情，指针和键盘焦点都离开后恢复保存的表情。双击或键盘激活侧栏头像可以打开伙伴资料卡。动态头像离屏或页面隐藏时暂停，减少动态效果时使用固定帧。普通、团队和工作流空白会话保留输入与必要状态。
