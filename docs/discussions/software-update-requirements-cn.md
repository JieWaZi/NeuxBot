# 软件升级需求核对

文档状态：访谈结果已收敛。本文保留用户确认结果与事实依据，当前交付基线见[首轮 SPEC](../superpowers/specs/2026-10-16-software-update-design.md)，执行、独立审查和验证状态见[实施计划](../superpowers/plans/2026-10-16-software-update.md)。

需求通过 `grill-with-docs` 核对。用户已要求按最终范围补齐 SPEC 和计划、启动独立子代理审查、修复并验证后推送功能分支及提交到 main 的 PR；不再将已延后的签名细节作为交付前提。

## 已确认的需求

- 为已经有首个版本的桌面软件增加升级能力，评估 GitHub Release 与适合项目的开源方案。
- 设置增加“关于软件”入口，显示软件版本，并在有新版本时提供下载入口。
- 发现新版本时，原通知铃铛位置改为下载按钮。
- 首轮采用自动检查与下载更新，随后打开安装包，由用户手动覆盖安装并重新启动；应用内自动安装并重启延后评估。
- 本轮不做正式发行代码签名，macOS 保留运行所需临时签名且不做 Apple 公证，Windows 不接入 Authenticode；后续用户规模增长后再评估正式签名。
- 中英文 README 说明未签名状态、macOS 与 Windows 安装提示的具体处理步骤，并区分系统提示和 HTTPS 证书错误；下载保留 HTTPS 及完整性校验。
- 以个人身份作为发行主体；账号注册、证书、签名服务申请及费用不作为本轮前提。
- 开发使用独立 worktree 与功能分支，不直接在 main 开发。

## 已确认的决策

### D1：首轮手动覆盖安装并重新启动

用户确认本轮采用“自动检查和下载更新 → 打开安装包 → 手动覆盖安装 → 重新启动”。下载完成与安装完成分别表达，应用提供打开已校验安装包的入口，不显示为已完成安装。

安装前由用户完成正在进行的工作并保存内容，从应用菜单或托盘真正退出；关闭窗口只会隐藏应用。随后覆盖原安装位置并手动重新启动，沿用原应用标识和独立用户数据目录。

现有实现只打开系统安装包，不主动退出、不静默执行替换脚本、不主动中断工作。应用内自动安装并重启延后评估，不作为本轮完成条件。

### D2：首轮未签名发行，正式签名延后

用户决定本轮先不做正式发行代码签名，待后续使用人数增多后再评估。macOS 沿用运行所需的临时签名，不使用 Developer ID、不做 Apple 公证；Windows 不接入 Authenticode。不申请开发者账号、不购买证书、不接入 SignPath 或其他云签名服务。

中英文 README 明示当前未签名状态，提供 macOS 单应用放行、Windows SmartScreen 提示和网络证书错误的处理说明。下载仍使用 HTTPS，摘要用于检查完整性，不描述为已认证发行者身份或已通过全部系统安全检测。

此前核实的签名服务及开源案例保留为[后续参考](software-release-security-cn.md)，不作为当前正式发布的前置条件。单应用安装例外不等于关闭全局安全保护，HTTPS 证书错误也不以关闭校验处理。

### D2-P：个人发行主体

用户选择个人身份发行。该偏好继续保留，账号与证书条件在后续决定启用正式签名时核验，本轮不继续访谈签名身份所在地区、服务资助资格或证书费用。

## 首轮保留的工程选择

用户确认目标及交付流程后，未另行指定的产品细节按既有实现保留，明确记为开发方工程选择。固定 GitHub 正式发行、启动约 15 秒及每 6 小时检查、手动点击下载、失败重试、未签名发行和手动覆盖安装的具体边界统一见[首轮 SPEC](../superpowers/specs/2026-10-16-software-update-design.md#工程选择与首轮边界)。

不增加镜像、预发行、忽略版本、暂停或断点续传、自动替换、强制停止工作、自动备份和自动回滚。铃铛替换不能改变通知事实与已读状态，工作看板仍应可达。真实平台安装与视觉验收没有被讨论确认或自动化检查替代。
