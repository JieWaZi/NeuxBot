# 聊天展示整改记录

本轮对应用户确认的 Harness 排版、宽表、图片和链接整改，并修正首次 A/B 已发现的三帧额外等待。实现继续使用本项目语义颜色、排版 Token 和共享控件；现有耗时、过程说明、网络组、工具折叠和最终正文分区保留。

| 范围     | 当前行为                                                                       | 对照与适配                                                                                            |
| -------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |

## 调度对照

运行实际旧 16ms 调度器、[首次实测三帧源码归档](chat-presentation-refactor-evidence/performance-review-batcher-before.ts.txt)和当前单帧产品源码，采用同一个虚拟时钟、100 个输入和五个输入相位；每个场景完整验证正文覆盖、即时终态和关闭后无遗留任务。

| 场景                | 旧 16ms timer p95 | 整改前三帧 p95 | 整改后单帧 p95 |
| ------------------- | ----------------: | -------------: | -------------: |
| 60Hz，每 20ms 一批  |              16ms |       49.667ms |       16.333ms |
| 60Hz，每 80ms 一批  |              16ms |       49.667ms |       16.333ms |
| 120Hz，每 20ms 一批 |              16ms |       24.667ms |        8.000ms |

以上为各输入相位中最差的 enqueue→onBatch p95，包含保留的全部样本；不含模型、网络、React、布局或 paint。60Hz/20ms 场景含终态的发布次数五个相位均值为三帧 40→单帧 100.2，等待减少伴随更高提交频率，不能据此宣称整个页面 CPU 同时下降。终态两侧均为 0ms 额外等待。

[完整相位记录与源码 SHA](chat-presentation-refactor-evidence/performance-review-scheduler.json)保留，归档三帧源码 SHA 与[首次 A/B](chat-presentation-performance-ab-cn.md)完全一致。复现入口为 `node packages/frontend/scripts/performance/scheduler-ab.mjs 29b609b`。

首次 A/B 中的长代码 CPU、完整公开链路 5 倍正文和前置快照成本，本轮没有重新测量或解决，整体性能验收仍不能宣布通过。
