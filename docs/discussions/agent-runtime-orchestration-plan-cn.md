# 编排入口 Runtime 迁移

> 历史阶段记录：本文的目录、独立 Go module 方案、迁移顺序和验收结果均以当时为准，不作为当前实现或重新验收的依据。当前执行能力已归入 `server/internal/agent/{core,host,environment}` 并属于 `server` 主模块；会话、启动与认证所有权以[职责收拢 Spec](agent-runtime-boundaries-spec-cn.md)及[当前架构说明](../architecture/runtimes-and-accounts-cn.md)为准。

## 目标与边界

团队、工作流、自动任务、IM 和 Chat 型知识操作统一使用已有独立 Runtime 宿主。业务编排继续拥有接纳、授权、幂等、依赖、取消和成果交付；Runtime 只负责技术会话与回合。保持输入、能力、交互和输出的明确端口，不给内核加入业务类型分支、通用注册框架或新的身份及锁。

普通 Chat 与编排最终共用 `Execution.Start` 和一个注入的 Runner，删除上一阶段的 `StartChat`、双 Runner 配置及随请求传递的迁移选择。共享账号、插件和能力授权沿既有执行生命周期提供；真实原生消费者退出后才释放其租约。保留原生 CLI 行为，不增加禁工具或禁 MCP 门槛。

执行端口明确提供带租约运行、已有会话摘要和工作区关闭能力；删除每轮可选类型断言、无租约执行回退和旧账号释放闭包。原生分叉及 CLI 目录仍通过各自明确方法提供，业务测试替身遵守同一所有权契约。

- [x] 旧链删除：查清旧 SDK.Run、ACP 回合执行与缓存的实际调用，删除无调用旧代码及专属测试。探测、启动准备、配置和原生分叉仍被使用的能力保留，不能为删文件破坏这些能力。

## 验证重点

| 入口 | 继续由业务拥有的职责 | 技术执行变化 |
| --- | --- | --- |
| 普通 Chat 与伙伴 | 消息、审批、提问、重试与分叉 | 删除 StartChat，统一 Start |
| 团队负责人和成员 | 团队接纳、依赖、报告与通知 | 全部使用同一宿主，各 Chat 保持独立会话 |
| 工作流节点与创作 | 冻结版本、节点状态、创作授权与成果 | Agent 节点及创作调用统一执行端口 |
| 自动任务 | 触发、幂等运行、交付记录 | 伙伴执行走 Start；团队和工作流沿各自编排进入 |
| IM | 消息去重、绑定授权、回执与外部交付 | 伙伴执行走 Start；团队消息沿团队编排进入 |
| 知识相关聊天 | 单库授权与已签发的领域能力 | 复用普通执行能力；独立生成与 Wiki 维护保持已有独立任务宿主 |

团队直接输入与调度任务保持同一聚合接纳边界；工作流保持冻结版本与节点成果语义；自动任务和 IM 不把接纳当成完成。工具授权撤销与原生文件/账号租约释放各有真实所有者；取消、隐藏摘要与重试不得回退到旧引擎或自动重放有副作用的调用。

只运行受影响包或用例，不运行仓库全量检查，不控制页面或真实用户数据。固定外部 acp-go 继续独立维护。真实 CLI、模型与 UI 验收单独记录，不能由替身测试冒充。

## 当前验证与删除范围

团队和工作流组合测试使用真实 Execution、ChatHost、独立 Runtime、临时 SQLite 和权威消息日志，仅替换外部 Driver。团队负责人和成员同时运行时各自使用私有执行工作区，共享批准的业务目录；停止后两条执行均保存取消终态。工作流覆盖创作授权、源码保存、固定版本、节点成果与持久终态。自动任务组合覆盖触发、冻结配置、幂等和删除时的活动执行保护。

执行层定向验证覆盖普通及团队接纳拒绝、配置变化、账号关闭失败、取消、重试、隐藏摘要与原生分叉。IM、自动知识授权及独立知识任务的直接回归通过；这些没有新增完整外部平台组合验收。可选真实 CLI 工作流验收已改接新宿主，本阶段未启用。

已删除旧 SDK.Run、Prompt、事件桥、回合队列、热会话缓存和无生产消费者的 TestConnection、默认回合配置、工具白名单；删除其专属测试，保留独立 Runtime 对应覆盖。当时旧目录保留仍用的 CLI 目录、探测、原生工厂、账号启动、工作区准备、公开错误分类与分叉；后续 CLI 收尾已拆分这些职责并删除旧目录。管理操作每次持有独占短连接；业务分叉预检通过宿主关闭源会话，关闭成功后才能持久化“原生操作已开始”，关闭失败仍允许同一请求恢复后首次派发。

阶段末仅进行一次集中 review，发现并修复上述分叉关闭与持久派发标记的时序问题。真实 Chat 日志回归证明：关闭失败不标记原生已开始，恢复后同请求可以首次派发；真正派发后超时则只对账，不重放分叉。修复后的 Fork 定向组合及执行/宿主 vet 通过。其余管理能力、业务组合、直接影响回归和文档检查通过；没有进行真实 CLI、账号、模型或 UI 验收。
