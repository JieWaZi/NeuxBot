**以一个 PR 贯穿这条链。** 事件到达时要同时认得“这是哪次投递”和“它说的是哪个仓库里的哪个 PR”。前者用于识别重投，后者用于找到相关工作。DeepSeek 先按事件 ID 去重，按来源讨论与已有 Ticket 的订阅关系分发，没有已接手其判断的工单时再进入评估，单作上下文的扇出仍可伴随评估。OpenBot 的工作流按规则匹配，同一 PR 已有活动运行时可排队，其他 PR 仍可推进。前一条规则决定是否续办原工作，后一条规则限制同一对象并发。在 Go 中，确定的规则直接派工，需要判断归属时才由 Router 处理。Worker 的结果带原请求回执，用户因而可以在那份报告下继续交代。[DeepSeek 事件接纳](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/core/intake.ts#L19-L60) · [OpenBot GitHub 事件匹配与排队](https://github.com/nightly-labs/openbot/blob/100c60e893eda3ce4761b4d10001a8e490c43536/src/backend/workflows/workflows.ts#L1973-L2034) · [OpenBot 回件](https://github.com/nightly-labs/openbot/blob/100c60e893eda3ce4761b4d10001a8e490c43536/src/backend/agent/turn-lifecycle.ts#L3315-L3335)

**重启后按已经发生的事恢复。** open-super-agent 将遗留的 running 执行标为中断。DeepSeek 给仍需继续的 Ticket 创建新 Assignment，并带恢复说明。其 Outbox 将发送意图与待处理动作一起落库。OpenBot 给伙伴回件使用原请求和稳定的幂等键。Go 侧按这三个上游边界区分“重新接着做”和“补交已做好的结果”。若外部平台缺少幂等或送达证据，重启记录本身不能证明对方是否收到。[运行中断](https://github.com/kadaliao/open-super-agent/blob/e9722c7462cbf220ece4e03f74257cfc7d19962a/server/crates/osa/src/tasklog.rs#L278-L295) · [恢复工作](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/docs/003-execution.md#L141-L157) · [投递收据](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/app/outbox.ts#L17-L50)
