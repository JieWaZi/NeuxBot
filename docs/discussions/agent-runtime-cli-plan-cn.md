# CLI 管理与旧 Runtime 收尾计划

> 历史阶段记录：本文的目录、独立 Go module 方案、迁移顺序和验收结果均以当时为准，不作为当前实现或重新验收的依据。当前执行能力已归入 `server/internal/agent/{core,host,environment}` 并属于 `server` 主模块；会话、启动与认证所有权以[职责收拢 Spec](agent-runtime-boundaries-spec-cn.md)及[当前架构说明](../architecture/runtimes-and-accounts-cn.md)为准。
> 执行方式：subagent-driven-development；按用户要求并行实现，阶段末统一审查一次。

**目标：** 删除 `server/internal/runtimes`，让 CLI 探测、原生分叉、启动工厂和产品宿主各有明确归属，执行内核保持不变。

**设计依据：** [Runtime 重构设计](agent-runtime-refactor-spec-cn.md)。本阶段承接入口统一阶段，不增加 HTTP 服务或企业功能，不保留旧包兼容转发。

## 结构与依赖

```text
packages/agent-runtime/
  runtime/、internal/engine/       调用与会话主链，本阶段不加入探测或分叉分支
  driver/acp/                     公开 ACP 会话与独立管理连接
    management.go                 初始化、无 Prompt 探测、原生分叉、资源关闭
    native/                       全部 CLI 的唯一公开 Agent 工厂
server/internal/runtimehost/
  contract/                       产品执行、目录、交互、结果与错误分类
  catalog/                        安装发现、启动准备、目录解释与管理调用装配
  workspace/                      产品指令与技能文件物化
  chat*.go、text.go、task.go       业务宿主与账号/资源租约
```

`Execution → runtimehost → agent-runtime`；`runtimehost/catalog → driver/acp → acp-go`。产品目录解释依赖宿主契约，独立模块不依赖 server。工作区准备从 CLI 目录服务移出，知识纯生成不主动注入指令文件、技能或 MCP。

探测由启动后台、显式刷新、运行环境设置和账号模型能力查询触发。执行准入使用已有设备快照及账号配置；具体模型、推理与模式在本次原生会话初始化时确认，不能在执行器上断言额外 Detect 接口。分叉在独立管理端口读取适配器声明，保留原有来源关闭预检、receipt 和仅对账语义。

## 全局约束

- acp-go 独立维护，依赖版本不变；原生 CLI 的自有工具、配置与 MCP 行为由 CLI 自己负责。
- 不新增身份、锁、轮询或重复缓存；保留真实资源所有权、取消、权限和耐久分叉屏障。
- 同一 CLI 的执行与探测/分叉共用一个原生工厂；产品模型展示和权限映射不下沉执行核心。
- 新增 Go 字段均有中文注释；测试跟随职责，不删除仍有价值的行为覆盖。
- 仅运行修改包与直接调用方的定向测试；不运行全仓测试，不控制桌面或浏览器。

## 审查重点

1. 新旧账号模型目录不同：不能每轮探测，也不能放宽原生初始化的确认。
2. 分叉关闭失败与重试：保持派发前预检及既有耐久屏障，不重复创建。
3. 多 CLI 状态目录：执行、探测和分叉共用工厂后仍正确传递持久状态路径。
4. 管理连接取消与关闭失败：不能丢失原生对象或提前释放正在使用的账号资源。
5. 迁移删除完整性：无旧包残留、重复工厂和核心中的厂商/业务分支。

## 完成与验证

旧 `server/internal/runtimes` 的 56 个文件已删除，代码调用方均改用实际职责包；原有测试样例随产品错误分类保留。管理端口与唯一原生工厂、目录/账号/工作区、配置准入、分叉及聊天宿主的定向测试通过；自动任务和工作流的真实 Core 组合测试通过。独立 ACP 管理与连接生命周期定向 race、相关包 vet、依赖边界检查通过。生成器重新生成后端 OpenAPI 和前端客户端，文档及差异检查通过。

本阶段只进行一次集中审查，确认一项退出顺序问题：目录关闭失败时账号服务和数据库必须仍可用于重试。已调整为管理连接先关闭，失败保留依赖；真实 Catalog、账号服务和 SQLite 回归证明首次失败保留、第二次成功回收。

以上为自动化及受控进程证据。本阶段未重新验收真实厂商 CLI、真实模型、真实账号刷新或桌面界面；打包与桌面生命周期的最终验收留待下一阶段。
