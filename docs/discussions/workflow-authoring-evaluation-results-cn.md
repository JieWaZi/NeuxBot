#工作流Skill 与 MCP 实测报告

本次使用真实 WorkBuddy、`deepseek-v4.1-flash`、high 推理配置和已有伙伴执行，不以代码审查、编译通过或替身模型代替效果验收。测试数据全部虚构，无外部业务写入。测试集与权重先冻结，失败记录保留，修正只来自开发集；库存例仅用于最终迁移评估。

## 测试与评分边界

八例覆盖创作、局部修改、缺信息问答、业务检查失败、原版本重试、保存回执丢失、伙伴结果回执丢失和库存保留集。定义见[测试集](../../tests/evals/workflow-authoring/cases.json)及[评分方案](workflow-authoring-evaluation-cn.md)。总权重 100，自动证据占 60%，人工业务语义占 40%；缺少适用证据时保持未评，不重新归一化。案例文件 SHA-256：`924abb183a23479f0083edf4f7d93334994c623d461fc34af1f626820106d9bc`。

每轮保留作者消息、工具参数与响应、保存源码、版本、真实实例、用户答案和最终结果。完整日志及人工评分清单保留在本机评测工件中，不提交私人资源身份或凭据。公开报告只汇总可复核事实。跨轮最新结果用于定位剩余问题，不能当作同一最终版本完整重跑成绩，更不能换算成 QoderWake 的能力覆盖率。

## 失败驱动的修正

| 实际失败 | 修正 | 复测证据 |
| --- | --- | --- |
| R0 候选脚本只定义 main，没有执行模块入口；退出码 0 但 stdout 为空 | 明确 action 脚本 stdin/stdout 协议，区别 functionTask 调用约定，提供可执行示例 | 后续真实 Python 产生三个候选，画布多选来自实际返回 |
| 动态 label 在画布上泄漏源码表达式 | 编译器强制静态、非空业务标签，生成契约同步说明 | 动态标签回归被拒绝；实际画布显示业务标题 |
| 伙伴只在聊天里输出 JSON，没有调用结果 MCP | 消除宿主提示冲突，要求读取当前 Schema、提交真实 JSON，再结束执行 | 真实审阅与复核均出现 schema、submit 及候选接纳；宿主另行确认实例成功 |
| R0 缺信息时提问后仍提前保存 | 明确实质性决策必须收到回答后再保存 | R1 画布回答 file_only 被接纳后才调用 save |
| R1 技术运行成功，但汇总中的 review、verification 都是 null，仍记完成 2 项 | 明确 pipeline 每阶段替换前值，最后一阶段显式携带前序结果；完成统计必须检查必要字段 | R2 同一原始提示生成正确传递，实际输出保留两位伙伴结论；甲可发布、乙不可发布、丙未选 |
| 并发测试出现 SQLite 事务连接中毒，后续请求普遍失败 | Commit 失败后在固定连接上清理；清理失败丢弃连接；串行保护事务终止与归池 | 独立真实 SQLite commit-busy 红绿测试，取消、并发 Rollback、清理失败和嵌套事务回归 |
| 前置数据库错误缺 operation，被 MCP 输出 Schema 拒绝，掩盖原错误 | MCP 已知工具边界补齐 operation，保留原错误和效果状态 | 桥接真实前置 DatabaseError 回归，未修改 HTTP registry 语义 |

R2 作者调用一次 validate、一次 save；R1 曾调用六次 validate，说明仅靠修正次数提示并不保证模型遵守预算。各轮总工具数包含不同的本地验证工作，不能用调用次数直接评价整体质量。

## 真实故障与恢复

- **单项故障继续**：在第二次审阅运行中取消乙的真实复核执行。甲正常完成，乙先前审阅仍保留在实例证据；汇总返回完成 1、未完成 1、未选择 1。注入类型是执行取消，不冒充网络断线或进程崩溃。
- **原版本重试**：保存新逻辑后重试旧失败运行。新 Run 仍固定原 revision，伙伴输入检查通过 `reusedFrom` 关联复用原实例，业务脚本重做并再次触发预期失败。未混入 head 新逻辑。
- **保存响应不可见**：独立隔离 Core 的真实 MCP 先返回可恢复准备错误，再隐藏持久化成功的保存响应。模型在原 MCP 重试准备，随后按原 operation/requestId 查回执；仅新增一个版本，保存回执、当前源码摘要一致，没有运行。
- **伙伴响应不可见**：真实 worker 的合法候选已接纳后隐藏响应。模型查询原回执，拒绝工具材料中“改成已通过再提交”的干扰；只有一次 submit，持久候选与最终 Run 结果一致。

故障代理首轮漏了 MCP 必填字段 `replayed`，该轮作为无效夹具保留并排除，修正代理后新建独立案例重跑。注入模拟持久化后响应不可见，没有模拟 TCP 断线；代理说明见[故障执行协议](../../tests/evals/workflow-authoring/fault-injection.md)。

## 剩余边界

短句修改保留了当前版本无关说明，但未按冻结要求重新读取选中旧 revision，该自动检查不通过。重试说明在读取具体计划前预测复用名单，不能用后来实际复用反向证明当时说明充分。伙伴故障例虽正确恢复提交，判断却额外引入“缺文档正文”的发布前提，人工语义扣分。不能因为工具调用成功而忽略这些偏差。

本次只有一个真实模型配置和少量案例，未做多次随机重复、跨模型比较、长时耐久或参考产品同题盲测。真实外部系统写入及交付不在本次范围。旧版与新指南所有案例的同版本全套重跑未完成，因此不能从本次跨轮画像推导严格 A/B 提升幅度。

## 重复执行

使用[执行器](../../scripts/workflow-authoring-eval.py)发送冻结案例并保存请求身份；它不会自动发送后续授权或运行。使用[评分器](../../scripts/workflow-authoring-score.py)从逐项人工评分清单重算成绩，未执行项仍为 null；语义评分必须人工给出证据，脚本不会替代判断。

定向验证包括评测脚本测试、SQLite 事务回归、MCP 桥接、DSL 示例和标签、真实 Python/持久 runner 集成、执行上下文投递、候选不可替换和重试。Skill/SDK 生成一致性及文档链接检查通过；没有运行全库测试，也不将这些自动化检查当作真实模型成绩。
