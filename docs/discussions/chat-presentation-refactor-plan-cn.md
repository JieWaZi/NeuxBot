# 聊天消息展示重构实施与验收计划

## 1. 执行范围与完成标准

本计划实施[消息展示与文件成果 Spec](chat-presentation-refactor-spec-cn.md)。规格是产品与架构规则的唯一来源；下文只规定任务、测试和交付证据。实际实现、已执行验证与待验收边界见[实施验收记录](chat-presentation-refactor-acceptance-cn.md)，不将文档检查视为功能验收。

实施以当前可运行代码为基线，保留无关修改。按用户授权使用三个 GPT-6.1 Sol 子代理完成 Markdown/节点、增量编排与独立快照。该开发授权不包含推送、真实模型调用或运行中 UI 操作；相应验收单列。

完成必须同时满足：既有产品行为保留、独立文件成果可恢复、唯一增量消息消费、定向回归通过、性能目标有证据、旧链路退出。源文件更少、总代码行数下降或使用同名库均不能代替验收。

清单勾选表示相应实现或交付物已完成，不代表该阶段全部性能与真实平台验收已经通过；未测与未达标项以验收记录为准。

## 4. 性能实施验收

### 4.1 方法

先测当前版本，再用相同输入、设备、构建模式和浏览器/桌面版本测迁移版本。记录 CPU、内存、刷新率、是否开启减少动态、采样工具、冷/热缓存与后台状态。每个受控场景至少执行 5 次，报告中位数、p95 和最大值；50/100/500ms 等延迟阈值来自本计划的验收目标，不是现有系统承诺。

计量至少包含：事件帧数与正文有效载荷、序列化字节与耗时、前端解析/节点构建次数、发布次数、源事件到可见提交延迟、主线程任务、峰值堆、文件 I/O、Git 子进程耗时和快照新增空间。不得通过关闭高亮、丢弃事件、只加载最后一条或隐藏既有信息来获得优势。

自动测试用受控事件重放和临时目录，性能测试是独立可复现入口，不在普通业务测试中加入不稳定的真实时间断言。真实平台 CPU/长任务与视觉测量在明确授权 UI 操作后执行。
