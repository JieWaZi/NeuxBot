# 主会话重构分项开发与验收

从下表选择本次要验收的能力。每个文件都写明用户故事、复用边界、自动化入口、桌面验收方法和不在该项范围内的工作。角色、寿命、消息传递与回调以[会话与工作架构](../superagent-conversation-architecture-cn.md)为准。固定版本的实现对照见[上游调研](../partner-main-conversation-research-cn.md)。

## 当前基线

伙伴及团队各有固定主会话。主会话显示公开短消息，默认的日常消息与未指定项目的交办沿用同一个普通会话作为来源。头像打开完整来源并定位对应回合，可以在原处续聊。两个视图共用提问、审批与工作台。具体会话行为见[聊天与工作台](../../guide/chat-and-workbench-cn.md)。

## 每次会话如何接手

本系列的代码开发交给 `gpt-6.2-sol` 子代理，推理强度设为 `xhigh`。每项先阅读 OpenSuperAgent 和 OpenBot 对应该场景的实际源码，从入口追到状态保存、回调与结果展示。优先复用已落地的处理逻辑，按项目的 Go、CLI 和既有前端组件边界移植或重写。第三方代码直接移植时保留原许可要求的声明。上游版本、采用的行为及本地差异记在规格或验收记录中，产品代码的命名和注释说明自身职责。Nuphos 用于对照公开对话和来源工作记录的交互。

1. 在同一工作树打开本索引与选中的规格。检查分支与本地修改；已有首条链路包含尚未提交的代码，其他新建工作树未必具有这份基线。
2. 从规格给出的真实入口编写定向回归，完成这一项。实现对照放在文档，产品代码和注释描述本项目自己的职责。复用现有会话、消息、执行、UI 组件和收据。
3. 记录实际运行的用例、结果和需要用户点击的操作。自动化通过后将该行更新为「待用户验收」，停在这一项。用户亲自确认后才标记「已验收」。
4. 下一项由用户在新会话指定。例如：“按主会话分项索引开发第 02 项，用 GPT-6.2 Sol xhigh 子代理对照 OpenSuperAgent 和 OpenBot 源码，只做这一项，完成后交给我验收。” 如果上一次桌面验收发现问题，先留在原项修正。

## 整体验收边界

开发阶段按新数据验收。一个主体始终有一个固定主会话；用户新建的是普通对话。画布手动启动的流程由用户在画布查看。全局定时工作流回报为默认关闭的开关，以每次运行开始时的选择为准。普通聊天的现有文件、图片、输入和右侧工作台交互是对应切片的复用基线。
