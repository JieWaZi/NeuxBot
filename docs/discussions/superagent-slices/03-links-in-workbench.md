# 03 主会话与工作记录中的网页链接在右侧工作台打开

## 用户问题

普通聊天已经可以在右侧打开网页。切到伙伴主会话或工作记录，点击同一种正文链接却跳出了工作台。

## 解决方案

从两个视图点击正文网页链接时，沿用普通聊天的网页打开规则，继续留在当前对话中。

## 用户故事

1. 作为用户，我希望在右侧边读网页边聊，以便保持当前工作上下文。
2. 作为阅读工作记录的用户，我希望同一类链接在两个视图行为一致。
3. 作为使用附件的用户，我希望打开本地文件、图片和代码位置时仍指向它们的真实来源。

## 实现决定

- 复用既有 URL 分类、工作台打开回调、页签与平台策略，仅把缺失的回调传到两个消息渲染入口。
- 公开会话不需要全局目录。网页链接的打开不依赖来源目录或当前伙伴是否正在运行。

## 测试与人工验收

1. 从已装配右侧工作台的主会话和来源页各点击一条 HTTPS 正文链接，断言打开同一个工作台浏览器入口，且没有重复调用系统浏览器。
2. 以普通聊天的现有链接用例为对照，回归附件、本地图片、代码引用、平台明确要求由系统处理的链接。
3. 桌面分别在主会话与来源点链接，收起及展开右侧工作台，确认会话草稿和当前网页保留。

## 验证记录

- 从主会话和来源工作记录的正文点击 HTTPS 链接，应用右侧显示浏览器页签，地址栏保留查询参数和片段。两个入口都覆盖了工作目录为空的情况。收起并重新展开工作台后，当前网页地址和会话草稿均保留。来源里按回合展示的公开分段链接也在同一工作台打开。
- 隔离桌面样例使用本地测试 CLI 发出两条带链接的公开消息。重新启动 Core 后，主会话及来源工作记录均能读到同一回合的链接正文。
- 桌面待用户验收。打开样例伙伴「网页链接验收」，点击正文中的「示例网页」，再点伙伴头像进入工作记录并点击「第二个示例网页」。可以在输入框留一行草稿，收起并重新展开工作台，检查草稿和网页地址。

## 不在本项范围

浏览器内核、网页权限和外部协议策略变更。
