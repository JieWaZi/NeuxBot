# 02 点击长主会话里的引用能定位到原话

## 用户问题

一条消息可以正确引用几百条以前的原话，但在重新打开会话后，原话可能还没有载入。点击引用没有可见结果。

## 解决方案

点击引用后按需要载入更早的消息，并定位到该条原话；原话已不可访问时在引用处给出反馈。

## 用户故事

1. 作为读者，我希望从跨页引用返回原话，以便看到当时的上下文。
2. 作为正在翻阅长记录的用户，我希望后台收到新发言时仍能定位到所选的消息。
3. 作为切换伙伴的用户，我希望已离开的页面结束定位，以免滚动到另一个会话。

## 实现决定

- 沿用本会话的公开消息身份、游标和普通聊天的定位交互。加载范围只针对点击的会话，不批量预读所有历史。
- 原消息是否属于该会话由读接口校验。定位不创建消息、工单、工作 Chat 或执行。

## 测试与人工验收

1. 从主会话组件的分页接口准备至少三页记录。首次只加载最新页，点击引用后，断言原始消息进入可见区且没有重复行。
2. 覆盖目标已载入、已删除或不可访问、分页失败后重试、读取中切换会话。校验草稿保留、其他会话滚动位置不受影响。
3. 桌面用一条跨页引用验收跳转位置，再试一条本页引用并返回原来的工作。

## 不在本项范围

全局消息搜索、跨主体搜索和新索引页。

## 验证记录

- 主会话页面与伙伴侧栏的 11 条定向用例通过。覆盖三页定位、键盘焦点、取消后重新定位、历史耗尽、无访问权限、失败后从原游标重试，以及切换伙伴时保留两边草稿和阅读位置。实时刷新分别覆盖翻页前后收到新发言、首次打开只读最新页、滚离原话后保持当前位置。
- 主会话 Go API 的原项目引用用例通过，覆盖同一主体向前分页和跨主体拒绝。隔离桌面样例使用本地测试 CLI 生成 38 轮、114 条公开消息。重新启动 Core 后按每页 50 条读得 50、50、14 条，消息标识唯一，末页和最新页各有一条被引用的原话。
- 用户已在桌面验证主会话引用跳转正常。
