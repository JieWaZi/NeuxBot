# 06 Router 按交办选择项目并将工作范围交给 Worker

## 用户问题

主会话本身可以跨项目使用。用户要求修改明确项目时，当前直启 CLI 的流程缺少派工时选择正确目录的环节。

## 解决方案

伙伴能判断简单问答或需要派工的交办，为后者选择获准的项目或用户指明的目录；有歧义就在原会话询问。

## 用户故事

1. 作为维护多个项目的用户，我希望说出项目名就能让伙伴在正确目录工作。
2. 作为交办人，我希望项目同名或路径含糊时先确认。
3. 作为用户，我希望回复旧项目 A 的发言时能回到 A 的工作范围，即使刚切到了项目 B。

## 实现决定

- 主会话未绑定既有工作的普通输入由 Router 理解语义并决定回答、澄清或派工，不依赖中英文关键词。派工时 Router 提议工作范围，宿主核对归属与授权并固定快照。
- 主会话使用固定地址。沿用既有目录核验、引用恢复、普通聊天执行入口和账号配置；运行关键路径沿用已选配置。
- 未明确绑定旧工作或指定范围的纯文本新消息先进入持久输入队列，提交接口返回原消息的接纳回执。Router 按主会话顺序领取。派工决定经本机核验后，将同一输入交给对应的工作 Chat。
- 日常问答由默认会话接待；需要执行的交办使用独立工作会话。头像按实际来源打开默认会话或工作会话。Router 的工作范围澄清直接发布，旧工作会话继续可读可续办。
- 聊天中的定时设置见[第 12 阶段](12-scheduled-reports.md)。
- Router 派出的每项独立交办使用一个工作会话。同一项目可有多个并行工作的记录。引用续办、在原记录追问和原提交重试均沿用原工作会话。
- 主会话的会话摘要设「任务」区，只显示由该主会话启动且仍在运行的任务。任务使用对应工作会话的名称和实际 CLI 图标。

## 测试与人工验收

1. 从主会话分别交办已添加项目 A、B，在两条消息的工作记录里检查各自的工作目录。在 B 的交办之后引用 A 的旧回件，确认新增回合只写入 A 的记录。
2. 测试明确获准临时目录、同名项目、无授权目录和简单问候。歧义时主会话出现澄清，回答前没有向任意目录启动工作。
3. 桌面用两个含同名文件的项目分别交办，打开各自来源文件，核对位置。
4. 在第一项工作结束前，向同一项目交办第二项独立工作。打开主会话摘要，核对两项同时运行时各有一行，以 CLI 图标和工作会话名识别。点击两行分别打开各自的工作记录。任务结束后从「任务」移除，仍可从原消息进入工作记录。
5. 用中英日分别问候、明确交办和否定另开；直答只在默认会话，不启动工作会话。独立派工的回报头像打开实际来源，引用续办复用同一来源。回到主会话核对草稿、阅读位置及公开消息。
6. 在模拟 CLI 阻塞首轮时检查发送回执。关闭原请求，同一主会话继续接收后续输入，重投首条输入返回原回执。释放 CLI 后核对发言顺序、原生会话复用和结果去重。
7. 对比首发、热续聊和 Core 重启后的阶段日志，分别核对队列等待、CLI 会话准备和原生回合耗时。支持原生恢复的 CLI 应在重启后使用原会话标识。

## 不在本项范围

全局目录选择器、扩大目录权限、跨主体转交责任。

## 验收记录

- 定向 Go 测试覆盖普通发送、授权项目和明确目录、歧义澄清、引用原工作范围、原提交重试，以及从任务接纳到实际运行的摘要刷新。CLI 协议测试使用模拟 Codex 子进程，核对临时路由调用的账户与模型选择、工具限制和临时目录回收。
- 2026-11-27 的定向前端回归共 8 个文件、169 项通过。覆盖普通发送、引用澄清、等待首答、头像入口、阅读游标、工作记录以及只在摘要列出本主会话正在运行的任务。独立普通聊天的未读可从工作看板查看。
- 模拟 Codex 子进程通过实际的 Router 与 Worker 协议。回归核对同项目两项工作使用各自的来源、原记录续聊和最终回件重投仅送达一次。
- 模拟 Codex 暂停原生回合时，真实发送入口已返回持久回执，取消原请求后仍可接纳后续输入。放行后两个直答按序发布并复用原生会话。另有协议回归覆盖 Codex 和 Claude 重启后恢复、旧直答引用补齐原问题，以及路由失败或重启后沿原提交对账。
- 桌面视觉和真实模型分别按本页验收步骤检查。
