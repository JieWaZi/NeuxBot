# 04 后台公开回报进入侧栏未读和工作看板

## 用户问题

离开主会话后，伙伴可以发来结果，用户却很难从侧栏或看板知道有新发言。

## 解决方案

交付到公开会话的合格消息增加未读，用户能从看板到达对应消息，并在实际读到后消除未读。

## 用户故事

1. 作为切到别的伙伴的用户，我希望新报告出现在原伙伴的未读里。
2. 作为读者，我希望点击待查看成果能直达对应的公开消息。
3. 作为协作者，我希望已读、待审批、待回答能分别处理。
4. 作为使用两个窗口的用户，我希望另一个窗口及时显示我已读到的位置。

## 实现决定

- 会话阅读保存权威边界；侧栏、看板及桌面提醒依既有规则消费同一份消息和读游标。只有真实公开的合格消息参与计算。
- 未接纳的草稿、自己的发言、CLI 步骤、静默检查不会制造未读。草稿或工作记录的阅读动作不代替看见公开消息。

## 测试与人工验收

1. 从真实公开发布入口在伙伴 A 添加两次独立发言和一次原键重放。在 B 保持前台时观察 A 的未读、看板条目和定位，再打开 A 并读到指定边界。
2. 覆盖跨窗同步、一条报告之后立刻到来第二条、断线重读、未答的审批；处理已读时保持原待决请求。
3. 桌面在两个伙伴间切换，从看板打开新结果，验证未读变化，同时检查过程消息不会产生新提醒。

## 验证记录

- 隔离 Core 通过本地测试 CLI 从公开发布工具连续发送两份报告并重放原收据。报告伙伴有两条未读，对照伙伴为零，看板只列一项，指向第一条公开消息。两个客户端订阅同一 Core 的阅读状态变化，读到第一条后，剩余边界指向第二条。
- 一端离线后，另一端手动标回未读。持旧代次的阅读请求返回冲突，重新连接后可以读到新的边界。读完两条后，看板条目消失。看板批量确认只处理操作时冻结的范围，保留随后到达的报告与未处理的审批。
- 渲染器 8 个相关测试文件的 273 条用例通过，覆盖看板深链先定位再阅读、来源记录不代读，以及新窗口首次从侧栏打开手动标为未读的主会话。Electron 事件与提醒的 28 条用例通过，包含点击旧系统提醒时保留后来设置的未读。
- 待办验收修复覆盖主会话来源的待回答和待审批请求。待办存在时，铃铛有提示点，工作看板可以打开原卡。刷新页面后，待回答的问题仍能作答，已结束的问题保留只读记录。
- 桌面待用户验收。先停在「对照伙伴」，查看「发布报告的伙伴」的未读数，再从工作看板「待我查看」打开该伙伴。确认定位到第一份报告，读完两份后侧栏数字消失。若要观察后台送达，在报告伙伴的主会话再发一条消息，随即切到对照伙伴，等待新的两份报告。

## 不在本项范围
