# Codex 账号、模型、权限与用量验收

本轮只迁移 Codex。账号、模型与设置、用量模块由 Sol 6.1 high 并行实施，各自提交后独立审查；公共运行时装配与真实产品验收由主实现完成。Go 代码按实际协议实现，既有 SDK、协议和纯配置能力按职责复用。

## 实现边界

| 能力        | 当前实现                                                                                                                                          |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 多账号      | 系统登录与受管 ChatGPT／API Key 分开；原生 Home 按账号与 AuthGeneration 隔离；普通配置修订、同主体令牌刷新与身份变更分别处理                      |
| 身份与配置  | 在初始化之后验证实际账号种类、配置根和凭据摘要；账号拥有的原生配置同时用于进程启动和线程配置，覆盖项目／环境中的冲突来源                          |
| 生命周期    | 一个 ProviderRuntime 为发现与聊天拥有真实连接；账号变更先阻止新租约、拒绝活动会话并清理闲置消费者；没有第二套执行 Manager                         |
| 模型        | 读取原生全部分页及隐藏模型；目录按账号主体、认证代次、程序身份与版本隔离；失败保留陈旧快照，畸形响应不当成空成功                                  |
| 强度与 Fast | 每模型使用原生选项；模型、强度、Fast 一次配置；默认／关闭／开启分别表达；已接纳的原生档位与原生报告保持独立，不支持 Fast 的模型切换明确清除旧档位 |
| 用量        | 规范原生 invocation 终态只写一次；业务 SQLite 保存可重建统计投影；Chat 保留引用。摘要与分组共享快照，重复回执和续接不重计                         |

主要代码分别位于 `services/aiaccount/codex_managed.go`、`internal/agent_next/model_catalog.go`、`services/runtimeenvironment/model_catalog.go`、`internal/usage`、`services/usage` 与前端 `modules/usage`。位置索引不保存第二份 Token 计数。

三种权限保留已有产品含义，从新建／恢复线程开始生效，继续应用于每次原生执行：

| 产品选项 | Codex 沙箱         | 审批       | 工作区网络           |
| -------- | ------------------ | ---------- | -------------------- |
| 默认权限 | read-only          | on-request | 不开启               |
| 自动审批 | workspace-write    | on-request | 显式关闭             |
| 完全访问 | danger-full-access | never      | 服从原生完全访问模式 |

工作区权限保留 NeuxBot 既有网络约束。模式名称不用于猜测原生权限，测试直接检查 thread/start、thread/resume 和 turn/start 载荷。

## 真实产品验收

通过隔离数据目录启动 NeuxBot Web 与真实 Core，使用本机 Codex CLI 0.163.0。首次引导列出 10 个真实模型，选择 GPT-6.1-Sol；聊天中设置 high、明确关闭 Fast、保持默认权限。两次请求均要求不使用工具、不访问文件。

第一轮回复验收标记；第二轮只要求回忆前一轮标记，正确返回同一标记。规范终态中的两个 invocation 指向同一个原生 session。原生归档的两份 turn_context 均为 `gpt-6.1-sol`、`high`、`on-request`、`read-only`，服务档位为空。两个公开执行终态均为 completed；业务终态没有重复存放原生用量。

| 项目                   |               第一轮 |              第二轮 | 用量页合计 |
| ---------------------- | -------------------: | ------------------: | ---------: |
| 普通输入               |               17,451 |                 420 |     17,871 |
| 缓存读取               |                7,552 |              24,832 |     32,384 |
| 缓存写入               |                    0 |                   0 |          0 |
| 输出                   |                   27 |                  16 |         43 |
| 其中推理               |                    9 |                   0 |          9 |
| 含缓存读取的已知 Token |               25,030 |              25,268 |     50,298 |

推理属于输出子集，不再次加总。用量页显示 2 次调用、50,298 已知小计、17,914 扣除缓存读取的 Token、1 次数据不完整、2 次未定价。页面数字与两个规范终态及 SQLite 的两行投影一致。重启 Core 并重新加载页面后，仍显示相同计数与完整性说明。

## 审查与验证

- 账号审查复现并关闭同主体刷新造成配置修订冲突、损坏投射阻止重新登录／退出、DeepSeek 原生身份模式不匹配、已登记旧投射没有退役四项问题。
- 模型与权限审查复现并关闭继承轮后切换模型漏清 Fast、打开线程时遗漏工作区网络限制、畸形目录覆盖成功快照三项问题。
- 用量审查复现并关闭刷新期间列表消失、旧与新消息续接漏掉已知用量、极小十进制金额被二次解析拒绝，以及缺少缓存计数的样本被错误归入普通输入。
- 公共接入审查复现并关闭退出期间回调访问已清空全局对象的问题；回调持有装配时绑定的实例，晚到原生终态及认证清理不会访问已移除的全局引用。
- 真实 Codex 配合合成 API Key 的无 Prompt 启动验证，证明受管账号能覆盖冲突的宿主环境及项目 provider，并在验证所选根与密钥摘要后才发布连接。
- 运行相关 Go 包定向测试、具名 race、前端模块测试及类型检查、API 生成一致性、文档检查。没有用全量测试或合成测试替代真实平台验收。

## 保留边界

- 真实会话使用系统账号。两个真实订阅之间切换、真实 OAuth 重新授权和在线刷新、DeepSeek 服务请求尚未以真实账号验收；隔离与变更行为由合成凭据、真实 SQLite、原生无 Prompt 启动和竞争测试覆盖。
- 原生实际回执缺少完整的发布方、服务档位和价格适用证据时，费用保持未定价。没有套用猜测价格，也没有把订阅额度当成消费费用。独立账号额度面板不属于本轮已交付的消费统计页面。
- 统计分组每页仍分批聚合选定日期范围，后台刷新追赶已加载深度时会重复扫描；内存有界，但不等同于恒定开销的分组分页。
- 三种权限的真实协议映射均有测试，本次模型实机只执行默认只读模式；没有以完全访问执行任何验收动作。
- 当前仍在隔离的 `agent_next` 候选目录与本地 Go workspace 中联调。acp-go 发布版本固定、最终目录替换、其他 CLI 和未迁移独立生成入口继续单列，不宣称已发布完成。
