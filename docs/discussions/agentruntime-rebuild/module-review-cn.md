# 重建模块审查与并行边界

本规则用于[重建方案](../../superpowers/specs/2026-11-04-agentruntime-rebuild-design.md)的实施验收，不表示任何模块已通过。

## 五项审查

1. **功能完成度**：逐项对应需求、真实入口、状态转换、错误出口和验证证据，明确已完成与缺失。测试通过不替代功能覆盖。
2. **OpenBot 实现偏差**：对照固定源码，记录原职责和行为、Go 落点、偏差原因、收益与代价。只有独立证据支持时才声称更好，否则说明尚未证明或应恢复参考机制。
3. **内聚与冗余**：检查重复状态、多余转换、废弃执行路径、仅转发层、分散文件和失真的命名。沿实际入口读到终态；依状态所有权组织，不能仅搬文件或加包装。
4. **实际复现**：关键问题提供固定提交、命令、事件顺序、实际与预期结果。区分静态发现、合成 fake CLI、真实 CLI 配隔离本机假服务、真实账号模型及 UI 验证。没有运行就不写成已复现；不重复无关测试。
5. **Go 复刻可行性**：OpenBot 已实现且适用的机制优先按相同职责和行为独立用 Go 实现。不能照用时说明协议、平台、语言或本项目约束及替代证据；参考实现本身的不安全重试不能照搬。保留来源与许可边界。

每个完整模块提交后独立审查。问题先归到唯一所有者及其状态转换规则，再确定完整模块修正，不能按失败用例追加互不一致的判断。再审除了复现原问题，还检查同一规则覆盖的其他入口。完成首批集成后另做整体边界审查。

## 隔离候选与切换

按重建方案第 9.1 节在临时 `agent_next` 目录实现，旧 Agent 冻结为对照。审查必须证明候选未通过调用、嵌入、别名或隐藏依赖复用旧执行所有者；单纯复制、搬移或重命名旧包不算重构。允许经核对的 SDK、生成协议与纯函数复用，复用清单应明确输入、输出和外部副作用。

先审所有权与状态规则，再沿实际 Go 调用和 ACP 服务入口分别验收。必须覆盖准备与控制命令、原生终态与连接故障、观察交付与 Usage 事实三组边界；普通路径测试通过不能替代这些交叉场景。切换提交同时检查实际装配、旧代码删除、临时路径消失、同一数据只有一个写入者和同一执行只有一个所有者。

## 并行开发

Codex、Claude、Cursor 使用独立 Git worktree 和分支，开发及架构审查使用 GPT-6.1 Sol high。Terra 仅承担简单整理和核对，不因 Sol 容量不足替换开发模型。

每位适配器实现者只拥有本厂商模块、必要测试及模块文档。Cursor 的标准 ACP 通用层、共享 acpmeta/SDK、NeuxBot 内部运行底座与产品接入由主线单一所有者协调；厂商实现者提出有实际消费者的合同需求，主线裁决后由指定 Sol 实现者修改。禁止各自建立同义公共合同、复制通用执行器或修改其他 worktree。

并行不表示依赖已验收。各模块的基线、未通过审查项和共享合同版本独立记录；集成前核对接口与行为并运行直接受影响验证。用户主工作区、账号与项目不用于破坏性试验。
