# 聊天接纳与原生会话修复

## 范围

处理已经确认的聊天、会话、插件与日志问题，以及 Qoder 配置分类适配；保留原 Codex、Claude、WorkBuddy、Cursor 修复。停止其他 CLI 的扩展实测；不改变 CLI 自有配置、工具与全局 MCP 行为。acp-go 与插件继续在各自仓库维护。

## 职责

Execution 冻结本轮输入与廉价配置事实。ChatHost 根据静态配置选择现有会话，仅新建原生消费者时取得会话资源；Runtime 驱动只串联协议生命周期。每轮的软件能力授权仍按本轮执行维护，不放进会话永久快照。账号修改关闭对应闲置会话，正在执行时保持忙碌边界。

插件管理中的显式登录、状态检查与测试连接仍属于管理操作；聊天发送不调用它们。插件授权管理通过既有协议准备加密交付材料，聊天只读取已有材料；宿主不解析供应商私有身份文件，不新增 TTL 缓存替代删除预检。

## 验收

### 架构复审与整改结果

| 审查问题                 | 当前归属与验证                                                                                                                                                                     |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 聊天仍调用授权程序       | 安装和授权管理生成加密交付材料；聊天持有身份占用后仅读取材料，无材料仍交付能力。回归证明聊天不启动桥接                                                                             |
| 凭据修订导致每轮冷启动   | 账号静态配置身份与凭据 CAS 修订分开；API Key、订阅账号真实临时数据库的两轮复用回归通过                                                                                             |
| 热会话令管理操作一直忙碌 | 既有会话所有者回收相关闲置消费者，活动回合保持忙碌；每轮用途更新并在结束后清空                                                                                                     |
| CLI 私有逻辑泄漏         | 原生环境在 agent/host/workspace 装配；Qoder 分类在独立 acp-go 对应适配器归一化；公共 ACP 不猜测 CLI 自定义选项 ID                                                                  |
| 差量编解码分散           | 编码、基准与解码全部归 eventlog，完整规范事件是 Execution 与 MessageView 的唯一交换内容                                                                                            |
| 统一审查发现管理时序遗漏 | 拟配置材料随安装事务提交；状态查询只读；取得身份占用后重读材料；非最后卸载不构造授权桥接；最后引用判断仅统计当前插件，无关插件不绕过身份清理。对应回归均确认修复前失败、修复后通过 |

本轮未修改或发布独立插件。已有安装若尚无私有交付材料，不在聊天中回填；通过显式重新授权或安装管理生成材料。缺失材料不阻止聊天，实际能力调用可以报告未授权。
